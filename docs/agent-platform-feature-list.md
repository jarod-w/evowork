# EvoWork 功能点清单

> EvoWork 是全场景职场 AI 智能体桌面工作台。用一句话描述需求，即可自主规划执行复杂任务并交付可验收的结果。

---

## 一、核心能力

| 能力               | 说明                                                                         |
| ------------------ | ---------------------------------------------------------------------------- |
| **理解自然语言**   | 用一句话下达任务，无需复杂操作步骤                                           |
| **自主规划执行**   | 自动拆解任务、规划步骤、完成交付                                             |
| **多模态任务处理** | 支持文档、表格、PPT、数据分析、图片生成、视频生成、3D 模型生成等多种任务类型 |
| **本地文件操作**   | 可读取授权的电脑文件夹，进行批量处理                                         |
| **多任务并行**     | 支持同时发起和管理多个任务，适合并行处理                                     |
| **结果可验收**     | 生成的文档、表格、PPT 等可直接使用和分享                                     |

---

## 二、适用场景

### 2.1 日常办公（默认模式）

- **文档生成**：生成工作报告、技术文档、会议纪要、README 等
- **数据分析**：上传数据文件，自动分析和可视化
- **PPT/报告生成**：从需求描述生成演示文稿和报告
- **深度研究**：对复杂问题进行深度调研并输出报告
- **邮件编辑、周报生成**等办公场景
- **批量文件处理**：自动整理、重命名、转换文件格式

### 2.3 设计创意

- **产品设计**：生成界面设计稿、组件设计、布局方案
- **PPT 设计**：从需求描述生成演示文稿
- **交互原型**：快速生成可交互的产品原型和流程图
- **品牌设计**：创建 Logo、品牌标识设计素材
- **海报设计**：生成营销海报、活动横幅、社交媒体配图

### 2.4 多模态内容生成

- **文生图 / 图生图**：通过 AI 模型从文字描述或参考图片生成图片
- **文生视频 / 图生视频**：生成短视频内容
- **文生 3D 模型 / 图生 3D 模型**：生成 3D 模型文件
- **图片视频特效**：基于模板对图片应用动效（如拥抱、变身、万物归尘等）

## 三、工作模式

| 模式                  | 说明                                                           |
| --------------------- | -------------------------------------------------------------- |
| **Craft（你说我做）** | 立即行动完成任务，可读写文件、执行命令、生成内容并直接交付结果 |
| **Plan（先想后做）**  | 分析需求、设计方案、拆解为步骤计划，经用户确认后执行           |
| **Ask（只谈不做）**   | 仅回答问题、读取文件、分析信息，不修改任何文件，不执行命令     |

## 四、任务管理

### 4.1 任务列表

- 左侧边栏显示所有创建过的任务，按文件夹分组
- 分为「任务」和「空间」两个板块
- 每个任务卡片显示：任务标题、当前状态、最近更新时间

### 4.2 搜索与筛选

- **搜索**：按任务标题快速查找
- **筛选**：按状态或日期筛选
- **重置筛选**：清空条件恢复查看全部

### 4.3 任务状态

| 状态   | 说明                       |
| ------ | -------------------------- |
| 进行中 | EvoWork 正在执行任务       |
| 已完成 | 任务已执行完成             |
| 失败   | 执行过程中出现问题         |
| 待处理 | 等待进一步处理或输入       |
| 规划中 | 正在分析需求并整理执行思路 |
| 已归档 | 已归档，用于后续查阅       |

### 4.4 任务操作

| 操作           | 说明                                    |
| -------------- | --------------------------------------- |
| 置顶           | 将任务置于列表顶端                      |
| 打开文件夹     | 打开任务所在文件夹                      |
| 重命名         | 修改任务名                              |
| 保存到工作空间 | 在任务列表中持久保存，可用 IDE 打开查看 |
| 分享任务       | 分享到任意渠道，自动生成公开链接        |
| 删除           | 从列表中删除任务                        |
| 归档           | 归档后可在「系统设置 - 数据管理」中查看 |

### 4.5 工作空间操作

- 在同一工作空间中新建任务
- 打开工作空间所在文件夹
- 从列表中移除工作空间

### 4.6 继续处理已有任务

- 对已完成、失败或中断的任务均可重新进入继续补充消息
- 基于已有上下文继续推进，无需从头创建

## 五、任务对话

### 5.1 对话交互

- 在输入框中直接输入需求或补充说明
- 点击发送按钮或按回键发送
- 在已有任务中继续追问，保持上下文连续性
- 执行过程中可查看回复、结果和中间步骤

### 5.2 顶部操作

| 操作         | 说明                                                   |
| ------------ | ------------------------------------------------------ |
| 对话内搜索   | 输入关键词快速查找目标对话内容                         |
| 分享任务     | 自动生成公开链接，分享到任意渠道                       |
| 历史提问     | 查看任务内历史对话记录，支持点击跳转                   |
| 显示详情面板 | 打开右侧边栏，查看产物、全部文件、文件变更和内置浏览器 |

### 5.3 文件和图片上传

- **粘贴截图**：`Ctrl/Cmd + V` 直接粘贴剪贴板图片
- **上传文件**：点击上传按钮或拖拽文件到输入框
- **引用上下文**：通过 `@` 引用文件、文档、规则等信息

**支持的文件类型**：PDF、Word、TXT、Markdown、RTF、Excel、CSV、TSV、PPT、常见图片（JPG/PNG/GIF/BMP）、ZIP/RAR 压缩包、各类编程语言代码文件。

### 5.4 隐私授权边界

- 文件处理默认在本地完成，原始数据不上传云端
- 服务端仅处理数据片段，用后即弃，不保存也不用于模型训练
- 仅能访问主动授权的文件夹，系统敏感目录自动拦截
- 高危操作需二次确认

### 5.5 执行过程展示

- 展示回复内容、阶段说明、结果摘要、可展开的中间步骤
- 无需离开任务即可查看输入、过程和输出

### 5.6 中断与继续

- 任务执行中可随时中断
- 中断后可继续补充说明、调整需求重新发送、基于已有内容继续推进

## 十五、下一代智能体平台：演进推论

> 本节不属于 EvoWork 现有功能，而是基于上述现状对**下一代平台**的判断，作为产品方向输入。

### 15.1 核心推论：竞争力不在「Agent 有多能干」，而在「敢让它干多少」

当所有平台的 Agent 都能写完那份报告、跑完那次分析时，能力本身不再是差异点——它会被下一版模型迅速抹平。真正的差异变成：**谁能让用户/企业放心把生产系统的写权限交出去。**

因此今天看起来最「不性感」的三件事，是唯一会持续增值的一层：

| 沉淀层             | 为什么不会被模型抹平                                           |
| ------------------ | -------------------------------------------------------------- |
| **审计与可复现**   | 责任归属是制度问题，不是能力问题。模型再强，也不能替人承担后果 |
| **权限与身份**     | 「Agent 代表谁在行动」必须由组织定义，模型无法自证授权         |
| **成本与并发治理** | Agent 越自主，越需要预算闸门；自主性提升会放大而非消除这个需求 |

> 推论的可检验形式：如果两个平台的 Agent 能力相当，采购决策会落在**放权深度**上——能否让它直接改生产配置、直接发对外邮件、直接动账务数据。

### 15.2 主线判断：演进不是功能变多，而是脚手架被吞掉

今天列出的许多能力（第三章工作模式、第八章技能系统、第九章专家系统等）本质是在为「模型还不够可靠、不够便宜、不够长程」打补丁。模型每往前一步，就有一层功能消失；剩下的从「产品功能」沉淀为「制度设施」。

### 15.3 三条驱动力

| 驱动力       | 决定什么                                                                                          |
| ------------ | ------------------------------------------------------------------------------------------------- |
| **模型能力** | 哪些功能被吸收进模型内部（提示工程、手写编排、通用技能都在被吞的路上）                            |
| **单位成本** | 并发规模。从「跑 1 个 Agent」到「跑 100 个 Agent 互相验证」，是成本曲线的函数，不是产品设计的函数 |
| **信任制度** | 放权边界。技术上能做 ≠ 允许它做。后期瓶颈会从模型转到责任归属                                     |

### 15.4 能力演进阶梯

| 能力轴       | 现在（本文档所述）          | 下一代              | 再下一代                          | 终局形态                                                                       |
| ------------ | --------------------------- | ------------------- | --------------------------------- | ------------------------------------------------------------------------------ |
| **任务单元** | 一次性任务（第四章）        | 长任务 + 检查点     | 持续目标                          | **声明式**：声明期望状态，Agent 持续 reconcile（控制循环，而非「跑完即结束」） |
| **交互界面** | 对话输入框（第五章）        | 常驻 + 异步审批队列 | 意图层：说目标不说步骤            | 界面从「输入框」退化为「决策 Inbox」——Agent 提议，人只做判断                   |
| **编排**     | 专家推荐（第九章）          | 人写 workflow / DAG | Agent 自己组队、按结果选拔        | 编排层消失，融入模型内部多路推理                                               |
| **技能**     | 人写 + 市场装（第八章）     | 从执行轨迹自蒸馏    | 技能间组合与继承                  | **通用技能全部消失**，只剩组织私有流程这类模型无法先验知道的部分               |
| **记忆**     | MEMORY.md（第十二章）       | 结构化 + 权限隔离   | 组织知识图谱                      | 记忆下沉为权重：组织持有的持续微调模型，云端只提供通用推理                     |
| **验证**     | 人工目检（第六章）          | 多 Agent 对抗验证   | 可执行的验收标准（验收即测试）    | **信任变成经济问题**：输出带 SLA、第三方审计、错误赔付                         |
| **权限**     | 目录授权（第十四章）        | policy-as-code      | Agent 成为 IAM 中的一等 principal | 法律主体化：代理权、责任归属、监管留痕                                         |
| **安全**     | 安装时静态审计（第八章）    | 污点追踪 + 最小权限 | 能力安全（不可伪造的凭据传递）    | 形式化隔离 + 保险兜底                                                          |
| **端云**     | 云推理 / 本地执行           | 按难度路由          | 端侧为主、云端兜底                | 个人模型常驻本地，云端只在重推理时被调用                                       |
| **互操作**   | MCP：Agent 调工具（第十章） | A2A：Agent 调 Agent | Agent 市场与结算                  | Agent 之间的经济体：合约、定价、声誉                                           |
| **可观测**   | 执行历史（第七章）          | trace + 成本归因    | 失败归因到具体决策                | 生产数据自动回流成 eval，平台自我优化闭环                                      |

### 15.5 会消失的 vs. 会沉淀的

**会消失**（被模型吞掉，不要在此建护城河）：提示词工程、Craft/Plan/Ask 式的模式切换、手写 workflow、绝大多数通用技能、连接器胶水代码，乃至「任务列表」这种 UI 形态本身。

**会沉淀**（模型再强也替代不了，且随规模增值）：

- 组织私有知识与流程（模型没见过的那部分）
- 权限、责任与审计
- 验收标准的定义权（「什么算做对了」永远由人定义）
- 成本与并发的治理

### 15.6 优先级判断

若资源只够做五件事，按此顺序：

| 序  | 方向                       | 理由                                             |
| --- | -------------------------- | ------------------------------------------------ |
| 1   | **事件驱动 + 异步审批**    | 把「工具」变成「同事」，是体验代差               |
| 2   | **Agent 编排与对抗式验证** | 决定复杂任务的完成质量                           |
| 3   | **审计 + 权限 + 成本治理** | 决定能否进入企业生产环境                         |
| 4   | **提示注入防护**           | 连接器越多洞越大，且是唯一会真正出安全事故的一项 |
| 5   | **技能自蒸馏**             | 决定长期是否具备复利                             |
