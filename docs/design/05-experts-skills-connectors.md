# 05 · 插件（技能 · 连接器 · EvoWork 专家）

> 上游：[总纲 §6.3 / §6.4 / §6.5](../evowork-on-codex-design.md)· D4 · K7 · Q5 · Q9 · [清单 §8 / §9 / §10](../agent-platform-feature-list.md)

> 对外统一使用“插件”；“技能 / 连接器 / EvoWork 专家”是插件页内的能力分类，不是三个一级产品入口。

## 1. 插件概念与三类能力

“插件”是用户发现、安装、使用和管理扩展能力的上层产品概念。三类能力回答同一个问题——**“怎样让 EvoWork 多会一件事”**——只是层次不同：

|        | 是什么                 | 内核载体                              | 增加的是                             |
| ------ | ---------------------- | ------------------------------------- | ------------------------------------ |
| EvoWork 专家 | 一个带独立配置层的角色 | `agent-roles` TOML + `spawn_subagent` | **谁来做**（人格、指令、模型、权限） |
| 技能   | 一段可被模型调用的能力 | `SKILL.md` + 脚本                     | **怎么做**（方法与模板）             |
| 连接器 | 一个外部系统的接入     | MCP server                            | **能碰什么**（数据与动作）           |

因此共用一个“插件”目录页与同一组页面级 Tab。专家必须标注“EvoWork 专家”，避免让用户误以为它是标准插件包中的通用组件。当前数据层仍按技能、连接器、专家分别管理；未来若增加多能力 bundle，再补插件级版本与事务化卸载。

## 2. 页面骨架（侧栏 + 目录页）

```
标题栏带  │ 插件  [技能] [连接器] [EvoWork 专家] ··· [搜索] [已安装] [添加]
─────────┴──────────────────────────────────────────────────────────────────
内容区
  ├ 搜索与来源/状态筛选
  └ ItemCard 网格（宽屏 3 列，随窗口降列）
```

三个 Tab 的右侧动作按钮：

| Tab    | 搜索占位   | 按钮 1       | 按钮 2          |
| ------ | ---------- | ------------ | --------------- |
| EvoWork 专家 | 搜索专家 | 已创建 N | ＋ 新建专家 |
| 技能   | 搜索技能   | 我已安装的 N | ＋ 添加技能     |
| 连接器 | 搜索连接器 | 已信任 N     | ＋ 自定义连接器 |

「我已安装的 N」是一个**筛选开关**（按下后网格只显示已装项），不是跳转 —— 截图里它带勾选图标，符合开关语义。

### 3.2 Q5 约束下的目录边界

截图 2 有三个 `TextTabs`：**推荐 / SkillHub / 套件**，且有「精选技能」「换一换」这些市场运营位。Q5 已决策 **v1 不做公开 registry、不做上架审核与评分**，因此：

| 截图元素                | v1 处理                   | 理由                                                                                  |
| ----------------------- | ------------------------- | ------------------------------------------------------------------------------------- |
| 「推荐」Tab             | ❌ 不作为独立内容页       | 当前没有稳定的推荐服务；按来源与状态筛选即可                                            |
| **「SkillHub」Tab**     | ❌ **不渲染**（不是置灰） | 公开市场推 v2。置灰会让用户反复点、反复失望；不存在比坏掉好                           |
| 「套件」Tab             | ❌ 当前不渲染             | 数据层尚无多能力 bundle 的聚合、版本和事务化卸载                                      |
| 「精选技能」+「换一换」 | ❌ 不渲染                 | 避免在管理页引入没有数据依据的运营推荐                                                |
| 分类 chips              | ✅ 保留                   | 来自 manifest 的 `category`                                                           |
| 评分 / 下载量 / 评论    | ❌ 不做                   | 需要 registry 与用户行为回传                                                          |

**来源标注是硬要求**：每张卡的角标行（01 §5.20）必须显示当前可判定的来源——`官方内置` / `本地目录` / `Git`。企业私有源接通后再增加对应来源，不先显示空入口。

### 3.3 安装流程与安全审计（清单 §8「P0/P1/P2 风险分级」）

总纲 §6.3 定了映射方向（`marketplace_policy.rs` + bundle 校验 + `guardian-v2` 白名单 → P0/P1/P2），本节把它落成用户看到的东西：

```
点击 ＋ → ① 静态审计（本机，不联网执行任何脚本）
              · 解析 manifest 与 SKILL.md
              · 提取声明的能力面：文件路径、网络域、要执行的命令、要装的 MCP server、hooks
              · 按规则定级
         → ② 分级卡（模态）
         → ③ 用户确认 → catalog 安装动作 → 落盘 → 目录刷新
```

| 级别          | 判定规则（EvoWork 侧定义）                                                                              | 分级卡表现                                                               | 用户动作                 |
| ------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------ |
| **P0 低风险** | 只读工作空间 + 无网络 + 无 shell + 无 hooks                                                             | `success` Badge「低风险」，只列能力摘要                                  | 一键安装                 |
| **P1 需注意** | 写工作空间内文件，或调用受限命令白名单内的命令，或声明有限网络域                                        | `warning` Badge，**逐项列出**：会写哪些路径、会跑哪些命令、会访问哪些域  | 勾选「我已了解」后安装   |
| **P2 高风险** | 声明 hooks（可拦截所有工具调用）、要求工作空间外路径、要求任意网络、含二进制、要求 `danger-full-access` | `danger` Badge + 红色边框，逐项列出 + **明确写出"它可以做什么最坏的事"** | 输入技能名确认（防误点） |

三条不可协商的规则：

1. **审计不执行任何被审计的代码**（否则审计本身就是攻击面）。只做静态解析。
2. 装完后能力面**不得扩大**：安装时声明 `network: none` 的技能，运行时若尝试出网，`pre_tool_use` hook 直接拒绝并记审计（10 §6）。这条把"安装时审计"从一次性检查变成持续约束 —— 否则 P0/P1/P2 只是装饰。
3. 私有源包必须**签名校验**（对齐 R11 的策略包签名思路）；校验失败一律拒装，不给"仍然安装"的出路。

### 3.4 自定义技能（清单 §8）

复用内核内置示例技能 `skill-creator` / `plugin-creator`（`codex-rs/skills/src/assets/samples/`，总纲 §3.4）。UI：「＋ 添加技能」下拉三项 —— 「从文件/目录安装」、「从 Git 安装」、「**让 EvoWork 帮我写一个**」。第三项等于新建一个任务并 `@skill-creator`，落到 04 的任务工作台，不另做编辑器。

技能详情页（点卡片进入）：概览（`SKILL.md` 渲染）· 能力面（审计结果，常驻可查）· 文件列表 · 版本与来源 · 用量统计（本机）· 卸载。

## 4. 连接器 Tab（截图 3）

### 4.1 数据来源

| UI               | 来源                                                                                                                                   |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 已添加列表与信任状态 | `services/catalog` 的连接器目录视图                                                                 |
| 配置                 | `config.toml` 的 `mcp_servers`；当前添加、信任与移除由桌面宿主写入                                       |
| OAuth                | 当前未接通，入口隐藏；后续接入时令牌必须进入安全存储，不落明文配置                                       |
| 工具级权限           | 借用 `app_tool_policy` 的权限模型思路（K7），当前未接通逐工具编辑时不显示对应操作                          |
| 手动调用/调试        | 当前不作为用户可见能力；内核握手和 live reload 接通后再开放                                               |

### 4.2 卡片与状态

`ItemCard` 带角标行，角标显示连接状态：

| 状态     | Badge              | 说明                                |
| -------- | ------------------ | ----------------------------------- |
| 待信任   | warning“待信任” | 显示“审查并信任”                     |
| 已信任   | success“已信任” | 表示配置已获用户信任，不冒充实时连接状态 |
| 配置错误 | danger“配置错误” | 显示可行动的字段错误                  |
| 已禁用   | neutral + 锁    | 企业策略禁用，显示原因                |

在内核 MCP 握手和状态订阅接通前，禁止显示“已连接 · N 个工具”或“启动失败”等实时状态。

### 4.3 Q9 约束下的降级：目录里不铺国内连接器

截图 3 的 18 张卡全是国内生态（腾讯微云 / 腾讯文档 / 企业微信 / 飞书 / 钉钉 / 腾讯会议 / QQ邮箱 / ima / 乐享 / TAPD / 通达信 / 腾讯自选股 / CNB / 福帮手 …）。**Q9 已决策本期全部不做，只保留 browser**。

| 截图元素                   | v1 处理                                                                                                               |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 国内生态连接器卡 × 18      | ❌ 不出现。不做"即将推出"占位卡 —— 占位卡等于承诺排期                                                                 |
| 「连接器推荐」（清单 §10） | ❌ 不做（Q9）                                                                                                         |
| 目录内容                   | ✅ `browser`（EvoWork 自建 MCP，CDP）+ 用户自建的 MCP server + 企业私有源下发的 MCP server                            |
| 「＋ 自定义连接器」        | ✅ **本期的主入口**。表单：名称 / 传输方式（stdio / SSE / HTTP）/ 命令或 URL / 环境变量 / 需要的凭据 / 工具权限默认值 |
| 分类 chips                 | ✅ 保留，但 v1 只有「浏览器」「自建」两类                                                                             |

**页面文案**（这是对用户如实说明的地方，不能藏）：连接器 Tab 顶部常驻一行 `caption`：「本版支持通过 MCP 协议接入任意第三方服务。官方连接器目录将在后续版本提供。」—— 既说清能力（MCP 完整复用，总纲 §6.5）又不虚构目录。

### 4.4 browser 连接器的特殊性

它是 v1 唯一的官方连接器，且同时服务两个地方：agent 的网页操作能力（MCP 工具）与结果区的浏览器视图（04 §6.4）。配置项对应 `BrowserUseConfig` 的 origin 级策略：

| 配置              | 默认                             | 说明                                 |
| ----------------- | -------------------------------- | ------------------------------------ |
| 允许访问的 origin | `localhost` + 任务中显式提到的域 | 白名单制，不给通配                   |
| 下载              | 关                               | 开启后下载落 `<工作空间>/downloads/` |
| 上传              | **关**                           | 开启是一条出网路径，需逐次授权（K6） |
| 表单提交 / 点击   | 需审批                           | 走 `permission_request`（10 §3）     |

### 4.5 信任机制（清单 §10）

新增连接器**必须显式信任后启用**，与技能的 P0/P1/P2 同源但更严 —— MCP server 是外部进程，能力面无法静态穷举：

1. 首次添加只落配置、**不启动**，状态为「待信任」。
2. 信任模态列出当前可静态确定的进程命令行、传输方式、URL/环境变量名和声明权限；不虚构尚未握手得到的工具清单。
3. 当前信任动作只表示允许写入 MCP 配置。内核 live reload、握手状态和逐工具“自动允许”接通前，不显示对应控件。
4. 运行期接通后，每次工具调用都必须经过 `pre_tool_use` hook 并记审计（10 §6）。

## 5. 专家 Tab（截图未覆盖，按设计系统推导）

### 5.1 数据模型

沿用总纲 §6.4 的 `agent-roles` TOML（`~/.evowork/agents/*.toml`），字段与总纲一致（`name` / `description` / `nickname_candidates` / `model` / `[collaboration_mode]`）。EvoWork 增补三个纯展示字段（不进内核解析路径，放独立 `[interface]` 段）：

```toml
[interface]
display_name = "财务分析专家"
avatar       = "finance.png"
category     = "投资理财"
sample_tasks = ["解读这份财报", "做一份预算表", "算这几个比率"]
```

### 5.2 页面

与技能 Tab 同构。`ItemCard` 内容 = 头像 28（圆形，专家用圆、技能/连接器用圆角方，以形状区分类别）+ 名称 + 一句话描述 + 分类角标。

专家详情：介绍 · 擅长任务（`sample_tasks`，点击即以该专家新建任务）· 使用的模型与权限 · 独立指令（可编辑）· 「直接对话」。

### 5.3 专家团（清单 §9「多角色协作」）

= 一组专家 + 一个编排提示，落成一个特殊技能包（`SKILL.md` 描述编排逻辑，内部用 `spawn_subagent`）。UI 在「套件」里呈现，卡片显示成员头像堆叠。运行时的子任务在对话流里以 `SubAgentActivity` 呈现（04 §5.2 #13），并受 Q11 的并发（3）与预算闸门约束（10 §5）。

### 5.4 「专家推荐」（清单 §9）

清单要求“根据任务需求智能推荐”，但当前没有端到端实现，因此主路径隐藏该能力。未来若实现，必须使用纯本地规则（K6）：

- 触发点：Composer 输入 > 20 字且停顿 800ms 后，在 Composer 上方出现一行轻量建议「这类任务 <财务分析专家> 更擅长 · 应用」。
- 规则：关键词/分类匹配 + 本机历史使用频次。匹配不到就不显示（**不硬凑**）。
- 可在设置里整体关闭。

## 6. Composer“使用插件”选择器

不再使用“发现应用”这一名称。左侧“插件”负责完整的发现与管理；Composer 的“使用插件”只负责把已安装、可信且当前可用的能力带入任务。K7 已决策不复用内核的 Apps / 连接器目录。

| 项 | 设计 |
| --- | --- |
| 入口 | Composer 的“+ 添加”→“使用插件” |
| 形态 | 锚定 Composer 的轻量选择器；不占侧栏品牌行 |
| 内容 | 已安装技能、已信任连接器、已创建的 EvoWork 专家 |
| 点击 | 把能力引用加入当前 Composer，不自动发送 |
| 管理 | 底部“管理插件”跳转 `/catalog/skills` |
| 内核 Apps 目录 | **不使用**（K7）；不订阅 `v2/apps.rs` 与 `app/list/updated` |

## 7. 空态与异常

| 情况                   | 表现                                                                                                                |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 无私有源配置（个人版） | 只显示官方内置、本地目录和 Git 来源；不显示空的私有源入口                                                           |
| 私有源不可达           | 网格显示已缓存的索引 + `--warning` 条「私有源暂时无法访问，显示的是缓存内容（更新于 X）」                           |
| 搜索无结果             | 空态 + 「没有找到 <词>」+ 「让 EvoWork 帮我写一个技能」                                                             |
| 安装失败               | 卡片回落未安装态 + Toast（含失败原因分类：签名校验失败 / 依赖缺失 / 磁盘空间 / 版本不兼容），**签名失败不提供重试** |
| MCP server 启动失败    | §4.2 danger 态 + 展开 stderr 摘要 + 「查看完整日志」（本机日志文件）                                                |
| 企业策略禁用某类       | 若用户需要理解该策略，在管理页保留锁态与原因；主使用选择器中隐藏                                                     |
