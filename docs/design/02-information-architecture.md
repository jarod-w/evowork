## 1. 顶层结构

截图 1 的侧边栏给出了产品的一级信息架构：**7 个固定入口 + 1 个动态任务区**。这与总纲 §6.1 的概念映射不是一一对应 —— 总纲只映射了「任务/空间/分组」三个概念，另外 4 个入口（助理、专家·技能·连接器、自动化、资料库）在总纲里分散在 §6.3–6.9，还有「更多」是纯自建。本文把它们统一成一张导航表。

```
EvoWork
├─ ①  新建任务          → 首页（Composer）                       03
├─ ②  助理              → 常驻助理会话（Q20 默认方案）             §4.2
├─ ③  项目              → 工作空间列表 → 空间详情                 §4.3
├─ ④  专家·技能·连接器   → 三 Tab 目录页                          05
├─ ⑤  自动化            → automation 列表 + 执行历史              07
├─ ⑥  资料库            → 三栏资料/产物库                        06
├─ ⑦  更多（尾标「灵感」）→ 二级入口聚合                           §4.7
└─ 任务 (N)             → 任务列表（分组 / 置顶 / 筛选 / 搜索）     04
```

**为什么「新建任务」是导航项而不是按钮**：它切换的是主内容区的一个视图（首页），与其他 6 项同级，且需要保持选中态（截图 1 即为该项选中）。实现上它不创建 Thread —— Thread 在首次 `turn/start` 时才创建（09 §3.2），所以从首页离开不会留下空任务。

## 4. 各入口的功能定义

### 4.1 ① 新建任务
见 03。要点：这是产品的默认落地页；冷启动、关闭最后一个任务、点击「新建任务」都到这里。

### 4.2 ② 助理（**Q20 默认方案**）

截图有此入口，总纲无对应条目。默认方案：**助理 = 一个常驻的特殊 Thread**，不是独立产品形态。

| 项 | 设计 |
|---|---|
| 身份 | 单一固定 thread（`assistant_thread_id` 存本机配置），冷启动时 `thread/resume`，不存在则 `thread/start` |
| cwd | `~/.evowork/assistant/`（一个空工作目录，不指向用户任何真实文件夹） |
| 默认模式 | **Ask**（只读 + 无网络 + 过滤写工具，README §4.1） |
| 是否进任务列表 | **不进**。它在导航项里，不在「任务 (N)」里 |
| 能做什么 | 回答问题、检索历史任务与资料（`thread/search` (exp)、`thread/searchOccurrences` (exp)、本机产物索引）、解释产物、推荐场景/技能/专家 |
| 不能做什么 | 写文件、执行命令、访问用户目录 —— 需要动手时引导「转为任务」 |
| 转为任务 | `thread/fork` 出新 thread → 分配真实工作空间 + 切到 Craft → 进入 `/tasks/:id` 并出现在任务列表。原助理会话保留 |
| 上下文长度 | 助理会话会无限增长，需 `thread/compact/start` 策略：token 用量达阈值自动压缩，并在界面上如实提示「已压缩早期对话」 |
| 记忆 | 助理是**用户级记忆的主要读取方**（`memories/read`）；写入仍需显式确认（06 §5） |

**为什么不做成独立形态**：任务列表、产物、审批、预算这些机制全部挂在 Thread 上；助理若自建一套会话存储，就要把这四套机制各做一遍（且与总纲 D6/Q11 的口径分裂）。做成特殊 Thread 后，助理天然拥有排队、中断、搜索、压缩、记忆能力。

**待决策的部分**（Q20）：助理的 token 消耗是否计入用户配额与单任务预算（Q11）。默认**计入**，但在通知与用量视图里单列一项「助理」，避免用户看不懂配额去哪了。

### 4.3 ③ 项目（= 总纲的「空间 / 工作空间」）

映射 `project/*`（实验方法，经 09 §3 适配层收口）。

| 视图 | 内容 |
|---|---|
| 列表 `/projects` | 目录式。卡片 = 空间名 + 根路径（省略中间段）+ 任务数 + 最近活动时间 + 产物数。动作：新建、导入现有文件夹、在此空间新建任务、打开所在文件夹、移除 |
| 详情 `/projects/:id` | 三栏。中栏 = 该空间的任务列表 + 文件树；主区 = 空间概览（最近产物、最近变更、绑定的自动化、空间级记忆 `AGENTS.md` 编辑入口） |

**清单 §4.5 的四个操作**逐一落点：在同一空间新建任务（→ `/home` 且预选工作空间）· 打开所在文件夹（本机 shell 调用）· 从列表移除（`project/delete` (exp)，**只解绑不删文件**，二次确认文案必须说清这一点）· 多根路径（`project/*` 支持绑定多个绝对路径 root）。

**路径失效**：Q1=A 下用户可能移动/删除文件夹。空间卡片需检测根路径存在性，失效时整卡置为 `--warning` 态 + 「路径已失效，重新指定」，**不静默改路径**（与总纲 §6.9 设备迁移同一条原则）。

### 4.7 ⑦ 更多（尾标「灵感」）

截图里「更多」右侧有尾标「灵感」，说明它既是折叠的二级入口聚合，也是内容入口。定义为一个 `Menu`（01 §5.19），分三组：

```
内容
  灵感 / 案例库          → 全部最佳实践案例（首页案例位的完整版）
  使用指南
管理
  设置                   → /settings
  数据管理（含归档任务）  → /settings/data     ← 清单 §4.4「归档后可在系统设置-数据管理中查看」
  设备与同步             → /devices
  用量与预算             → /settings/usage
系统
  检查更新 · 关于 · 反馈 · 退出登录
```

**「数据管理」是归档任务的唯一入口**（清单 §4.4 明确要求），实现为 `thread/list?archived=true` + 批量取消归档/删除 + 本机存储占用明细（rollout 文件、解析缓存、产物索引）。

## 5. 用户区的两个入口（截图 1 底部）

### 5.1 通知中心（铃铛）

抽屉（宽 360，右侧滑入）。EvoWork 需要通知的事件全部来自已定决策，不需要新机制：

| 通知类型 | 触发 | 来源 | 动作 |
|---|---|---|---|
| 待你确认 | 审批请求 / `request_user_input` | `item/*/requestApproval`（README F14） | 跳到该任务的审批卡 |
| 任务完成 / 失败 | `turn/completed` status | 事件流 | 跳到任务 |
| 自动化执行结果 | `automation_run` 落库 | 本机调度器 | 跳到自动化详情 |
| **自动化已自动暂停** | 连续失败 3 次（Q8） | 本机调度器 | 跳到自动化详情 + 「恢复」 |
| **触发被跳过** | misfire / 机器离线 / 超窗（D5） | 本机调度器 | 展示 `skip_reason` 的人话版（07 §5.3） |
| **预算耗尽，已暂停等待你决定** | `ThreadGoal.budget` 用尽（Q11） | 预算闸门 | 跳到任务 + 「追加预算 / 结束任务」 |
| 设备离线提醒 | 绑定设备离线 > 7 天（Q15） | 云端 + 本机 | 「迁移到本机」 |
| 策略包已更新 / 已过期降级 | 签名策略包下发（R11） | 云端控制面 | 查看详情 |

规则：① 通知**全部落本机表**，云端不推送内容（K6）；② 系统级通知（macOS Notification Center / Windows 通知）只发前 5 类，且只带标题不带正文；③ 未读数显示在 `UserFooter` 铃铛与「更多」→无（不做 badge 泛滥）。

### 5.2 设备中心（设备图标）

这个入口是 **Q15 的 UI 落点**，总纲 §6.9 定了数据模型但没定界面。抽屉内容：

```
本机  MacBook-Pro-J  ·  当前设备  ·  最后在线 刚刚
      3 个自动化在此设备运行 · 12 个产物索引在本机
其他设备
      Windows-Office  ·  离线 9 天  ⚠ 超过 7 天
      2 个自动化绑定在此设备（只读）      [迁移到本机]
```

- 「迁移到本机」按 Q15：排他操作 + 云端定义做乐观锁 + **重置 misfire 基准** + 工作空间路径校验失败则拒绝迁移（07 §6）。
- 必须如实说明 A 方案的缺口（总纲 D6）：抽屉底部固定一行 `caption`：「产物与执行历史只保存在各自设备本机，不跨设备同步。」

## 7. 全局搜索（`⌘K`）

截图 1 标题栏第二个图标即此物。四类结果混排，各自最多 5 条：

| 类型 | 数据源 | 备注 |
|---|---|---|
| 任务 | `thread/search` (exp) + 本机投影表标题索引 | 显示状态 Badge + 空间名 |
| 对话内容 | `thread/searchOccurrences` (exp) | 显示命中片段 + 所属任务 |
| 资料 / 产物 | 本机产物索引 + 资料目录（`fs/*`） | 显示类型图标 + 位置 |
| 技能 / 连接器 / 专家 / 场景 | 本机目录 | 直接安装或应用 |
| 命令 | 静态命令表 | 如「新建自动化」「打开数据管理」 |

**隐私约束**：全局搜索**只查本机**（K6）。私有源的技能检索是唯一的联网查询，且只发送查询词、不发送任何本地内容；界面上在结果分组标题右侧标注「来自企业私有源」以示区分。

## 8. Deeplink

即使 Q1=A 是纯本地应用，仍需要 deeplink 支持三个场景：分享链接回跳（Q10）、系统通知点击、CLI 唤起 GUI（Q13）。

```
evowork://task/<threadId>
evowork://automation/<id>
evowork://library/<nodeId>
evowork://share/<shareId>        ← 云端分享页「在 EvoWork 中打开」
evowork://home?scenario=office&prompt=<urlencoded>
```

规则：① deeplink **不携带任何文件内容**，只带 ID 与场景/提示词；② `prompt` 参数只**写入 Composer 不自动发送**（防止外部链接直接触发执行）；③ 未知 ID 时给出明确错误（「该任务不在本机，可能创建于其他设备」）而非空白页 —— 这是 A 方案跨设备缺口的必然结果，要如实说。

## 9. 首次运行与授权引导

Q1=A + K6 决定了必须有一次显式的目录授权，不能默认全盘可读。

```
① 欢迎 + 隐私说明（一屏，讲清"执行都在本机、模型调用会出网"两件事）
② 选择工作空间目录（至少一个）→ 写入首个 project
③ 权限默认值（默认 = 工作空间可写；可选只读）→ 写入 default_permissions
④ 模型接入（登录账号 / 填企业网关地址）→ 验证 model/list 可用
⑤ 可选：安装解析运行时（Python/Node，+100–300MB，R10）→ 可跳过，跳过则文档解析降级（08 §4）
⑥ 完成 → 进首页，Composer 已预选刚建的工作空间
```

第 ⑤ 步必须允许跳过并明确后果，否则 300MB 下载会挡在首次体验前面（R10）。第 ① 屏的两句话是 Q3 承诺的对外表达，措辞需与网关的不落盘承诺（Q14）一致，不得夸大为"完全不出网"。
