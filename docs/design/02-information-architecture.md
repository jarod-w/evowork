## 1. 顶层结构

一级信息架构以“先开始对话，再按需进入管理页面”为原则。侧栏先放高频功能入口，再按“项目 → 项目内最近任务 → 最近未归属任务”组织工作上下文。插件作为统一的产品概念进入一级导航，技能、连接器和专家只在插件页内作为能力分类。

```
EvoWork
├─ 新任务               → 首页 Composer                           03
├─ 搜索                 → 任务标题与对话内容                       §7
├─ 自动化               → 规则与执行历史                           07
├─ 插件                 → 技能 / 连接器 / EvoWork 专家             05
├─ 资料库               → 本地资料与产物                           06
├─ 项目                 → 最近 3 项；每项预览最近 5 个任务           §4.3
├─ 最近任务             → 未在可见项目中展示的任务；按最近活动排序     04
└─ 用户菜单             → 模型与账号 / 用量 / 数据 / 安全 / 审计 / 关于
```

“新任务”是顶部主按钮，同时导航到首页；点击本身不创建 Thread。Thread 仍在首次 `turn/start` 时创建（09 §3.2），所以从首页离开不会留下空任务。

## 3. 主内容区的三种形态

| 形态                   | 用在                                   | 结构                                                     |
| ---------------------- | -------------------------------------- | -------------------------------------------------------- |
| **中心式**             | 首页                                   | 内容列 ≤768 居中：问候 → Composer → 最多 4 个上下文建议 |
| **目录式**             | 插件、项目列表、自动化列表             | 标题栏放 Tab、搜索与一个主动作；内容区使用网格或表格     |
| **管理三栏式**         | 资料库、复杂项目详情                   | 侧边栏 + 可选中栏 272 + 主区                             |
| **对话工作式**         | 任务工作台                             | 侧边栏 + 对话；结果工作区按内容和用户意图打开            |

三种形态共用同一侧边栏与标题栏带（01 §3.2），切换时**侧边栏不重绘**（只换选中态），主内容区做 `--dur-base` 淡入。

## 4. 各入口的功能定义

### 4.1 ① 新建任务

见 03。要点：这是产品的默认落地页；冷启动、关闭最后一个任务、点击「新建任务」都到这里。

### 4.2 ② 助理（**2026-09-07 下架 · 方案保留**）

> **状态：本期不做。** 侧边栏入口、路由、图标与空态文案已从 `apps/desktop` 移除，`apps/desktop/test/app.test.tsx` 有一条断言钉住"侧边栏里没有助理"。
>
> **为什么下架**：下表这条链路（固定 thread + 固定 cwd + 默认 Ask + 自动压缩 + 读用户级记忆）**一行都没实现**，入口只能落到一个「还没做好」的空页 —— 那是在产品骨架上占一格去说一句道歉，而侧边栏的每一项都在向用户承诺"这里有东西"。
>
> **恢复它要做什么**：先有这条链路，再把 `MAIN_NAV` 那一项与 `NAV_TO_VIEW` 的视图加回来，并删掉那条断言。下面的方案（Q20 已决策）**不作废**，它就是恢复时照着做的东西。

截图有此入口，总纲无对应条目。决策方案（Q20）：**助理 = 一个常驻的特殊 Thread**，不是独立产品形态。

| 项             | 设计                                                                                                                                |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 身份           | 单一固定 thread（`assistant_thread_id` 存本机配置），冷启动时 `thread/resume`，不存在则 `thread/start`                              |
| cwd            | `~/.evowork/assistant/`（一个空工作目录，不指向用户任何真实文件夹）                                                                 |
| 默认模式       | 内部走 `evowork-ask`（只读 + 无网络）。**不出现在 Composer 三档里**（Q45）               |
| 是否进任务列表 | **不进**。它在导航项里，不在「任务 (N)」里                                                                                          |
| 能做什么       | 回答问题、检索历史任务与资料（`thread/search` (exp)、`thread/searchOccurrences` (exp)、本机产物索引）、解释产物、推荐场景/技能/专家 |
| 不能做什么     | 写文件、执行命令、访问用户目录 —— 需要动手时引导「转为任务」                                                                        |
| 转为任务       | `thread/fork` 出新 thread → 分配真实工作空间 + 切到「请求批准」→ 进入 `/tasks/:id` 并出现在任务列表。原助理会话保留                  |
| 上下文长度     | 助理会话会无限增长，需 `thread/compact/start` 策略：token 用量达阈值自动压缩，并在界面上如实提示「已压缩早期对话」                  |
| 记忆           | 与普通新任务一样由 Codex 自动使用已提取记忆；当前 app-server 不提供正文列表或逐条写入接口，助理不另造一套记忆 UI                         |

**为什么不做成独立形态**：任务列表、产物、审批、预算这些机制全部挂在 Thread 上；助理若自建一套会话存储，就要把这四套机制各做一遍（且与总纲 D6/Q11 的口径分裂）。做成特殊 Thread 后，助理天然拥有排队、中断、搜索、压缩、记忆能力。

**已定规则**（Q20）：助理若未来恢复，其 token 消耗计入用户配额与单任务预算（Q11），并在通知与用量视图里单列一项“助理”。

### 4.3 项目（对外统一名称）

映射 `project/*`（实验方法，经 09 §3 适配层收口）。

| 视图                 | 内容                                                                                                                                             |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 列表 `/projects`     | 目录式。卡片 = 项目名 + 根路径（省略中间段）+ 任务数 + 最近活动时间 + 产物数。动作：新建、导入现有文件夹、在此项目中新建任务、打开所在文件夹、移除 |
| 详情 `/projects/:id` | 项目页集中显示任务、文件、项目说明和自动化。侧栏同时在项目行下预览最近 5 个任务，完整清单仍在项目页。                                                           |

侧栏“项目”标题行在悬停、键盘聚焦或项目页选中时显示 `⋯` 与 `+`：`+` 不要求先进入项目页，
直接打开共用的“创建项目”对话框；`⋯` 收口“查看所有项目”和“导入现有文件夹”。创建、
导入、改名或移除成功后，侧栏与 Composer 的项目快照必须同步更新，不能只刷新项目页卡片。

**建项目的第四个入口：Composer 里直接选文件夹**（2026-10-01，[选目录即建项目 spec](../superpowers/specs/2026-09-27-composer-pick-folder-design.md)）。
「选择项目」菜单底部常驻「选择文件夹…」，选完后建成项目并选中（03 §4.5）。四个入口（引导第②步、`+` 新建、导入、Composer）
走同一条后台路径，下面三条规则都在那里，任何入口都绕不过去：

- **去重**：选中的目录解析软链后与某个已有项目的根相同，就复用那个项目（Toast「这个文件夹已经是项目「X」」），不新建、不重复镜像。
  新建对话框里撞上已有项目时同样复用，用户填的名字不生效。
- **自动命名**：用目录名；与已有项目重名时写成「目录名 · 上级目录名」，仍重名追加「 (2)」。用户在新建对话框里自己填的名字不改。
- **不能当项目根的目录**：磁盘根、主目录本身及其上级、`~/.evowork`（10 §2.3）。

**侧栏排序与任务归属**（同一 spec，Q-F4 / Q-F5）：

- 侧栏的项目按**最近活动**排序：该项目下最近一个任务的时间，一个任务都没有时用创建时间。Composer 的默认预选用同一个函数。
  原先按创建时间排序，选文件夹变成一步操作以后，新建的项目会把正在用的老项目挤出侧栏前 3 个。
- 任务属于**匹配最长的项目根**。嵌套项目（monorepo 里的仓库与子包）里的任务只算最深的那个，侧栏分组与项目卡片计数共用这一个判定，
  不再出现同一个任务同时算进两张卡片的情况。

**「最近产物」与「最近变更」已合并为「最近的文件动作」**（2026-09-07）：两者在数据上
是 `artifact` 表的同一批行（`operation_kind` 区分生成与修改），分成两块会让同一个文件
在上下各出现一次。列：文件 · 动作 · 来自哪个任务 · 时间。

**清单 §4.5 的四个操作**逐一落点：在同一项目新建任务（→ `/home` 且预选项目）· 打开所在文件夹（本机 shell 调用）· 从列表移除（`project/delete` (exp)，**只解绑不删文件**，二次确认文案必须说清这一点）· 多根路径（`project/*` 支持绑定多个绝对路径 root）。

**路径失效**：Q1=A 下用户可能移动/删除文件夹。空间卡片需检测根路径存在性，失效时整卡置为 `--warning` 态 + 「路径已失效，重新指定」，**不静默改路径**（与总纲 §6.9 设备迁移同一条原则）。

### 4.7 用户菜单

侧栏不设置“更多/灵感”运营入口。低频管理功能统一收入左下用户菜单（01 §5.19）：

```
账号

管理
  用量与预算             → /settings/usage
  数据管理（含归档任务）  → /settings/data
```

## 5. 通知与设备（接通后再暴露）

当前用户区只显示统一用户菜单。通知中心与设备中心的产品定义保留在下文，但在数据与动作端到端接通前不显示入口；不得以可点击空壳占用主路径。

### 5.1 通知中心（铃铛）

抽屉（宽 360，右侧滑入）。EvoWork 需要通知的事件全部来自已定决策，不需要新机制：

| 通知类型                       | 触发                            | 来源                                   | 动作                                   |
| ------------------------------ | ------------------------------- | -------------------------------------- | -------------------------------------- |
| 待你确认                       | 审批请求 / `request_user_input` | `item/*/requestApproval`（README F14） | 跳到该任务的审批卡                     |
| 任务完成 / 失败                | `turn/completed` status         | 事件流                                 | 跳到任务                               |
| 自动化执行结果                 | `automation_run` 落库           | 本机调度器                             | 跳到自动化详情                         |
| **自动化已自动暂停**           | 连续失败 3 次（Q8）             | 本机调度器                             | 跳到自动化详情 + 「恢复」              |
| **触发被跳过**                 | misfire / 机器离线 / 超窗（D5） | 本机调度器                             | 展示 `skip_reason` 的人话版（07 §5.3） |
| **预算耗尽，已暂停等待你决定** | `ThreadGoal.tokenBudget` 用尽（Q11） | 预算闸门                               | 跳到任务 + 「追加预算 / 结束任务」     |
| 设备离线提醒                   | 绑定设备离线 > 7 天（Q15）      | 云端 + 本机                            | 「迁移到本机」                         |
| 策略包已更新 / 已过期降级      | 签名策略包下发（R11）           | 云端控制面                             | 查看详情                               |

规则：① 通知**全部落本机表**，云端不推送内容（K6）；② 系统级通知（macOS Notification Center / Windows 通知）只发前 5 类，且只带标题不带正文；③ 未读数显示在 `UserFooter` 铃铛与「更多」→无（不做 badge 泛滥）。

### 5.2 设备中心（设备图标）

这个入口是 **Q15 的 UI 落点**，总纲 §6.9 定了数据模型但没定界面。抽屉内容：

```
本机  MacBook-Pro-J  ·  当前设备  ·  最后在线 刚刚
      3 个自动化在此设备运行 · 12 个产物索引在本机
其他设备
      Windows-Office  ·  离线 9 天  ⚠ 超过 7 天
      2 个自动化绑定在此设备（只读）      [迁移到本机]
```

- 「迁移到本机」按 Q15：排他操作 + 云端定义做乐观锁 + **重置 misfire 基准** + 工作空间路径校验失败则拒绝迁移（07 §6）。
- 必须如实说明 A 方案的缺口（总纲 D6）：抽屉底部固定一行 `caption`：「产物与执行历史只保存在各自设备本机，不跨设备同步。」
- **登录设备的吊销**是另一件事（[11 Q40](11-account-and-models.md)）：权威在 identity，WEB 账号页与本抽屉都能触发。按钮文案分开 —— 「吊销登录」作废该设备的 refresh；「迁移到本机」改的是 automation 的 `device_id`。未登录时不向 identity 拉设备列表（11 §13.4）。

## 7. 全局搜索（`⌘K`）

截图 1 标题栏第二个图标即此物。四类结果混排，各自最多 5 条：

| 类型                        | 数据源                                     | 备注                             |
| --------------------------- | ------------------------------------------ | -------------------------------- |
| 任务                        | `thread/search` (exp) + 本机投影表标题索引 | 显示状态 Badge + 空间名          |
| 对话内容                    | `thread/searchOccurrences` (exp)           | 显示命中片段 + 所属任务          |
| 资料 / 产物                 | 本机产物索引 + 资料目录（`fs/*`）          | 显示类型图标 + 位置              |
| 插件能力（技能 / 连接器 / 专家） | 本机目录                                | 打开插件页或直接使用             |
| 命令                        | 静态命令表                                 | 如「新建自动化」「打开数据管理」 |

**隐私约束**：全局搜索**只查本机**（K6）。私有源的技能检索是唯一的联网查询，且只发送查询词、不发送任何本地内容；界面上在结果分组标题右侧标注「来自企业私有源」以示区分。

> **当前实现边界（2026-09-15）**：`⌘/Ctrl + K` 与侧栏入口打开覆盖在当前界面上的全局搜索面板；
> 空查询显示最近聊天与快捷操作，输入后使用 `thread/search` 显示任务标题和对话正文摘要，点击后可继续旧任务；
> 实验方法不可用时如实退回本机标题搜索。`thread/searchOccurrences` 的单消息定位、
> 资料/产物/插件结果混排和高级筛选仍是本节目标，尚未进入面板。

## 8. Deeplink

即使 Q1=A 是纯本地应用，仍需要 deeplink 支持三个场景：分享链接回跳（Q10）、系统通知点击、CLI 唤起 GUI（Q13）。

```
evowork://task/<threadId>
evowork://automation/<id>
evowork://library/<nodeId>
evowork://share/<shareId>        ← 云端分享页「在 EvoWork 中打开」
evowork://home?scenario=office&prompt=<urlencoded>
```

规则：① deeplink **不携带任何文件内容**，只带 ID 与场景/提示词；② `prompt` 参数只**写入 Composer 不自动发送**（防止外部链接直接触发执行）；③ 未知 ID 时给出明确错误（「该任务不在本机，可能创建于其他设备」）而非空白页 —— 这是 A 方案跨设备缺口的必然结果，要如实说。

**2026-09-27 落地**（`apps/desktop/src/main/deeplink.ts` + `bootstrap.ts`）。三条规则各自的实现处：

| 规则 | 落在哪 | 怎么守住 |
| --- | --- | --- |
| ① 不携带文件内容 | `DeeplinkTarget` 这个联合 | 类型里没有能装内容的字段；`test/deeplink.test.ts` 扫这个联合的源码 |
| ② `prompt` 只写入不发送 | 解析结果里那个字段**叫 `prefill`** | 名字是这条规则最便宜的守卫 —— 一个叫 `prompt` 的字段迟早会被接到发送上。测试同时扫源码里没有 `send(` / `autoSend` / `submit` |
| ③ 未知 ID 给明确错误 | `resolveDeeplink` 查本机有没有 | 解析成功与**找得到**是两种结果，不是一种。四句话各自说清"不在这台电脑上"意味着什么 |

**另外两件缺了任何一件都比"深链不工作"更糟**：不注册协议 → 点了什么都不发生；不要单实例锁 → 点链接会再开一个应用，两个进程抢同一个 sqlite。

> **2026-09-27 订正：上面这两件当天写下来了，但没有被实现。**
> `bootstrap.ts` 对着注入端口接得好好的，而真入口 `electron-entry.mjs` 的端口里
> **一项都没填**（`setAsDefaultProtocolClient` / `onOpenUrl` / `onSecondInstance`），
> bootstrap 用 `?.` 调它们 —— 漏填不报错、不打日志。`requestSingleInstanceLock`
> 更彻底：类型上有声明、配着一段讲"两个进程抢同一个 sqlite"的注释，**从没有被调用过**。
> 再加上 `build/electron-builder.yml` 当时没有 `protocols:`，产物的 Info.plist 里没有
> `CFBundleURLTypes` —— 而 macOS 上 `setAsDefaultProtocolClient` 只能注册已经写进
> Info.plist 的 scheme。四处叠起来：装出来的应用上，`evowork://` 点了毫无反应。
>
> 四处都已补齐。真正的修复是第五处：`apps/desktop/test/electron-entry-port.test.ts`
> 把 bootstrap 对端口的全部访问与真入口实际提供的键对出包含关系 —— 真入口是 `.mjs`、
> 本来就不在类型检查里，这个洞不堵会一直在。

**推还是存，由渲染层订阅没订阅决定**（2026-09-27 实现时发现的一处真缺陷，同日订正过一次）：
渲染层还没挂载、还没订阅事件时，`webContents.send` 推过去**就丢了** —— 用户那一侧是
"点了链接什么都没发生"，而日志里一切正常。所以主进程存一条待领的
（`service-host.ts` 的 `pendingDeeplink`），渲染层挂载后 `takeDeeplink` 领一次、领完清掉。

第一版的判据是一个叫 `cold` 的布尔，只有 argv 那条路传 `true`。**那等于把"冷启动"和
"走 argv"当成了同一件事** —— 在 Windows / Linux 上成立，在 macOS 上不成立：那边系统用
`open-url`，而用户在应用没开着的时候点一条分享链接，那个事件会在 `whenReady`
**之前**就来。那同样是冷启动，只是不走 argv，于是被当成热路径直接推掉、丢了。
现在判据是 `host.rendererSubscribed()`，信号取自渲染层挂载时那一次 `takeDeeplink()`
（它在挂载 effect 里，而订阅 `onUiEvent` 的 effect 紧挨在后面、同一次 commit 里同步跑完，
所以那条 IPC 到主进程时订阅一定已经在了）。**那个调用因此不只是取值** ——
`app.test.tsx` 有一条守着它别被删掉。

**验到哪一步**（2026-09-27 在真 `.app` 上跑出来的，不是推断）：

| | 结论 | 证据 |
| --- | --- | --- |
| 冷启动 argv | ✅ | 真 `process.argv` → 解析 → 查本机 → 待领 → 渲染层领走 → 画出来，断言规则 3 那句错误 |
| 协议注册 | ✅ | `lsregister -dump` 里这个包 `claimed schemes: evowork:` —— **整条链路上唯一一条不是我们自己说的证据** |
| 单实例锁 | ✅ | 三条判据缺一不可：第二个实例干净退出 · 它那个**全新的 `EVOWORK_HOME` 目录没被建出来**（证明没走到开库）· argv 递到第一个实例并画了出来 |
| macOS `open-url` 的派发 | **验不到** | 直接 exec 起的进程收不到那个 Apple Event（实测：`open` 退出码 0、不新起进程、连看 20 秒没反应）；而经 LaunchServices 启动就没法把 `EVOWORK_HOME` 递进去，测试会跑在**用户真实数据**上 |

最后一条**单独登记，不并进"深链验过了"**。`launchctl setenv EVOWORK_HOME` 技术上能绕开隔离问题，
但那是会话级的全局改动：脚本中途崩掉就会把用户自己的 EvoWork 指到一个临时目录，
下次打开像是数据全没了。为一条断言不值。

「macOS 会不会早发 `open-url`」是 Apple 的行为，验不了也不必验；
「**它早到了我们会不会丢**」是我们的行为，已经拎进 `main/early-events.ts` 单独测了
（接线前到的要补发 · 接线后到的直接走 · **补发完要清空**，否则第二次接线会重放旧链接）。

**还有一条不在上表里，因为它比上面任何一条都大**：热路径的 `webContents.send` 推的是
`evowork:event`，而渲染层监听的是 `evowork:ui-event`（`preload` 的 `RENDERER_CHANNELS.uiEvent`）。
少三个字符，`send` 照常返回、不报错 —— **"应用开着的时候点深链"从来没有工作过**。
冷启动走拉（队列）所以一直是好的，正是它把这件事盖住了。
现在频道走 `IPC.uiEvent` 常量，并有一条类级别的断言守着「主进程发的每个频道，渲染层都得在听」。

`evowork://share/<id>` 有一条专门的文案：点它的多半是**接收方**，他本机当然没有这份产物，所以话是「它是别人分享给你的，请用网页上的下载」而不是含糊的「打不开」。

## 9. 首次运行与授权引导

Q1=A + K6 决定了必须有一次显式的目录授权，不能默认全盘可读。

```
① 欢迎 + 隐私说明（一屏，讲清"执行都在本机、模型调用会出网"两件事）
② 选择项目目录（至少一个）→ 写入首个 project
③ 可选：安装解析运行时（Python/Node，+100–300MB，R10）→ 可跳过，跳过则文档解析降级（08 §4）
④ 完成 → 进首页，Composer 已预选刚建的项目
```

引导仍不问默认权限：Composer 三档已经接到 `turn/start`，但引导里选一个看起来像全局默认、实际只对当前任务生效的档，会让人以为改了本机默认。权限档继续只在 Composer 里选。

模型不在引导里配。走完之后去「设置 → 模型」添加自定义模型；没配时 Composer 顶部 danger 条挡住发送，并给「去设置添加模型」（03 §8：**不静默换一个模型**）。

第 ③ 步必须允许跳过并明确后果，否则 300MB 下载会挡在首次体验前面（R10）。第 ① 屏的两句话是 Q3 承诺的对外表达，措辞需与网关的不落盘承诺（Q14）一致，不得夸大为"完全不出网"。
