# 20 · 外部记忆导入

2026-10-17。Claude Code 项目记忆复用发货内核专用迁移协议；WorkBuddy 文本快照复用正式模型工具及 hook 回执，见本文末节。不自建记忆正文库。

## 入口与流程

「设置 → 导入」、个性化的「导入已有记忆」、`/memories` 弹窗链接及本地 `/import` 命令共用向导。命令不创建任务、不发送模型请求。来源确认后才检测；按项目勾选，确认后仅导入 MEMORY 项，不迁移配置、会话、插件或指令。取消检测/选择不写入记忆。无可靠项目路径的来源由内核跳过，不改绑为全局记忆。

四步：选择 Claude Code → 检测并选择项目 → 确认本机目的地及模型整理用量 → 展示各项目导入结果。项目目录只展示协议提供的可靠元数据，不能从编码后的来源项目键猜路径。未变化项目不重复提供；默认手动更新，重新检测并确认。手动更新按来源现状同步副本（包括文件删减），确认页明确说明。可显式开启自动同步，范围与行为见下方第二版。

## 协议边界

适配层调用 `externalAgentConfig/detect`、`externalAgentConfig/import`、`externalAgentConfig/import/readHistories`。宿主只接受本次检测签发的候选选择，过滤全部非记忆迁移项目；提交前复核候选仍可导入。首版通过按需轮询原生导入历史核对完成结果，不依赖瞬时通知。提交前拒绝时回到重新选择；写请求失败或结果未知不自动重放，提示检查历史后重新检测。

产品补齐缺失的 `features.external_agent_memory_import = true`，保留明确 false；实际方法不可用或配置关闭时明确降级。记忆使用、生成及提取/整理模型设置保持不变，导入后可显式开启读取，不能顺带打开生成。

资料复制成功不等于整理就绪。完成页说明后台整理后用于后续新任务，不承诺已加载任务热更新；V1 无整理进度，V2 状态也不能证明某次导入已完成整理。整理会沿用获准模型及网关、消耗用量，导入确认页须说明。原始文件解析与复制在本机，不声称模型整理也不出网。

## 边界与首版验收

Claude Code 迁移路径无任意文件导入、Cursor 记忆、逐条编辑、批次撤销、云端同步或中心记忆发布；WorkBuddy 的显式文本/文件快照入口见末节。清空沿用原生能力；导入历史是操作记录，不冒充尚存的记忆条目。

先用隔离 HOME 和合成 Claude 来源验证发货内核，再验证真实 Electron/IPC/适配层/原生导入及后台整理。覆盖取消零写入、仅选中项目、重复检测、部分失败、历史刷新/重开、不支持/关闭、禁读和命令不进入网关。合成网关只验证调度、工具执行及上下文传递，不据此声称真实模型整理质量或严格知识隔离；项目范围由原生来源记录与整理指令维护。

已验证结果与命令见 [2026-10-17 验收记录](../verification/2026-10-17-memory-import.md)。

MiMo 真实模型补验中，两个项目均正确使用各自约定，单任务/全局禁读没有注入索引，未导入项目没有借用其他项目约定。但全局索引实际含两个项目的具体内容，三个项目的读取任务均可见，且可检索共享正文。因此首版只验证了本轮 scope 遵循行为，不提供按项目不可见或任意文件读取的 ACL；不能把「本轮未误用」表述为严格隔离。

## 第二版：接口复用与同步（已接通）

发货二进制基线 `d583e73c4d12`，沿用 P6，不新增内核补丁。`AgentMessage.memoryCitation` 提供路径、行号、说明及关联任务；前端只展示协议给出的引用，不读取记忆正文，不把模型引用当作完整检索审计。历史与实时消息走同一条规范化链路。

`memory/status` 仅返回 V2 整体已整理任务数与就绪布尔值。设置页与导入结果显示同一状态，允许刷新；V1 明示不提供进度。没有批次整理进度、错误或重试接口，因此不编造百分比、失败原因或“重新整理”动作，也不为显示状态切换管线。

发货协议没有自动同步调度/配置方法。复用原生 `detect` 的变化检测与 `import` 的同步复制，由适配层增加默认关闭、每分钟一次的本机调度。开启时冻结用户确认的 Claude Code 已导入项目清单；新增来源项目与后来导入项目不自动扩大授权。界面列出范围并说明文件删减同步和后台模型用量。仅保存授权与操作状态，不扫描/解析来源文件或保存记忆正文。关闭后不再提交写操作；已提交操作可能完成。

同步与手动导入串行。后台同步不消费/替换向导的候选选择。提交前复核授权，先持久化暂停状态再发写请求，成功取得原生 importId 后等历史确认完成；超时、断线、部分失败或进程在写入中退出均暂停并提示核对历史，不自动重放。应用重开保留范围与开关；仅在开关开启时调度，应用退出停止。源项目整体消失时原生检测可能不再提供候选，因此不承诺自动遗忘来源项目或撤销衍生记忆。

严格隔离与按项目遗忘只做[独立方案](21-project-memory-isolation-and-forgetting.md)，不在本轮实现。不能将同步删除副本表述为删除所有衍生知识。

本轮接口核实、确定性与 MiMo 实模型结果、内核重启专项检查见[第二版验收记录](../verification/2026-10-17-memory-capabilities.md)。

## WorkBuddy 文本快照导入

发货内核没有通用 memory/write RPC；正式模型工具 `memories.add_ad_hoc_note` 可写入追加式记忆资料。首版通过专用临时会话调用该工具，复用已受信任的策略包 PostToolUse hook 与公开 hook/completed 通知，以文件名和 SHA-256 核对正文。禁止依赖标为 internal use only 的 experimentalRawEvents；模型说“已保存”不算回执。没有受信任的同步 PostToolUse hook 时明确不可用。

设置与 /import 共用来源选择，WorkBuddy 支持粘贴或读取用户选择的 UTF-8 Markdown/TXT（最多 64 KiB），本地预览编辑后再确认。确认时选择已有可用模型、个人偏好或已登记项目；模型与范围在提交时重新校验。只有确认导入才创建临时环境/会话并经既有模型网关发送正文，提示模型用量与后续整理延迟。不会扫描 WorkBuddy 私有目录、登录其账号或自动同步。

正文包含来源和用户确认的 scope，作为不可信历史资料，不升级为系统指令。原文直接放在带内容摘要的快照边界之间，再作为工具 JSON 参数发送；避免原文先变为 JSON 字符串导致模型解开内层转义。成功仍要求正文哈希匹配；只规范化快照结束标记外的尾部 LF，原文内空行、范围、标记和空格均保持精确。项目标签仅表达使用范围，当前内核无项目 ACL；个人资料才可成为跨项目偏好。文本不写入独立产品记忆库，宿主只存哈希、范围、时间、原生文件名和结果。相同规范化文本与范围不重复提交；重启、断线、超时或缺少可信回执标为结果未确认，不自动重放。导入与 Claude 同步/导入、清空串行；正常完成后取消临时会话订阅。整体清空成功才清除相应去重登记。

编辑后的内容作为新快照追加，不覆写或自动撤回之前的记忆。临时会话使用公开 threadSource 标记，启动通知早于响应时也不会进入任务页或触发队列查询；完成后取消订阅。若超时后无法确认原生回合已经停止，则暂停后续记忆写操作，需重开应用后核对；不通过自动重启内核解决未知写入。

原生 ad-hoc 工具只保存资料，不主动 enqueue 整理；临时会话不运行后台提取。后续普通新任务启动内核整理，仍受六小时成功冷却期等原生约束。保存成功不代表已整理可用，不能靠重启内核或生产代码修改作业时间戳加速。端到端测试分别证明保存回执、后续整理及新任务使用；测试专用时间夹具必须在证据中注明。
