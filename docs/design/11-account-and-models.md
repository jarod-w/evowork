## 0. 一句话

「用户注册」和「模型管理」现在被同一个网关令牌串在一起，但它们**不是一件事**：模型管理是纯本机的事（不需要账号，今天就能做，顺手关掉 status.md §4 的第一个卡住项），账号是 D9 已批准的第一项云端职责（需要一套云上部署与若干非技术前置条件）。**先做前者、后者单独立项**，是本文的核心建议。

### 1.2 现状的三个结构性问题

不是"还没写"，是**写法会在加账号时出错**：

| # | 问题 | 现在为什么不出错 | 加了账号之后为什么会出错 |
| --- | --- | --- | --- |
| 1 | **拓扑靠 URL 反推** | 只有两种情况（本机 / 别处），一个布尔值够用 | 会有三种上游（§3），而且**同一台机器上可以同时存在两种**（Q36=A）。「云端托管」与「企业私有」的 base_url 都不是 loopback，但**令牌来源、密钥归属、登录目标 IdP 全都不同** —— 一个布尔值分不开，而分错的表现是"下拉 401，而真正的网关在别人的机器上"（[gateway-env.ts:140](../../apps/desktop/src/main/gateway-env.ts#L140) 的注释已经预见到这一点） |
| 2 | **密钥与令牌是同一档明文文件** | 单机自用，威胁模型就是"别提交进仓库" | 托管形态下 refresh token 等价于账号本身。明文文件里放一个能换钱的凭据，与 Q14「密钥托管」的整个卖点冲突 |
| 3 | **模型表只有一层** | P0 三家钉死，`verified` 字段如实透出，够用 | 企业要锁模型（R11）、用户要加私有 endpoint（Q29 保留的配置项）、托管与 BYOK 要共存（Q36=A）—— 三个需求都要求这张表可被覆盖，而覆盖就要定**合并顺序** |

## 2. 核心判断：两件事，不是一件

| | 模型管理（BYOK 面） | 账号（托管面） |
| --- | --- | --- |
| 回答什么 | 有哪些模型 · 哪家配了密钥 · 密钥存哪 · 私有 endpoint 怎么加 | 我是谁 · 额度还剩多少 · 企业策略是什么 · 分享链接归谁 |
| 在哪执行 | **全部本机** | 云端 + 本机令牌生命周期 |
| 需要账号吗 | **不需要** | 是它本身 |
| 需要云上部署吗 | 不需要 | 需要（§10.1 的外部前置条件） |
| 与 D9 的关系 | 无关（本机事） | D9 四类云端职责的**第一与第四类** |
| 量级 | 1–1.5 人周 | 2–3 人周 + 一套云上部署 + 非技术前置 |

**捆在一起做的具体风险**，D9 的原话已经写在那儿了：

> 后续任何设计若需要"服务端在用户离线时替他做事"，必须先回到本条重新决策。

一旦有了账号，"任务列表存云端好方便跨设备"这种需求会自己长出来 —— 而 Q17 刚刚否掉了个人云盘、Q19 刚刚把团队空间压成只读订阅。**账号必须被设计成"解锁若干云端职责的凭据"，而不是"数据的归属主体"**。这条是本文所有取舍的出发点，§6 是它的机制化。

## 3. 三种上游必须显式建模（拓扑是每个模型一条链路）

### 3.1 上游表

**前提（D11，§11.3）**：**本机网关常驻**，它是内核唯一的 provider 端点 —— 内核看到的 `model_providers.evowork.base_url` **恒为 loopback**。下面三种是**本机网关的上游**，不是"整机的形态"：**A 与 B 可以同时存在于一台机器**（Q36=A），一个模型走哪条由它的 `credentialSource`（§4.2）决定。

| 上游 | 谁在对面 | 厂商密钥归谁 | 访问令牌谁签 | 账号 | 什么时候走这条 |
| --- | --- | --- | --- | --- | --- |
| **A · 本机 BYOK** | 用户填的厂商 endpoint（本机直连） | **用户自己**（`safeStorage`） | 无 —— 不经过我们的任何服务 | **不需要** | 用户的自定义模型；**断网时唯一还能用的一条** |
| **B · 云端托管** | 我们的云端网关 | 我们 / 租户管理员（Q14 密钥托管，§13.2） | identity 签发的短期 JWT | **必需** | 管理员配置的默认模型 |
| **C · 企业私有** | 客户机房的网关 | **客户自持**（Q14 私有部署包） | 客户的 identity，或静态 token | 企业 SSO（OIDC） | 私有化交付时的默认模型 |

**A 与 B/C 的区别不只是"钱谁付"**：A 这条链路上没有我们的任何服务，所以它是 Q30=A「未登录也能用」和 K6「本地优先」的物理实现，而不只是一句承诺（验收口径第 14 条：拔网线后 A 仍可用）。

### 3.2 mode 是权威，上游 URL 是派生的

`mode` 回答的是"**默认模型的上游在哪**"，**不是"网关在哪"** —— 网关永远在本机（§3.1）。新增 EvoWork 自己的配置文件 `~/.evowork/app.toml`（**不进 `config.toml`** —— 那是内核的配置文件，理由已写在 [service-host.ts:71-76](../../apps/desktop/src/main/service-host.ts#L71-L76)：混进去等于让内核的配置文件承载我们的凭据）：

```toml
[gateway]
# 默认模型的上游在哪（§3.1 的 A / B / C）：
#   local   = 没有默认模型，只有用户自己的自定义模型
#   hosted  = 我们的云端网关
#   private = 客户机房的网关
mode = "local"
# private 时必填；local / hosted 由宿主按 mode 生成，不接受手填
upstream_base_url = ""
```

**字段名是 `upstream_base_url` 而不是 `base_url`**：内核的 `config.toml` 里已经有一个 `model_providers.evowork.base_url`（[config.toml.template:23-30](../../config/config.toml.template#L23-L30)），而那一个**恒为 loopback、宿主生成一次就不再变**。两个都叫 `base_url` 正是把"网关在哪"和"上游在哪"混成一件事的那个源头 —— 这个混淆已经付过一次代价（§1.2 问题 1）。

**方向必须是 mode → 上游，不能反过来**：`isLocalGateway()` 退化为一处一次性兼容读取（老装机的 `config.toml` 里已有非 loopback 的 base_url 而 `app.toml` 还不存在时，按 URL 反推一次并写回 `app.toml`，之后不再推断）。**内核侧的 base_url 从此不携带任何拓扑信息**，D11 的第①条机制化就是这个。

**为什么值得为此加一个文件**：上游决定了四件事的走向（要不要连我们的云、令牌哪来、密钥归谁、登录到哪个 IdP）。让这四件事各自去猜同一个 URL，就是 CLAUDE.md §9.1「两个模块各自对，合起来可能不对」的标准形状 —— 而这次合起来错了的表现是一个 401，最难查的那种。

## 4. 阶段 1 · 模型管理（不依赖账号，今天就能做）

### 4.1 模型注册表的四层与合并顺序

| 层 | 来源 | 谁能改 | 能做什么 |
| --- | --- | --- | --- |
| **① 内置元数据** | 代码里的 `P0_MODELS`（capabilities.ts） | 我们 | 只提供"这个 model id 长什么样"：能力徽标 · 上下文长度 · `verified`。**不自带凭据，所以单靠它不能让一个模型可用** |
| **②' 租户默认模型** | 云端网关的目录端点；租户管理员在 WEB 管理端配置（Q37=B，§13.2） | 租户管理员 | 增删默认模型 · 上游 base_url / key / 协议适配类型 · 每人额度 |
| **② 企业覆盖** | **签名策略包**（R11 已有通道，不新建） | 租户管理员 | 停用某模型 · 改 `allowed` · 锁定 `allow_custom_models` |
| **③ 本机自定义** | `~/.evowork/models.toml` + `safeStorage`（Q34=A） | 用户 | **只能追加**私有 endpoint（Q29 保留的配置项，`PRIVATE_MODEL_*` 那组 env 是它的雏形）。追加时**必须选协议适配类型**，理由同 §13.2 |

**合并顺序：② > ②' > ③ > ①**。

- **② 压所有**：它是禁令。反过来的话企业锁不住 —— 用户在 `models.toml` 里加一条就绕过了策略包，那 R11 的整个缓解手段就没了
- **②' 压 ③**：同一个 model id 冲突时租户口径优先
- **① 垫底**：它只是元数据。这也解释了为什么"内置三家"不等于"能用三家" —— 能不能用取决于②'有没有配、或③有没有填密钥

**被企业停用的模型要显示成「被企业策略停用」，不隐藏。** 这与 [10 §2.2](10-security-permissions-ux.md) 的「未知 profile 显示 id 本身，不隐藏」是同一条纪律：消失的东西无法被排查，而用户会去问客服"我明明配了密钥为什么没有"。

### 4.2 每个模型标出凭据来源

`ModelCatalogEntry`（[gateway/src/catalog.ts](../../services/gateway/src/catalog.ts)）新增一个字段：

```ts
readonly credentialSource: 'byok' | 'hosted' | 'private';
```

下拉里跟着 `provider/model` 一起显示（01 §5.15 的等宽标签旁）。**为什么这必须对用户可见**：它同时回答"这次调用花的是谁的钱"和"数据过的是谁的境"。后者是 K6 隐私叙事的一部分 —— 一个用户以为在用自己密钥、实际走了我们托管的调用，是**隐私承诺层面的**问题，不是计费问题。

这个字段也是 **Q36=A（共存）**的数据面：登录用户的下拉里会**同时**出现 `hosted` 的默认模型和 `byok` 的自定义模型，靠这个标签区分。

**它同时是一条安全边界**：`hosted` 条目在**类型层面**就不带 `apiKey`，也不带上游 `baseUrl` —— 那把 key 属于服务端，不属于这台机器（§13.2，验收口径第 13 条）。

### 4.3 密钥存储：Electron `safeStorage`

| 项 | 落法 |
| --- | --- |
| 存 | `safeStorage.encryptString()` → 密文写 `~/.evowork/secrets.bin`（macOS Keychain / Windows DPAPI / Linux libsecret 托底） |
| 用 | 宿主解密后**经进程环境注入网关子进程** —— 网关只从进程环境读密钥（[gateway/src/main.ts](../../services/gateway/src/main.ts)），这条路径现成，全程不落明文盘 |
| 读回 | **不读回渲染层**。UI 只显示「已保存 · 后四位」，改就是整条覆盖（延续 [ipc.ts:388-394](../../apps/desktop/src/shared/ipc.ts#L388-L394) 已有的纪律：密钥只走一次 IPC，不回传、不进日志） |
| 迁移 | 首次启动时若存在 `gateway.env` 且 `secrets.bin` 不存在 → 导入后**把 `gateway.env` 改名为 `gateway.env.migrated`**，不删（`docs/build-and-deploy.md` 一直让人写那个文件，静默删掉会让照文档操作的人困惑） |
| **不在这里的** | **管理员配置的默认模型的 key** —— 它只存服务端，从不下发（§13.2）。`/settings/models` 里那些标「由管理员配置」的条目，连后四位都不显示：那不是用户的密钥 |
| **不可用时** | Linux 上无可用 keyring 时 `safeStorage.isEncryptionAvailable()` 为 false（或退化为固定密钥的 `basic_text`，等价于明文）。**必须显式告知并让用户选择**，不静默写明文 —— CLAUDE.md §9.1「降级、跳过、认不出来都要如实说」 |

文案（不可用时）：

> 这台电脑上没有可用的系统密钥库，EvoWork 无法加密保存 API 密钥。
> 可以选择：**以 600 权限的明文文件保存**（仅本机可读，但同机的其他程序能读到），或**每次启动时手动填入**（不保存）。

## 5. 阶段 2 · 账号

### 5.1 注册与登录形态

**Q33=A 已决策**：系统浏览器 + OAuth 2.0 Authorization Code + PKCE + loopback 回调。凭据形态是 **Q32=B 邮箱密码 + 邮件验证**，而那个表单**只出现在 WEB 上**（§13.1）。

```
App 内点「登录」
  → shell.openExternal(authorize_url + code_challenge)     ← 系统浏览器，不是内嵌 webview
  → 用户在浏览器里完成注册/登录（邮箱密码 + 邮件验证，Q32=B；或企业 OIDC SSO）
  → 重定向到 http://127.0.0.1:<临时端口>/callback?code=...
  → 本机 HTTP 服务器收 code（只监听 loopback，一次性，收到即关）
  → identity 换 access + refresh token
  → refresh 进 safeStorage，access 只在内存
```

| 决定 | 理由 |
| --- | --- |
| **绝不用 Electron 内嵌 webview 收密码**（Q32=B 之后这条从"原则"变成"硬约束"：主路径本来就是密码） | ① 改不掉的钓鱼面（用户无法验证地址栏）② 密码进渲染进程 ③ 企业 SSO 的 IdP 普遍拒绝在内嵌 webview 里工作（Google / 多数 Azure AD 配置直接拒绝）。这不是偏好问题，是这条路走不通 |
| loopback 回调而非自定义 scheme | 自定义 scheme（`evowork://`）在 macOS 上要 App 已注册且用户可能有多个版本；loopback 端口是进程私有的，且 PKCE 已经封住了 code 拦截 |
| PKCE 必须有 | 桌面应用是 public client，没有 client_secret 可藏。没有 PKCE 时 loopback 上的 code 可被同机其他程序抢 |
| 备选：device code flow | 无浏览器环境（远程终端、企业锁定机）时的退路。**只在 Q33 决定要覆盖这类环境时才做** |

### 5.2 令牌模型

| 令牌 | 生命期 | 存哪 | 谁验 |
| --- | --- | --- | --- |
| access（JWT） | **15 分钟** | 只在宿主进程内存 | **网关本地验签**（JWKS 缓存 + 时钟偏移宽限），不每次回源 identity |
| refresh | 30 天，滑动续期，**绑 `device_id`** | `safeStorage` | identity |

**JWT claims 里不能有能装内容的字段** —— 只有 `sub` / `tenant` / `exp` / `iat` / `scope` / `quotaClass` / `deviceId` / `role`（`member \| admin`，枚举不是自由字符串）。`role` **只用于决定客户端是否显示"管理端"入口，不授权任何客户端能力** —— 授权在服务端，客户端知道自己是管理员也做不了管理动作（§13.1）。做法与 [services/policy 的 `audit.ts`](../../services/policy/src/) 一致：**在类型层面就没有那个字段**，想记内容得先改类型，而改类型会被 review 看见（status.md §3 的 M4 表格里已经有这条纪律）。

网关侧 `authenticate` 的替换（[server.ts:31](../../services/gateway/src/server.ts#L31)）：

```
mode = hosted   → jwtAuth(jwks)          ← 新增
mode = private  → staticTokenAuth(...)   ← 保留，不动
mode = local    → staticTokenAuth(自签)  ← 保留，不动
```

**`staticTokenAuth` 必须保留**：Q14 的企业私有部署包是"客户自持密钥"，那条路径不能被强制要求先有我们的账号。删掉它等于把私有化交付绑死在我们的云上。

### 5.3 目录落点

| 放哪 | 内容 | 为什么是这里 |
| --- | --- | --- |
| **`packages/account/`**（新） | 协议类型 · JWT 验签 · PKCE 帮助函数（**无网络、无存储、无 Electron**） | 三个消费者：identity（签发）· gateway（验签）· desktop main（客户端）。正是 CLAUDE.md §3 对 `packages/` 的定义："被两层以上使用、复制会造成语义分裂"。协议类型两侧共用这一条是硬要求，理由写在 [catalog.ts 的头注释](../../services/gateway/src/catalog.ts#L1-L14)里：此前模型目录端点是 server.ts 里的内联字面量，消费侧只能照抄一份类型，**两边各自都能编译，改一个字段名就在运行时静默断掉** |
| **`services/identity/`** | 云端服务：注册 · 登录 · 令牌签发与刷新 · 租户 · 配额 · 计量汇总 · 策略包签名 | README 已定位为云端 |
| **`apps/desktop/src/main/account.ts`** | 本机编排：登录流程 · loopback 服务器 · 令牌刷新循环 · 登出 | `safeStorage` 与 `shell.openExternal` 是 Electron API。放进 `services/` 会把 Electron 拖进服务层的依赖树 —— 而服务层现在是可以在纯 node 下跑测试的 |

### 5.4 未登录路径（Q30=A 的落法）

Q30 已决策为 **A（未登录可用，但只能用自定义模型）**，引导里两条路**并列摆放，不是先后**：

```
引导第④步（现在是"填三家密钥"）改为二选一：

  ┌ 用我自己的模型密钥 ────────┐   ┌ 登录 EvoWork 账号 ──────────┐
  │ 密钥只存这台电脑            │   │ 无需自备密钥，用托管额度     │
  │ 不需要注册，也不需要联网登录 │   │ 可跨设备用同一份额度与分享   │
  └ → 上游 A                   ┘   └ → 上游 B                    ┘
                        「稍后再说」（可跳过，进 App 后 Composer 顶部有 danger 条）
```

**右边那张卡不列具体的默认模型** —— 未登录时客户端对我们的云零请求（§13.4），所以它只能说明"有这个类别"，说不出有哪几个。

跳过时的行为已有现成落点：`ModelCatalogResult.reason = 'no-keys'` → Composer 顶部 danger 条 + 录入框（[ipc.ts:170-186](../../apps/desktop/src/shared/ipc.ts#L170-L186) 与 [03 §8](03-home-and-composer.md)）。新增一种 `reason = 'not-signed-in'`：**下一步动作是"登录"而不是"填密钥"**，这正是那个枚举存在的理由（"只给文案的话，「检查模型接入」对没配密钥的用户永远是再 fetch 一次失败"）。

**这个 reason 只在"未登录**且**一个自定义模型都没有"时给**：未登录但配了自己的密钥 = 产品完全可用（Q30=A 的字面意思），此时报它就是误报，而误报一次就足以让"本地优先"这句话在用户那里失效。

### 5.5 登出与本机数据

**登出只清令牌，不动任何本机数据。**

这不是为了省事，是数据归属的直接推论：14 张本机表没有 `user_id`（§1.1），因为**数据属于这台机器，不属于账号**。这与 Q15「automation 绑定创建它的设备」是同一条纪律。

| 动作 | 影响 |
| --- | --- |
| 登出 | 清 access + refresh；默认模型从下拉里消失（自定义模型不受影响）；**任务、产物、自动化、审计全部保留** |
| 换账号登录 | 同上 + 新令牌。**不做数据迁移，也不做"是否合并"询问** |
| **注销**（Q39，§13.9） | **只清云端**：身份、全部设备的 refresh、租户成员关系、托管额度、由该账号创建的分享链接。**本机表行数不变**，与登出同一条断言。入口只在 WEB（要再输一次密码） |
| 卸载 | 与账号无关（删 `~/.evowork/`） |

**Q31=A 的直接后果**：换账号登录后看到的还是这台机器原有的任务与产物。隔离边界是 **OS 账号**，不是 EvoWork 账号 —— 多人共用一台电脑就各用自己的 OS 账号，产品内不提供第二层隔离（§9.1）。

文案（登出确认）：

> 退出后这台电脑上的任务、产物和自动化都会保留，只是暂时无法使用托管的模型额度与分享功能。

文案（登录页 / 换账号，**Q31=A 要求写明，不能让用户自己推断**）：

> 任务、产物和自动化保存在这台电脑上，不随账号切换。

文案（注销确认，**Q39 要求写明**）：

> 注销后将无法再使用托管模型额度与分享功能。这台电脑上的任务、产物和自动化都会保留，不受影响。

## 6. 数据面纪律（最容易破的三处）

### 6.1 identity 的数据面只有身份与计量，无内容

D9 表格里那一格的原话就是「只有身份与计量，无内容」。落成具体禁令：

| 允许上行 | **禁止上行** |
| --- | --- |
| `sub` · `tenant` · `deviceId` · `appVersion` · `platform` | prompt / 响应体（Q14 已管住网关，identity 同理） |
| `model` · `provider` · `tokensIn` / `tokensOut` / `tokensCached` · `durationMs` · `errorCode` | **`threadId`** —— 见下 |
| 时间戳（分钟粒度足够） | 文件名 · 任务标题 · 工作空间路径 · 技能名 |

**`threadId` 是这里最容易放进去的一个字段，也是必须挡住的**：它看起来是个无意义的随机 id，但带上它，云端就能按任务重建用户的活动时间线（几点在干活、一个任务用了多少轮、什么时候失败）。那已经是内容面了，而 D9 承诺的是"无内容"。计量只需要**按天按模型的聚合**，不需要能归因到某个任务。

### 6.2 日志字段先注册，否则被静默丢掉

`packages/logging` 的 `BUILTIN_FIELDS`（[fields.ts:57](../../packages/logging/src/fields.ts#L57)）是白名单，**未注册的字段被静默丢掉**（生产 `onViolation: 'drop'`）。已有的可直接用：`tokensIn/Out/Cached` · `provider` · `model` · `deviceId` · `durationMs` · `errorCode` · `signatureFingerprint`。

需要新注册的（都不能装自然语言）：

| 字段 | kind | 用途 |
| --- | --- | --- |
| `tenantId` | `id` | 租户（阶段 2/3） |
| `credentialSource` | `token` | `byok` / `hosted` / `private`（§4.2） |
| `authMode` | `token` | `local` / `hosted` / `private` |
| `secretStore` | `token` | `keychain` / `dpapi` / `libsecret` / `plaintext-fallback` —— §4.3 的降级要**可审计**，否则"用户到底有没有走明文兜底"事后查不出来 |
| `quotaClass` | `token` | 额度档位 |

**不要注册的**：`userId`（用 `sub` 的摘要或 `tenantId`，避免在本机日志里留一个能对外关联到人的稳定标识）· 任何 `*Name`。

### 6.3 出网路径登记（K6）

D9 的四类云端职责里已包含账号，但**登录与令牌刷新这两个具体动作此前没写过**。按 K6「新增出网路径时在设计文档里登记」，回写总纲时补进 D9 的表：

| 触发 | 去哪 | 带什么 | 不联网时 |
| --- | --- | --- | --- |
| 用户点「登录」 | identity 授权端点（系统浏览器） | PKCE challenge · `deviceId` · 客户端版本。**无用户内容** | 登录失败，明确提示；**只用自定义模型的用户完全不需要这条路径** |
| 令牌刷新 | identity token 端点 | refresh token · `deviceId` | 默认模型不可用（如实说明，并在有自定义模型时给出切换动作，§8）；策略包按 R11 的宽限与超期降级 |
| 计量上报 | identity 计量端点 | §6.1 允许列表，**按天按模型聚合** | 本机排队，**上限内丢弃而不是无限堆积**（一个只增不减的队列是另一种数据留存） |

## 8. 失败路径与文案

CLAUDE.md §9.1「降级、跳过、认不出来都要如实说」在这一块的落点：

| 状态 | 下一步动作 | 文案 |
| --- | --- | --- |
| 未登录 + **一个自定义模型都没有** | **两个动作并列**：登录 / 填自己的密钥 | 「使用托管模型需要先登录。也可以改用自己的 API 密钥，密钥只保存在这台电脑上。」 |
| 未登录 + **已有自定义模型** | **无** | 无 UI —— 产品完全可用（Q30=A）。**不提示"登录可解锁更多模型"**：那是把一句"能用"变成一句待办，而未登录是我们承诺支持的常态，不是待修复状态 |
| 未登录 + 企业锁了 `allow_custom_models` | **登录** | 「你所在组织要求登录后使用统一配置的模型。」—— 说清是**企业策略**而不是"你没配密钥"，否则用户会去翻设置页找一个已经被锁掉的入口（§13.5） |
| access 过期 + 能联网 | 静默刷新 | 无 UI |
| refresh 过期 / 被吊销 | **重新登录** | 「登录已过期，请重新登录。这台电脑上的任务和产物不受影响。」 |
| 拿不到网络 + 当前用的是**默认模型** | 重试；**有自定义模型时并列给"切到自定义模型"** | 「连不上 EvoWork 服务。任务、产物和自动化仍可查看，但现在无法调用默认模型。」**不自动切**（不静默降级：切了就等于替用户决定这次调用花谁的钱、数据过谁的境） |
| `safeStorage` 不可用 | **让用户选**（§4.3） | 见 §4.3，**不静默写明文** |
| 模型被企业策略停用 | 换模型 | 「这个模型已被你所在组织停用。」**不隐藏该项**（§4.1） |
| 托管额度耗尽 | 换 BYOK；企业锁了自定义模型时改为联系管理员 | 「本月托管额度已用完。可以改用自己的 API 密钥继续。」**没有「升级 / 充值」**（Q42：v1 不做支付）。**不自动降级到便宜模型**（Q11）。企业锁了自定义模型时后半句换成「请联系你所在组织的管理员」 |
| 策略包超期 | 只读 + 恢复路径 | 「安全策略已过期，已切换为只读模式。请连接企业网络以更新。」（R11） |

### 11.1 新增 D10 —— 账号是凭据，不是数据归属主体

**决策**：账号解锁 D9 的四类云端职责，**但不改变数据归属** —— 任务、产物、自动化、审计属于**这台机器**，不属于账号。落地形式：本机 14 张表不引入 `user_id`（Q31=A）；登出只清令牌（§5.5）；**注销只清云端身份与额度**（Q39）；不做跨设备同步（Q17 / Q19 已定）。

**理由**：这是 D9 那句「后续任何设计若需要"服务端在用户离线时替他做事"，必须先回到本条重新决策」在有账号之后唯一能自洽的形态。把账号做成数据归属主体，"云端存一份方便跨设备"就成了顺理成章的下一步，而那会依次推翻 Q17、Q19、K6 与 D9 本身。

**机制化**（不靠自觉）：① `packages/logging` 不注册 `userId`，计量上报的类型里**没有 `threadId` 字段**（§6.1 / §6.2）② identity 的协议类型里没有任何能装内容的字段 ③ 登出与**注销**路径都有断言钉住"本机表行数不变"（Q39）。

### 11.3 新增 D11 —— 本机网关是唯一的 provider 端点，上游按模型路由

**决策**：内核的 `model_providers.evowork.base_url` **恒为 loopback**；本机网关常驻并按 model id 决定上游 —— 自定义模型用本机密钥直连厂商，默认模型转发到云端网关。拓扑（`app.toml` 的 `mode`）描述的是"默认模型的上游在哪"，不是"网关在哪"。详见 §13.3。

**理由**：这是"同一台机器上 BYOK 与托管共存"（Q36=A）与"内核只有一个 provider"这两个事实唯一的自洽解。反方向（把用户密钥上传云端网关统一路由）同时破 K6 的本地优先与 Q14 的密钥托管卖点，且断网后 BYOK 也不能用。

**机制化**：① 内核侧 base_url 不再携带拓扑信息，`isLocalGateway()` 的 URL 反推退休（§1.2 问题 1 关闭）② 客户端收到的目录条目类型里没有 `apiKey`、hosted 条目没有上游 `baseUrl`（验收口径 13）③ 本机网关转发模式复用 Q14 的不落盘检查，不开例外（验收口径 16）。

| 11 | **本机 sqlite 的任何表（含后续迁移器新建的表）都不出现 `user_id` / `tenant_id` 列** —— 扫 schema，不是扫某几张表（同 K6 在 `services/ingest` 的整目录扫法）（Q31=A / D10） | 数据归属从"这台机器"漂成"这个账号"，而这个方向**去掉比加上难**，且会依次推翻 Q17 / Q19 |
| 12 | **`password` 不出现在 IPC 契约、宿主进程、桌面 `app.toml`、与 `packages/logging` 的字段注册表里**（Q32=B + Q33=A + Q38）。允许出现的只有 identity 服务端引导配置 / 对应环境变量，以及 WEB 登录表单本身 | 密码进了渲染进程、客户端配置或日志；Q38 的引导明文若漏进 `~/.evowork/`，等于管理员密码发到每一台电脑 |
| 13 | **客户端收到的模型目录类型里没有 `apiKey`，hosted 条目也没有上游 `baseUrl`** —— 类型层面没有，不是运行时过滤（§13.2） | 租户共享的厂商 key 落到每一台客户机；一台泄漏 = 整租户额度泄漏，且计量失真 |
| 14 | **未登录时抓不到任何指向我们域名的请求**（连模型清单都不拉）；**拔掉网线后自定义模型仍可用**（§13.4） | Q30=A 的"不需要联网"变成一句空话；而这正是相对云端 agent 产品的核心差异 |
| 15 | **管理端 API 的返回类型里没有任何任务 / 产物 / prompt 字段**（§13.1） | "管理员能不能看员工的任务"这个企业采购必问项，答案从"结构上不能"退化成"我们承诺不看" |
| 16 | **本机网关的转发模式不落盘、不记正文** —— 复用 Q14 已有的检查，不给它开例外（§13.3） | 多一跳转发就多一处能落盘的地方，而 Q14 的承诺是全链路的 |
| 17 | **引导配置的明文密码只在本租户 0 个 admin 时被消费一次**，写入库的是 argon2id；已有 admin 时重启不覆盖密码（§13.8） | 「改配置再重启」变成一次无审计的管理员密码重置 |
| 18 | **不能收回最后一名 admin**；授予对象必须已经注册；目标若属于其他租户则拒绝（§13.8） | 管理端没人能进，只能停服务清库；或把别的租户的人拽过来 |
| 19 | **identity 启动路径不发送短信**。手机号只作为登录标识（§13.8） | Q32=B 换来的排期确定性被一条引导配置打回短信资质 |
| 20 | **吊销某 `device_id` 后该设备上的 refresh 立即失效**；WEB 与客户端走同一条 identity API（Q40） | 丢了笔记本却吊销不了；或两端各做一套，吊销了客户端、WEB 侧令牌还活着 |
| 21 | **分享页不对 docx / xlsx / pptx 做 HTML 渲染或脚本执行**，只给元数据 + 下载（Q41） | 不可信办公文件在浏览器里变成 XSS 面；Visualizer 的 iframe 纪律在分享页被绕开 |
| 22 | **最后一名 admin 不能注销自己的账号**（Q38 + Q39 的组合） | 管理端没人能进，只能停服务清库 |

**第 3 条与第 5 条是这一块的两条"结构上不可能"型断言**（同 K6 在 `services/ingest` 的整目录扫描、Q14 在 `packages/logging` 的字段注册表）：不是靠约定，是靠"想记就得先改类型，而改类型会被 review 看见"。

## 13. 客户端与 WEB 的关系（Q30 / Q33 / Q34 / Q36 / Q37 / Q38 / Q39–Q42 的落地）

> 来源是产品的五条口径：① 管理员设默认模型的 base_url + key ② 普通用户可自定义模型 ③ 登录后可用默认模型，未登录只能用自定义模型 ④ 自定义模型的密钥进 `safeStorage` ⑤ 登录走系统浏览器 + PKCE + loopback。
> ①–⑤ 分别落成 Q37=B · Q36=A · Q30=A · Q34=A · Q33=A。**其中第 ③ 条与"内核只有一个 provider base_url"这个事实冲突**，解法是 §13.3 —— 这是本节唯一的架构改动。

### 13.1 三个面各自负责什么

| 面 | 谁在用 | 有什么 | **明确没有什么** |
| --- | --- | --- | --- |
| **客户端**（Electron） | 普通用户 | 全部执行面 · 任务 / 产物 / 自动化 · 自定义模型与密钥 · 设置页 · 本机网关 · **吊销本机或其他设备的登录**（Q40，调 identity） | **没有管理员界面**；不能查看或修改默认模型的 key；看不到本机之外的任何数据；**不在客户端里做注销**（Q39，要再输密码，只走 WEB） |
| **WEB · 账号** | 普通用户 | 注册（邮箱 + 邮件验证，Q32=B）· 登录（**邮箱或手机号** + 密码，§13.8）· 密码重置 · 额度查看（**无充值**，Q42）· **设备列表与吊销**（Q40）· **注销**（Q39） | 不做任务执行、不做产物浏览 —— 数据属于机器（D10）；**不发短信**；**不做支付** |
| **WEB · 管理端** | **租户管理员**（Q37=B） | 默认模型（base_url + key + 协议适配类型）· 成员 · **授予 / 收回管理员**（Q38，§13.8）· 每人额度（只配上限，不收款）· 签名策略包签发（R11 已有通道） | **不接触任何内容面**；不能在客户端里做这些动作 |
| **WEB · 分享页** | 链接接收方 | Q10 的产物只读查看（显式授权 + 有效期）· **办公文件只下载**（Q41，§13.9） | 不需要账号；与管理端不共享任何数据面；**不在浏览器里渲染 docx/xlsx/pptx** |

**「管理端不接触任何内容面」是要写进对外文案的一条保证** —— 企业采购必问"管理员能不能看员工的任务"。答案是**结构上看不到**，不是"我们承诺不看"：内容从不上云（D9 / K6），管理端 API 的类型里没有能装内容的字段（验收口径第 15 条）。这是 D10「账号是凭据，不是数据归属主体」在管理侧的同一条推论。

**工程落点**：新增 `apps/web/`（一个 Vite 应用，三个路由分区：`/(signin|signup|verify|reset)` · `/admin/*` · `/s/<share-id>`），管理端与账号 API 落在 `services/identity`。**新增目录要按 CLAUDE.md §3 的规矩配一份 README 并登记进目录表**。

### 13.2 默认模型：key 只存服务端，客户端只见模型

| 项 | 落法 |
| --- | --- |
| 管理员填什么 | 上游 `base_url` + `api_key` + **协议适配类型** |
| key 存哪 | identity / 云端网关侧。**从不下发到客户端** —— 客户端拿到的目录条目类型里就没有 `apiKey`，hosted 条目也没有上游 `baseUrl`（验收口径第 13 条） |
| 因此调用路径 | 默认模型**必须经云端网关**（它持 key、做计量与配额），客户端不直连厂商 |
| 客户端怎么显示 | `/settings/models` 里标「由管理员配置」，只读，不显示 key 的任何部分（连后四位都没有 —— 那不是用户的密钥） |

**「协议适配类型」这一项最容易漏**：`base_url + key` 不足以决定"怎么跟对面说话"（D2 的语义矩阵 —— 流式事件重排、工具调用降级、reasoning 占位、cache 口径各家不同）。管理员填的是一个厂商枚举而不是自由 URL，否则网关只能猜，而猜错的表现是"配好了但流式输出是乱的"。同一条对用户的自定义模型也成立（§4.1 的 ③ 层）。

**反面（为什么不让客户端拿 key 直连）**：租户共享的一把 key 分发到每台客户机，等于一台机器泄漏就是整租户额度泄漏，而且计量彻底失真（Q35=A 要按 token 计量，计量点只能在持 key 的那一侧）。

### 13.3 一个内核只有一个 base_url —— 所以本机网关常驻，按模型路由上游

第 ③ 条要求同一台机器上两类模型共存（Q36=A），但内核只有一个 `model_providers.evowork.base_url`。**解法是让本机网关始终在链路上，成为那个唯一的 base_url，由它按 model id 决定上游**：

```
内核（唯一 provider base_url = 127.0.0.1:8787，永不变）
        │
   本机网关（常驻，按 model id 路由上游）
        │
        ├── credentialSource = byok / private   ← 用户的自定义模型
        │      → 用 safeStorage 解密后注入的用户密钥，直连用户填的 endpoint
        │        密钥不出本机；**断网时这条路仍然可用**
        │
        └── credentialSource = hosted           ← 管理员配置的默认模型
               → 转发到云端网关，带 access JWT
                 key 在服务端；计量（Q35）与配额在服务端
```

**这条改写了 §3.1（上游表）、§3.2（`mode` 语义与 `upstream_base_url` 的命名）与验收口径第 8 条** —— 三处正文在 v0.2 已按本节改完，不必再对照心算（§14）。

**为什么不反过来**（客户端把用户密钥上传云端网关、统一由云端路由）：那让用户的厂商密钥离开本机，同时和 K6 的本地优先叙事、Q14 的密钥托管卖点冲突；而且断网后 BYOK 也不能用了 —— 而"不联网也能干活"正是 Q30=A 的同一条理由。

**代价**：托管调用多一跳本机转发（流式直通，量级 ms）+ 本机网关多一个转发模式，约 **2 人日**。**转发模式同样不落盘、不记正文** —— Q14 的约束对它一视同仁，不开例外（验收口径第 16 条）。

**副作用（是好的那种）**：`isLocalGateway()` 那处 URL 反推彻底退休 —— 内核侧的 base_url 不再携带任何拓扑信息，拓扑只在 `app.toml` 的 `mode` 里，§1.2 第 1 个结构性问题就此关闭。

### 13.4 未登录 = 对我们的云零请求

| 规则 | 为什么 |
| --- | --- |
| 未登录时客户端**不向我们的云发任何请求**，连默认模型清单都不拉 | 拉一次就是一次可被指纹化的出网，而 Q30=A 承诺的是"不需要联网" |
| 所以未登录时下拉里**没有具体的默认模型**，只有一句「登录后可使用管理员配置的默认模型」 | 说明这个类别存在、但不列内容 —— 这是"不隐藏"纪律（§4.1）在零出网约束下唯一自洽的形态 |
| Composer 顶部的 danger 条**只在一个可用模型都没有时**出现 | 未登录但配了自定义模型 = 完全可用，此时报 `not-signed-in` 就是误报。所以 `reason = 'not-signed-in'` 只用于"未登录**且**没有任何自定义模型"（§5.4 已按此写） |
| 自定义模型的调用**完全不上报**：不计量、不记 token 数 | 花的是用户自己的钱，没有计费理由；上报就只剩一个副作用 —— 在云端拼出一条活动时间线（§6.1 禁的正是这个） |

### 13.5 「锁自定义模型」与未登录的组合效应

四层注册表与合并顺序在 **§4.1**（v0.2 已按 Q37=B 改写，新增第 ②' 层「租户默认模型」，① 降级为纯元数据）。本节只补 §4.1 单独看不出来的那一处组合：

**第 ② 层能关掉产品的第 2 条口径** —— 管理员锁 `allow_custom_models` 后用户不能加自定义模型（字段已在 §4.1 里，不新增）。它与 Q30=A 叠起来会出现一个**两条路都走不通**的状态：未登录 + 不能自定义 = 一个模型都没有。这不是 bug，是企业策略的正常结果，但**文案必须说清是策略而不是"你没配密钥"**（§8 有专门一行），否则用户会去翻一个已经被锁掉的入口。

**这正是 CLAUDE.md §9.1「两个模块各自对，合起来可能不对」的形状**：§4.1 的锁是对的，Q30=A 的未登录可用也是对的，合起来才出现那个空状态 —— 而它只在"企业客户 + 新员工第一次开 App"这个组合下出现，最容易漏测。

### 13.6 新增 Q37（已决策）

| # | 问题 | 选项 | **决策** | 代价 |
| --- | --- | --- | --- | --- |
| ✅ **Q37** | 「管理员」是谁？ | A 我们的运营管理员 · B **租户管理员** · C 私有部署方管理员 | **B（2026-09-07）**：租户是管理端的一个维度，A / C 都是它的退化情形 —— 我们的运营 = 一个内部租户，私有部署 = 只有一个租户。一套代码覆盖三种形态 | **M10b 要提前引入租户模型**（原属 M10c），+3～5 人日。见 §13.7 |

`access` JWT 的 claims 因此多一个 `role: 'member' \| 'admin'`（枚举，不是自由字符串，仍满足 §5.2 的"不能装内容"）。**它只用于决定客户端是否显示"管理端"入口，不授权任何客户端能力** —— 授权在服务端，客户端知道自己是管理员也做不了管理动作（§13.1：客户端没有管理界面）。

**第一个 `admin` 从哪来、之后怎么把这个角色给别人**，见 **Q38 / §13.8**。Q37 只回答「管理员是租户维度」，不回答鸡生蛋。

### 13.8 种子管理员与授权（Q38，2026-09-08）

Q37 定了「管理员是租户管理员」，没定**库是空的时候第一个 admin 从哪来**。Q38 的答案是两条，合在一起才完整：

1. **引导**：identity 服务端配置里写种子管理员的**邮箱或手机号**，加上密码。进程第一次起来、库里还没有 admin 时，用它创建本部署的种子租户和种子管理员。
2. **转让**：已经是 admin 的人，在 WEB 管理端把管理员权限给**另一个已注册的用户**（可同时存在多名 admin）。

#### 配置在哪、不在哪

这段配置属于 **identity 进程**（私有部署包里的那份，或我们托管 identity 时运维拿着的那份）。**不是**桌面的 `~/.evowork/app.toml`，也不是内核的 `config.toml`。

写进客户端配置等于把管理员密码发到每一台电脑上，同时破 Q33=A（密码只出现在 WEB 表单 / identity 服务端）和验收口径第 12 条。

```toml
# identity 服务端。字段名是示意，落地时进 identity 自己的配置，不进内核 schema。
[bootstrap]
# 邮箱、手机号至少一个；两个都写则视为同一人的两个登录标识。
email = "admin@example.com"
phone = ""
password = "change-me-on-first-login"
tenant_name = "default"
```

密码也可以改从环境变量读（`EVOWORK_BOOTSTRAP_ADMIN_PASSWORD`），避免明文进仓库或进备份 tar。和 `gateway.env` 那档过渡方案不同：这里的读者是 identity 服务端，文件权限仍按 600，且**只在引导那一次被读**。

#### 只在「库里还没有管理员」时生效

| 启动时的库状态 | 配置里的 `password` |
| --- | --- |
| 本租户 **0 个** `role = admin` | 用配置创建（或提升）该用户为 admin，密码立刻 **argon2id 写入库** |
| 已经有至少一名 admin | **忽略**配置里的明文密码，不重置、不覆盖 |

忽略已经存在的 admin，是为了防止「改一下配置再重启」变成一次无审计的密码重置。要改种子账号的密码，走 WEB 的忘记密码 / 登录后改密。

引导出来的账号第一次登录，**必须改密**（配置里那串只用于第一次进门）。改完之前管理端只给改密，不给配模型、不加成员。

#### 手机号不发短信（不重开 Q32=A）

Q32=B 否掉的是**短信验证码通道**（资质与排期）。Q38 的手机号是**登录标识**：和邮箱一样，配密码就能登。登录页接受「邮箱或手机号 + 密码」。

| | 邮箱 | 手机号 |
| --- | --- | --- |
| 自助注册 | 要，且走邮件验证（Q32=B） | **v1 不做**自助注册，避免又回到短信 |
| 引导配置 | 可 | 可 |
| 登录 | 可 | 可（仅当该账号已经绑了手机号：引导写入，或 admin 在成员页补上） |
| 验证通道 | 发信域（§10.1 已有） | **无**。不发短信，也不做「手机验证码登录」 |

只写了手机号、没写邮箱的种子管理员：用手机号 + 密码登录。没有邮箱则走不了「邮件重置密码」—— 这种账号必须靠另一名 admin 重置，或运维走「库里 0 个 admin」的引导通道。私有化交付建议邮箱、手机号都写上。

#### 把管理员给另一个已注册用户

入口只在 WEB 管理端的成员页，不在客户端，也不在配置文件里加第二个人。

| 规则 | 为什么 |
| --- | --- |
| 目标必须**已经注册**（identity 里有这条账号） | 配置引导只解决鸡生蛋；日常加人走注册，不在配置里堆账号 |
| 目标还不是本租户成员 → 加入本租户并设为 `admin` | 「已注册」不等于「已在本租户」；未加入租户就不能用托管模型，给 admin 的同时要把他放进租户 |
| 目标是其他租户的成员 → **拒绝**，文案说清 | 一套 identity 上的多个租户不能靠「授 admin」把人拽走；要换租户先退出 |
| 可以有多名 admin | 一个人离职不能让管理端没人进 |
| **不能收回最后一名 admin** | 否则又回到鸡生蛋，只能停服务清库 |
| 收回 admin 后角色变回 `member`，人还在租户里 | 撤的是权限，不是账号 |
| 每次授予 / 收回都记身份面审计（谁、对谁、何时） | 企业必问；类型里仍然没有任务 / 产物 / prompt（验收口径第 15 条） |

客户端 JWT 的 `role` 只决定要不要显示「管理端」入口（§13.6）。授了 admin 之后，下次刷新 token 才会带上新 `role`；当前这张 15 分钟 access 过期前，入口可能还是旧的 —— 管理动作本身以服务端当时的角色为准，不认客户端显示。

#### 自助注册的人还不是成员

Q38=B 否掉了「注册即个人租户」。因此：

- 注册只产生 identity 账号，**不**产生租户，也**不**自动变成任何租户的 admin。
- 未加入任何租户的登录用户：没有默认模型（与未登录相同的目录口径，§13.4），只能用自己的自定义模型。
- 进入某个租户的两条路：已有 admin 把他加为 `member`，或按上表授为 `admin`。

这与 Q30=A 兼容：没被加入租户的人仍然能用产品，只是走 BYOK。

一个 identity 部署默认一个种子租户（私有化 = 这个租户；我们自己的托管运营 = 这个租户）。**在同一套 identity 上再开第二个客户租户**本期不做 —— 那是 Q37=B 的非退化情形，有客户再加，不进 M10b。

### 13.9 注销 · 设备吊销 · 分享页 · 额度（Q39–Q42，2026-09-08）

四条都是上次评审建议、今日拍板。Q38 解决「第一个 admin 从哪来」；这四条解决账号上线后立刻会被问到、且答错会破 D10 / K6 / Q11 的事。

#### Q39 · 注销只清云端

| 清掉 | 不动 |
| --- | --- |
| identity 账号 · 全部设备的 refresh · 租户成员关系 · 托管额度账 · 由该账号创建的分享链接（云端对象删除，链接失效） | 本机 16 张表的任何一行 · 工作空间文件 · `safeStorage` 里的自定义模型密钥 · 自动化定义 |

入口**只在 WEB 账号页**：要再输一次密码。客户端 `/settings/account` 只放「前往注销」—— 点开跳系统浏览器。密码不进 IPC（验收口径第 12 条）。

与 Q38 的组合：最后一名 admin **不能注销自己**（验收口径第 22 条）。先把管理员授给别人，或运维走「库里 0 个 admin」的引导通道。

文案见 §5.5。测试与登出共用「本机表行数不变」。

#### Q40 · 吊销的权威是 identity

refresh 已经绑 `device_id`（§5.2）。吊销 = identity 把该 `device_id` 下所有未过期 refresh 标作废。下一次用它换 access 失败，文案走 §8「登录已过期」。

| 入口 | 做什么 |
| --- | --- |
| WEB 账号页 | 列出该账号全部设备（名称 · 平台 · 最后活跃，**不列 cwd / 任务标题**）· 单台吊销 · 吊销其他全部 |
| 客户端 `/settings/account` 与 `/devices` | 同一份列表的投影；点吊销调同一条 identity API |
| 当前这台被吊销 | 等于登出：清本机令牌，本机数据保留 |

`/devices` 抽屉里本来就有 Q15 的自动化迁移。两件事不要合成一个按钮：**「吊销登录」**作废云端会话，「迁移到本机」改的是 automation 的 `device_id`。细则回写 [02 §5.2](02-information-architecture.md)。

未登录时客户端对 identity **零请求**（§13.4），设备列表自然是空的 —— 不要为了填抽屉去打云。

#### Q41 · 分享页不渲染办公文件

`/s/<share-id>` 给链接接收方看。无账号、不带管理端 cookie。

| 类型 | 页面上有什么 |
| --- | --- |
| docx / xlsx / pptx | 文件名 · 类型 Badge · 大小 · 有效期倒计时 · **下载** · 「在 EvoWork 中打开」（`evowork://share/<id>`，本机没有该产物时如实说，02 §8） |
| 图片 / PDF | 同上 + 预览。预览页 CSP 收死，不执行未知脚本 |
| 已过期 / 已撤销 / 密码错误 | 失效页，不泄露文件名以外的元数据 |

办公文件在浏览器里渲染 = 把不可信文件当 HTML 跑，和 Visualizer 同时给 `allow-scripts` + `allow-same-origin` 是同一类破口。访问密码（08 §7.1 已有）只挡住下载，不因此开通预览。

本页不进 M10b，跟「分享的上传实现」同一切片。细则回写 [08 §7.4](08-artifacts-and-ingest.md)。

#### Q42 · v1 不做支付

托管额度按 token 计量并折算金额（Q35=A），展示成「已用 X / Y」+ `QuotaFooter`。**没有充值、升级、套餐、支付二维码。**

耗尽时的两个动作已经在 §8：改用自己的密钥，或（企业锁了自定义模型时）联系管理员。不自动切便宜模型（Q11）。

这与 Q17「资料库没有升级入口」是同一条纪律落在另一块表面上 —— 存储面刚砍掉的「升级」，不许从额度面长回来。商业化以后单独决策，不进本期。
