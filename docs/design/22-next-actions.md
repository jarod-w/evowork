# 任务完成后的下一步建议

用户于 2026-10-20 确认：由当前执行 Agent 通过本机 MCP 提交结构化建议，不另发推荐模型请求。首版同一任务内继续，最多三个候选，仅展示第一条；点击“填入”或 Tab 采纳为可编辑草稿，发送仍走现有去重、队列与审批链路。

建议优先采用用户明确说出的下一阶段目标。“本轮只做分析、先不制作汇报”限制当前执行范围，不等于拒绝可选引导；已完成当前交付时应优先把尚未授权执行的后续目标列为候选。没有明确目标且确无有价值的后续动作时仍允许空列表，用户明确不要建议或禁止工具时尊重用户要求。

国内 Chat 适配必须保留产品 developer 消息的优先级：将 Responses 输入中的 developer 映射为 Chat system，普通用户正文仍为 user，不得把产品指令降级为用户内容。验收探针仅记录建议规则是否存在、是否位于 system 消息及工具是否可用的布尔值，不保存请求正文。

2026-10-21 补充：真实模型在纯文本追问后可能完全漏调登记工具。通过官方 Stop command hook，在当前手动根任务的原回合结束前检查是否尝试登记；完全没有尝试时最多提醒一次，由同一个执行 Agent 补报 delivered/needs_input 和候选（允许空）。已尝试但失败不重试，等待输入不生成候选；用户禁用工具时提醒也要求尊重。宿主不解析最终正文、不伪造候选、不新增任务或独立推荐模型。提醒可能增加原回合的模型推理与用量，沿用原生预算和停止机制；第二次 Stop 无条件放行，模型仍可能不遵守。

已当场核对只读内核：`hooks/src/schema.rs:588` 的 Stop 输入包含 session_id、turn_id、stop_hook_active；`core/src/session/turn.rs:645` 在 Stop block 后注入 continuation 并继续同一回合，`:679` 标记 stop_hook_active。宿主只接收三个身份/布尔字段，不读取 transcript_path 或 last_assistant_message。仅当前进程观察到的在途回合可提醒，迟到、归档、子任务、自动化、活动目标、队列或状态未知均放行；不让可选引导阻塞任务。

## 边界与状态

- 不修改执行内核，不增加外网请求。本机 next_actions MCP 使用随包 Electron Node，经回环 HTTP 与随机令牌访问宿主；宿主用真实在途 MCP item 核对来源任务、回合、工具和完整参数，不信模型自报身份。
- 工具仅登记 proposed，成功回合结束后成为 available。回合完成不等于业务成功；Agent 必须声明当前是交付还是等待输入，并只在交付时提出建议。原任务范围内的工作应继续完成，不能转成下一步。
- 权威表 next_action 保存当前任务最后一组建议与 accepted/dismissed/expired 状态；正文只在该本机表与正常工具历史，不进入投影或日志。建议不进入待执行队列。
- 新回合开始使旧建议失效；失败和中断使本回合候选失效；归档时隐藏，删除时清理，执行内核断开清理未发布建议。恢复时只认可与当前已完成回合一致的 available 状态。
- 查询时再次核对最新成功回合、派生状态、根任务身份、审批、原生与本机队列、目标。目标仅无目标或 complete 时展示；暂停、预算耗尽、仍在推进或状态无法读取时隐藏。
- 界面在草稿、附件、引用、队列、补全、运行、审批和预算状态下隐藏建议，不覆盖草稿；异步响应须匹配任务与回合版本。同回合软刷新期间保留已显示候选，避免吞 Tab，采纳仍由宿主再次核对；新回合立即清理。采纳只填入文本并保存状态，不执行；关闭持久化，不刷新复现。
- 建议允许为空，不做模板或独立模型兜底。已完成工作不应重复推荐，具体目标必须来自当前上下文。此为模型质量约束，宿主不能仅凭完成事件证明语义正确。

## 接线与验收

services/store 提供本机建议记录；services/kernel-adapter 提供来源绑定和生命周期；apps/desktop 主进程托管本机 MCP，preload 暴露查询/采纳/关闭动作，Composer 复用现有输入框与 PillButton。

验收包括非法/伪造/迟到调用、跨回合隔离、失败与目标/队列抑制、存储升级与恢复、草稿不覆盖及采纳不发送、完整 check 和真实 Electron/发货内核/本机确定性上游的 MCP 到输入框旅程。真实厂商模型的建议质量另行验收。
