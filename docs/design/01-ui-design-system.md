## 2. Design Token

Token 是唯一的样式来源。组件里不允许出现字面量颜色、字号、圆角。

### 2.1 中性色（暖灰基调 —— 截图的底色不是纯灰，带黄绿暖偏）

| Token              | 值                    | 用途                                        |
| ------------------ | --------------------- | ------------------------------------------- |
| `--bg-app`         | `#F2F1EE`             | 侧边栏、中栏、窗口 chrome                   |
| `--bg-canvas`      | `#FCFCFA`             | 主内容区底色                                |
| `--bg-surface`     | `#FFFFFF`             | 卡片、弹层、输入卡                          |
| `--bg-sunken`      | `#F7F6F3`             | Composer 外壳、分段控件轨道、筛选 chip 轨道 |
| `--bg-hover`       | `rgba(29,29,27,.045)` | 行/按钮悬停                                 |
| `--bg-active`      | `rgba(29,29,27,.075)` | 按下                                        |
| `--bg-selected`    | `#E9E8E4`             | 侧边栏选中行、"全部"选中 chip               |
| `--bg-inverse`     | `#1D1D1B`             | 顶部分段控件的选中态                        |
| `--text-primary`   | `#1F1F1D`             | 标题、正文                                  |

### 2.2 品牌与语义色

| Token                          | 值                    | 用途                           |
| ------------------------------ | --------------------- | ------------------------------ |
| `--accent`                     | `#2FA37A`             | 品牌绿（截图头像/活动卡同源）  |
| `--accent-weak`                | `#E8F5EE`             | 活动卡底、成功态底             |
| `--accent-strong`              | `#1B6B4F`             | 绿底上的文字、图标             |
| `--info` / `--info-weak`       | `#3B7DD8` / `#E9F1FC` | 规划中、提示条                 |
| `--success` / `--success-weak` | `#2FA37A` / `#E8F5EE` | 已完成                         |
| `--warning` / `--warning-weak` | `#C98A16` / `#FBF2DE` | 待处理、配额告警、misfire 提示 |
| `--danger` / `--danger-weak`   | `#D24B3E` / `#FBECEA` | 失败、高危审批、删除           |
| `--focus-ring`                 | **`#2FA37A`（不透明）** | 键盘聚焦环。**2026-09-05 修订**：原写 `@ 40%`，与 §8.3「对 `--bg-surface` 3.16 : 1，达标」矛盾 —— 40% 压在白底上实测只有 **1.54**，3.16 是不透明 accent 的值。按 §8.3 第 2 条的意图（聚焦态是键盘用户的主要定位手段）取不透明。这是实现阶段唯一改动过数值的 token，两个数字都被 `packages/tokens` 的测试钉住 |

**语义色的文字变体**（必需，不可省）：上面四个基色是**图形色**（圆点、边条、进度填充），对比度只够非文本用途。任何**文字**（Badge 文案、提示条正文、危险菜单项）必须用下面的加深变体：

| Token             | 值        | 在 `-weak` 底上 | 在白底上 |
| ----------------- | --------- | --------------- | -------- |
| `--accent-strong` | `#1B6B4F` | 5.7 : 1         | 6.4 : 1  |
| `--info-text`     | `#225CAC` | 5.8 : 1         | 6.6 : 1  |
| `--warning-text`  | `#895E0F` | 5.1 : 1         | 5.7 : 1  |
| `--danger-text`   | `#A53227` | 5.9 : 1         | 6.8 : 1  |

用基色写文字会直接失败：`--warning` 在 `--warning-weak` 上只有 **2.6 : 1**，`--info` 3.6 : 1，`--danger` 3.8 : 1（实测值见 §8.2）。这条是本设计系统里最容易被忽略、后果最直接的一条。

> **品牌 token 是 K5 的落点**：`--accent` 系列 + `appName` + `logo` + `mascot` 四项构成品牌层。换品牌只改这四项，布局零改动（README §3）。

### 2.3 圆角

`--r-xs 6` · `--r-sm 8` · `--r-md 10` · `--r-lg 12` · `--r-xl 16` · `--r-2xl 20` · `--r-full 999`

用法：图标按钮 `sm` · 侧边栏行 `sm` · 输入框 `sm` · 卡片 `lg` · 封面图 `md` · Composer 外壳 `xl` · 所有 chip / 分段控件 / 头像 `full`。

### 2.4 阴影

| Token         | 值                                                             | 用途               |
| ------------- | -------------------------------------------------------------- | ------------------ |
| `--shadow-xs` | `0 1px 2px rgba(24,24,20,.05)`                                 | chip、小按钮       |
| `--shadow-sm` | `0 1px 3px rgba(24,24,20,.06), 0 1px 2px rgba(24,24,20,.04)`   | 卡片静态           |
| `--shadow-md` | `0 4px 12px rgba(24,24,20,.08), 0 1px 3px rgba(24,24,20,.05)`  | 卡片悬停、Composer |
| `--shadow-lg` | `0 12px 32px rgba(24,24,20,.12), 0 2px 8px rgba(24,24,20,.06)` | 弹层、下拉、活动卡 |

截图的卡片阴影**极轻**（近乎只有描边）。规则：静态卡片用 `--border-subtle` + `--shadow-xs`，悬停才升到 `--shadow-md`。不要一上来就打重阴影。

### 2.5 间距刻度

`2 · 4 · 6 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64`

不允许 10 / 14 / 18 / 22 这类中间值。

### 2.6 字体与排版

```
字族  "PingFang SC", "HarmonyOS Sans SC", "Microsoft YaHei",
      "Noto Sans CJK SC", -apple-system, "Segoe UI", Roboto, sans-serif
等宽  "SF Mono", "JetBrains Mono", Menlo, Consolas, monospace   ← 命令/diff/代码
```

| Token     | 字号/行高/字重                         | 用途                                | 出现在                       |
| --------- | -------------------------------------- | ----------------------------------- | ---------------------------- |
| `display` | 36 / 44 / 700，`letter-spacing -.02em` | 首页问候语（高窗口）                | 「今天想完成什么？」         |
| `title-1` | 20 / 28 / 700                          | 页面区块标题                        | 截图 2「精选技能」「推荐」   |
| `title-2` | 17 / 24 / 600                          | 面板标题                            | 截图 4「资料库」「最近」     |
| `body-lg` | 15 / 24 / 400                          | Composer 输入、区块副标题、卡片标题 | 截图 1 placeholder           |
| `label`   | 13 / 20 / 500                          | 导航、按钮、chip、表头              | 侧边栏全部                   |
| `body`    | 13 / 20 / 400                          | 卡片描述、消息正文                  | 截图 2 描述文字              |
| `caption` | 12 / 16 / 400                          | 时间戳、分区标题、配额              | 「1天前」「已使用 880.1 KB」 |
| `micro`   | 11 / 14 / 500                          | 角标、版本号                        | 「V5.5.1」                   |

**中文排版硬规则**：① 行高不低于字号 ×1.5（`body` 13/20 = 1.54）；② 卡片描述固定 **2 行**、`-webkit-line-clamp: 2`，不足 2 行也占 2 行高度，保证网格对齐（截图 2/3 的卡片高度一致即此规则）；③ 中英混排在数字与中文之间不插空格，由字族自然处理；④ 禁止 `text-align: justify`。

### 2.7 动效

| Token                                      | 值                          |
| ------------------------------------------ | --------------------------- |
| `--dur-fast` / `--dur-base` / `--dur-slow` | `120ms` / `180ms` / `280ms` |
| `--ease-out`                               | `cubic-bezier(.2,.8,.2,1)`  |
| `--ease-inout`                             | `cubic-bezier(.4,0,.2,1)`   |

用法：悬停/按下 `fast`；面板展开、下拉、Tab 切换 `base`（`ease-out`）；三栏宽度变化、抽屉 `slow`。**流式文字追加不做逐字动画**（会让长回复看起来卡顿），只在新 Item 插入时做 120ms 淡入 + 4pt 上移。`prefers-reduced-motion` 下全部降为 0ms 并保留最终态。

`1 内容` · `10 吸顶/吸底` · `100 下拉/Popover` · `200 抽屉/侧滑` · `300 模态` · `400 审批置顶条` · `500 Toast` · `600 拖拽镜像`

## 3. 布局

### 3.1 三种骨架

```
A · 默认对话                    B · 按需结果工作区
┌──────────┬──────────────────┐ ┌──────────┬──────────────┬───────────┐
│ 侧边栏    │ 对话 / 页面主区    │ │ 侧边栏    │ 对话区        │ 结果工作区 │
│ 260      │ flex, 内容列 ≤800 │ │ 260      │ flex          │ 42%       │
└──────────┴──────────────────┘ └──────────┴──────────────┴───────────┘

C · 管理页（资料库 / 项目详情等）
┌──────────┬──────────┬──────────────────┐
│ 侧边栏    │ 可选中栏  │ 页面主区          │
│ 260      │ 272      │ flex             │
└──────────┴──────────┴──────────────────┘
```

| 区         | 宽度                                  | 底色          | 可调                   |
| ---------- | ------------------------------------- | ------------- | ---------------------- |
| 侧边栏     | **260**（可折叠至 0）                 | `--bg-app`    | 否（固定宽，只可折叠） |
| 管理页中栏 | **272**                               | `--bg-app`    | 可拖拽 240–360         |
| 主内容区   | 剩余                                  | `--bg-canvas` | —                      |
| 对话内容列 | **max 800，水平居中**，左右各留 ≥28   | —             | —                      |
| 结果工作区 | 默认主窗口的 **42%**，最小 420、最大 720 | `--bg-surface` | 可拖拽                 |

**对话内容列 800 是可读性上限，不是所有页面的固定宽度。** 插件、设置、资料库等管理页可按表格或网格需要使用更宽主区。结果工作区打开时优先保证消息正文可读，不以固定三等分挤压对话。

### 3.2 标题栏带（关键结构，容易做错）

窗口顶栏保持轻量，只放当前上下文与少量高频动作：

```
y 0 ────────────────────────────────────────────────── 52 ──
│ ●●●  [折叠]               │ 页面标题 / 当前模型        [动作]│
│ ←── 侧边栏段 260 ──────→ │ ←────── 主内容区段 ─────────→ │
```

- 标题栏带高 **52**，全宽，无背景色（继承各栏底色），无下边框。
- 侧边栏段：macOS `hiddenInset` 下必须先为交通灯预留空间，品牌名从第三颗灯右侧开始且空间不足时省略；再放侧栏折叠按钮。Windows / Linux 使用系统标题栏，不加这段占位。搜索改为侧栏中的明确入口。
- 任务页：左侧为任务标题，右侧最多保留“打开结果”和任务菜单；运行、待审批、失败时才显示状态。
- 首页：可显示当前模型选择，不显示营销、运营或活动入口。
- 管理页：可在顶栏放页面 Tab、搜索和一个主动作；低频动作收入菜单。

### 3.3 侧边栏纵向结构

```
y   0  ┌ 标题栏带：折叠 + 品牌                    高 52
   52  ├ 新任务主按钮 + 搜索入口                  高 72
  124  ├ 项目：最近 3–5 项 + 查看全部             按内容
       ├ 最近任务：置顶优先 + 分页滚动             flex
       ├ 插件 / 自动化 / 资料库                   高 96
  620  └ 用户菜单                                 高 62
  682
```

- 侧边栏水平内边距 **8**（可点击行的外边界），纯文本标题额外内缩 12（视觉左对齐于 20）。
- 导航与列表节奏 **33** = 行高 28 + 行距 5。
- 项目行不展开项目内任务树；点击后进入项目详情。项目与最近任务是独立分区。
- 中部内容为唯一滚动区；插件、自动化、资料库与用户菜单吸底。不设置运营位。

### 3.4 网格

| 场景                               | 列  | 列宽   | 间距 |
| ---------------------------------- | --- | ------ | ---- |
| 技能 / 连接器 / 专家卡（截图 2/3） | 3   | 258    | 12   |
| 资料库提示卡（截图 4）             | 2   | 222    | 12   |
| 结果区产物卡（04）                 | 2   | 自适应 | 12   |

窗口 < 1240 时三列降为两列，< 1024 时降为一列（内容列宽随之收窄，仍居中）。

### 3.5 主内容区垂直节奏（首页）

`顶部弹性留白 → 问候语 44 → 24 → Composer 适配内容 → 16 → 上下文建议 30 → 底部说明`

首页主操作组位于视觉中部略上方。上下文建议最多 4 个，用户开始输入后立即消失；不展示场景分段控件、常驻案例或运营内容。

## 4. 响应与状态

### 4.1 折叠

- 侧边栏折叠（标题栏第一个图标 / `⌘\`）：宽度 260 → 0，`--dur-slow`，主内容区跟随。折叠后在主内容区左上角浮出一个展开 `IconButton`（截图 4 主区左上角那个图标即此物）。
- 管理页中栏折叠（`⌘⌥\`）：272 → 0。
- 结果工作区（04）默认收起，`⌘I` 或用户点击产物、文件、diff、网页预览时打开；系统主动打开必须满足 04 §1 的意图规则。

### 4.2 断点

| 宽度      | 行为                                                        |
| --------- | ----------------------------------------------------------- |
| ≥1440     | 侧栏 + 对话；结果工作区打开时保持并排                        |
| 1180–1439 | 侧栏 + 对话；结果工作区打开后适度压缩对话                    |
| 900–1179  | 侧栏可折叠；结果工作区覆盖主区；管理页中栏与结果区不同时打开 |
| <900      | 侧栏为抽屉；管理页单列；提示建议放大窗口                     |

### 4.3 空态

统一结构：图标 40（`--text-tertiary`）→ 12 → 主文案 `body-lg`/`--text-primary` → 6 → 辅文案 `body`/`--text-secondary` → 16 → 主行动按钮（可选）。垂直居中于容器，容器高 < 200 时只保留主文案一行。

**空态文案必须给出下一步动作**，不写"暂无数据"。例：任务列表空 → 「还没有任务 / 在上方输入一句需求就能开始」+ 按钮「新建任务」。

### 4.4 加载与骨架

- 列表/网格：骨架卡（`--bg-sunken` 填充 + 1.4s 呼吸），数量按上次渲染数（≤6）。
- 行内小范围：不用 spinner，用文本占位「正在读取…」。
- 首屏 > 400ms 才显示骨架，避免闪烁。
- **禁止全屏 loading 遮罩**（会打断对话流）。

### 5.3 NavItem（侧边栏主导航）

高 28，`--r-sm`，左内边距 8：图标 20 + 8 + `label`。可选右侧计数，但不承载营销尾标。

### 5.4 SidebarSectionHeader（「任务 (8)」）

### 5.5 TaskListItem

高 28，`--r-sm`，左内边距 8：状态点 6 + 8 + 标题（`label`，单行省略）+ 弹性 + 时间（`caption`/`--text-tertiary`，右内边距 8）。

### 5.6 PromoCard（退出主路径）

该组件是旧截图遗留库存，新版侧栏和首页均不设置运营位，不得在主路径实例化。若未来另立运营需求，必须重新评审其数据来源、隐私边界与关闭策略。

### 5.7 UserFooter

高 62，内边距 8 12。头像 28 圆形 + 10 + 两行（名称 `label`、版本 `micro`/`--text-tertiary`）+ 弹性 + 更多按钮。点击打开统一用户菜单；模型与账号、用量与预算、数据管理、安全与权限、用量与审计、关于从此进入。尚未接通的通知与设备入口不显示。

确定进度条。高 4、`--r-full`、轨道 `--bg-selected`、填充 `--accent`，宽度按 `percent` 插值。

那条带 >80% 转 `--warning`、>95% 转 `--danger` 的阈值配色，是"用量"语义而非"进度"语义，
合并会让两种含义共用一套颜色规则。

> **为什么它是第 33 个组件**：办公扩展的安装要几分钟，而 08 §4 要求这几分钟里
> 用户能看出"在下什么、还要多久"。此前清单里唯一的条形是 QuotaFooter 的用量条，
> 语义不同。按 Q24 的规矩，先登记再实现。

```

```

**它是已登记的模态壳，不是既成事实**：新模态一律用它搭。渲染层眼下还有**四处**各写一遍的
确认面板——`views/library.tsx` 与 `views/sidebar.tsx`（**两处共用 `ew-delete-confirm`**）、
`components/changes-view.tsx` 的 `ew-revert-confirm`、`components/composer.tsx` 的
`ew-danger-confirm`（`components/approval-card.tsx` 的 `role="alertdialog"` 不算，
那是 10 §3 规格下的内联审批卡，不是模态）。实现 Dialog 时只并入 `library.tsx` 这一处，
刻意把改动面控制住；其余三处**登记为待还债务**，之后再逐个折进来。

**`ew-delete-confirm` 的 CSS 规则因此不能跟着 library 一起删** —— sidebar 还在用它。
2026-09-08 实现 Dialog 时差点删掉：三个选择器共用一条容器规则，而 sidebar 的测试
只断言 role 与文案，删了一条测试都不会红，表现是那个确认框丢掉边框背景阴影。理由不是好看：三份各写一遍的确认文案，「删文件」还是
「删索引」这种措辞纪律会在其中一处慢慢走样而没人发现，直到用户真的删错了东西。

### 5.35 SecretInput（密钥录入）

高 32（同 §5.16 SearchInput）、`--r-md`、`--bg-surface` + 1px `--border-subtle`，等宽字体显示已保存态。
**三种状态是三件不同的事，不能压成一个输入框**：

```
① 空       [ 粘贴 API 密钥…                     ]            ← type=password，autocomplete=off
② 刚粘贴   [ ••••••••••••••••••••••  ] [保存]  形状提示       ← 形状不对时 warning 文案，但不拦保存
③ 已保存   已保存 · ****3f9a   [更换] [清除]                   ← 值不可读回；「清除」是显式动作
```

| 项       | 规格                                                                                                                                        |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 遮罩     | `type="password"` + `autocomplete="off"` + `spellCheck=false`。**没有"显示密码"的小眼睛** —— 见下                                             |
| 形状校验 | 粘贴即校验长度与前缀，只给提示**不拦保存**：厂商随时会改 key 的形状，拦下来的代价是用户拿着一把有效的 key 进不去（10 §2.2「认不出来也要显示」） |
| 已保存态 | 只显示后四位。**没有读回路径** —— 值不进 `value` prop，也不从任何 IPC 返回                                                                    |
| 清除     | 显式动作，**不是把输入框清空**：后者在用户看来与"没保存成功"无法区分                                                                          |
| 不可用   | `safeStorage` 不可用时组件上方挂一条 `TipBanner`（§5.29）说明只能明文保存或每次手填，**不静默降级**（11 §4.3）                                |

**为什么不能复用 SearchInput（§5.16）加一个 `secret` prop**：`SearchInput` 的值是可读回的
（受控 `value`），而密钥的"不可读回"是一条**安全属性**。做成同一个组件的 prop，就存在
"某处忘了传那个 prop"这种失败方式，而它的表现是密钥出现在渲染进程里 —— 等于出现在任何一个
XSS 面上（11 §12 第 2 条）。两个组件的话，这种失败方式在类型层面就不存在。

**没有"显示密码"按钮**同理：它要求组件持有明文并能渲染出来。用户想确认自己贴对了，
靠的是后四位与一次连通性检查，不是把 key 亮在屏幕上（旁边可能坐着别人）。

> **为什么它是第 35 个组件（不是 11 §4.5 原写的第 34 个）**：那份设计写于 2026-09-07，
> 当天 `Dialog` 抢先占了 5.34。按 Q24 的规矩先登记后实现 —— 这条编号冲突正是登记制度
> 起作用的地方：两个组件同时被"计划成第 34 个"，而清单里只能有一个。

## 6. 状态视觉规范

### 6.1 任务状态（清单 §4.3 六态）

| 状态   | 点色               | Badge                     | 侧边栏行                          |
| ------ | ------------------ | ------------------------- | --------------------------------- |
| 进行中 | `--accent` + 呼吸  | `success` 底 · 「进行中」 | 标题 600                          |
| 规划中 | `--info`           | `info` · 「规划中」       | 标题 600                          |
| 待处理 | `--warning` + 呼吸 | `warning` · 「待你确认」  | 标题 600 + 行尾 `--warning` 圆点  |
| 已完成 | `--text-tertiary`  | `neutral` · 「已完成」    | 常规                              |
| 失败   | `--danger`         | `danger` · 「失败」       | 常规 + 标题前 `--danger` 感叹图标 |
| 已归档 | 无点               | `neutral` · 「已归档」    | 整行 `--text-tertiary`            |

「待你确认」用第二人称，因为它要求用户行动；其余用客观描述。状态派生规则见 04 §3.2（**不能只读 `ThreadStatus`**，README F7/F8）。

Badge 文案一律用 §2.2 的 `-text` 变体，底用 `-weak`。**6px 状态点不满足 3:1**（`--accent` 对 `--bg-app` 实测 2.80、`--warning` 2.61、`--text-tertiary` 2.50），因此它在无障碍上被定义为**冗余装饰** —— 状态的可感知性由同一行的文字 Badge 或图标承担，点只做快速扫视。这也是 §8 "状态不靠颜色单传" 那条的技术前提，不是事后补充说明。

### 6.2 焦点与键盘

- 焦点环：`0 0 0 2px --focus-ring`，`outline-offset 1px`，圆角随组件。**只在键盘导航时出现**（`:focus-visible`）。
- 所有可交互元素必须可 Tab 到达；列表用 `↑↓` 在项间移动、`Tab` 跳出列表（roving tabindex）。
- `Esc` 逐层关闭：Menu → Popover → 抽屉 → 模态。

### 6.3 禁用与只读

禁用：`--text-tertiary` + `opacity .6` + `cursor: not-allowed`，**必须配 tooltip 说明原因**。
只读（非禁用，如其他设备上的自动化、Ask 模式下的写操作）：正常颜色 + 右上角 12px 锁图标 + tooltip 说明「在 <设备名> 上运行，点击可迁移到本机」（07 §6）。两者视觉必须可区分。

### 7.1 图标

- 20×20 网格，描边 **1.5**，圆角端点与连接（`round`），单色（`currentColor`）。
- 尺寸档：14（chip 内）· 15（按钮内）· 16（菜单/树）· 18（中栏导航）· 20（侧边栏/标题栏）· 28（卡片主图标）· 40（空态）。
- 侧边栏入口的图标语义：新任务 = 圆内加号 · 搜索 = 放大镜 · 项目 = 文件夹/三点连线 · 插件 = 拼图/扩展 · 自动化 = 圆内勾选 · 资料库 = 打开的书 · 用户菜单 = 头像/更多。
- 图标不承载颜色语义；语义由旁边的 `Badge`/`StatusDot` 表达。

### 7.2 应用/技能/连接器图标

来自 plugin manifest 的 `interface.logo`（总纲 §6.3）。渲染规则：28×28，`--r-sm`（不裁成圆），缺图时用 `interface.brandColor` 填底 + 名称首字（中文取首字、英文取首字母大写），字色按底色亮度自动取黑/白。

### 7.3 首页品牌约束

首页不展示吉祥物、活动 Popover、积分、案例墙或其他运营位。品牌通过应用名称、logo、暖灰 token 和强调色表达，不以营销内容占用任务主路径。

## 8. 可访问性与国际化

### 8.1 要求

| 项                               | 要求                                                                                                                                                                      |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文本对比度                       | 正文 ≥ 4.5 : 1。`--text-secondary` 在 `--bg-surface` 上 5.18、在 `--bg-app` 上 **4.59** —— 后者只剩 0.09 余量，因此**侧边栏与中栏的次要文字不得再调浅**，也不得叠加透明度 |
| `--text-tertiary` 的唯一合法用途 | 只用于**非必要信息**（时间戳、占位符、版本号）。实测 2.50–2.82 : 1，**不满足任何文本要求**，不得用于说明文字、标签、按钮                                                  |
| 非文本对比度                     | 目标 3 : 1。**当前调色板不满足**（见 §8.2），处理方式是 §8.3 的高对比模式，不是假装达标                                                                                   |
| 状态不靠颜色单传                 | 6 种任务状态除颜色外均带文字 Badge 或图标（§6.1）；失败额外带感叹图标。状态点按 §6.1 定义为冗余装饰                                                                       |
| 语义色文字                       | 必须用 §2.2 的 `-text` / `-strong` 变体，禁止用基色写文字                                                                                                                 |
| 命中区                           | 最小 28×28（桌面指针场景）。这**低于**触屏 44 的通例，是明确取舍：本产品无触屏形态（总纲 Q1=A 桌面应用）。若未来上平板，`IconButton` 需整体升到 36                        |
| 键盘                             | 全功能键盘可达；快捷键表见 02 §6                                                                                                                                          |
| 减少动效                         | `prefers-reduced-motion` 下动效归零、呼吸动画改为静态实心点                                                                                                               |
| 屏幕阅读器                       | 流式消息区用 `aria-live="polite"`（**不用 assertive**，否则每个 token 都打断）；审批卡用 `role="alertdialog"` + 焦点自动落到卡上                                          |
| 语言                             | 简体中文为唯一 v1 语言。所有文案走资源表，不硬编码；预留英文，界面按 +30% 文本宽度做溢出验证（侧边栏导航是最紧的地方）                                                    |

### 8.2 实测对比度（WCAG 2.1 相对亮度公式，2026-09-04 计算）

**必须知道的四个数**，它们决定了上面几条规则不是偏好而是约束：

| 组合                                   | 实测        | 判定                           |
| -------------------------------------- | ----------- | ------------------------------ |
| `--text-primary` on 任意浅底           | 14.6 – 16.5 | ✅ 远超                        |
| `--text-secondary` on `--bg-app`       | **4.59**    | ✅ 勉强过（余量 0.09）         |
| `--text-tertiary` on `--bg-app`        | 2.50        | ❌ 非文本用途专用              |
| `--border-default` on `--bg-surface`   | **1.39**    | ❌ 目标 3.0                    |
| `--border-strong` on `--bg-surface`    | 1.68        | ❌ 目标 3.0                    |
| `--warning` on `--warning-weak`        | 2.64        | ❌ 用 `--warning-text`（5.14） |

| `--danger` on `--danger-weak`          | 3.80        | ❌ 用 `--danger-text`（5.93）  |

### 8.3 边框对比度：一个必须正面承认的取舍

截图的分隔线与控件描边是**极浅的暖灰**，这是这套视觉语言的识别特征之一。要把 `--border-default` 提到 3 : 1 需要做到 `#949389` 左右 —— 那已经是中灰实线，界面会立刻变"重"，不再是附件里那个产品。

**取舍与处理**（不许两头都要）：

1. **默认主题保真度优先**，边框按截图重建，并接受它在 WCAG 1.4.11 上不达标这个事实。
2. **控件的边界不得只靠描边表达**：输入框、下拉、chip 必须同时具备**填充差异**（`--bg-surface` on `--bg-app`）与**尺寸/内边距差异**；聚焦态用 2px `--focus-ring`（**不透明 accent**，对 `--bg-surface` 3.16 : 1，达标；半透明版本只有 1.54，够不上 —— 见 §2.2 该 token 的修订说明），这是键盘用户的主要定位手段。
3. **提供高对比模式**，在 `prefers-contrast: more` 与设置项「高对比度」下均生效，只覆盖三个 token：

| Token              | 默认      | 高对比    | 高对比下的比值 |
| ------------------ | --------- | --------- | -------------- |
| `--border-subtle`  | `#E7E6E1` | `#A3A29B` | 2.56           |
| `--border-default` | `#DCDBD5` | `#8A8981` | **3.51** ✅    |
| `--border-strong`  | `#C9C8C1` | `#6E6D68` | 5.18           |

高对比模式**不改**布局、圆角、字号，因此不产生第二套设计；它是同一套 token 的一组覆盖值。
