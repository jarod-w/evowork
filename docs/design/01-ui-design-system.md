## 1. 设计基准与容差

| 项           | 值                         | 说明                                                                 |
| ------------ | -------------------------- | -------------------------------------------------------------------- |
| 视觉基线     | ui-design 技能 2026-09-16  | 精确数值来自该技能的 foundations，不是永恒品牌规则                   |
| 默认窗口     | **1280 × 820**             | 无已存 bounds 时的桌面默认；不超过工作区 85% × 80%                   |
| 最小支持窗口 | **480 × 600**              | 低于此用单栏紧凑布局，不要把桌面 chrome 整体缩小，见 §4.2            |
| 三区并存     | **≥ 1100**                 | 导航 + 聚焦工作 + 可选结果区可以同时出现                             |
| 测量容差     | **±2pt**                   | 适用于 token 与组件尺寸；页面布局按本文规则验收，不做像素复刻        |

**取整原则**：一律向 4 的倍数取整（间距）或向 8 的倍数取整（组件高度），以落在 §2.5 的间距刻度上。Composer 单行圆角 **22** 是圆角特例，不进入间距刻度。

需求冲突时的顺序与技能相同：① 无障碍与平台行为 ② 信息架构与任务清晰度 ③ 现有产品约束（C3–C7、K5、CJK 字体）④ 与工作台基线的相似程度。

## 2. Design Token

Token 是唯一的样式来源。组件里不允许出现字面量颜色、字号、圆角。产品壳继续使用本节的 `--bg-*` / `--text-*` 名；数值对齐技能的 `--ew-ui-*` 语义，由 `packages/tokens` 生成一份，禁止在 `app.css` 再引入 `ui-tokens.css`。

### 2.1 中性色（冷灰工作台层）

技能基线是低饱和中性分层，不是旧截图的暖灰。浅色值如下；暗色值见技能 `ui-tokens.css` 的 `[data-theme='dark']`，**本版不注入产品 CSS**（C7）。

| ------------------ | -------------------------- | ------------------------------------------- |
| `--bg-app`         | `#f9f9f9`                  | 侧边栏、中栏、窗口 chrome                   |
| `--bg-canvas`      | `#ffffff`                  | 主内容区底色                                |
| `--bg-surface`     | `#ffffff`                  | 卡片、弹层、输入卡                          |
| `--bg-sunken`      | `#f3f3f3`                  | Composer 内轨、分段控件轨道、筛选 chip 轨道 |
| `--bg-hover`       | `#ededed`                  | 行/按钮悬停                                 |
| `--bg-active`      | `#dfdfdf`                  | 按下                                        |
| `--bg-selected`    | `#ededed`                  | 侧边栏选中行、"全部"选中 chip               |
| `--bg-inverse`     | `#0d0d0d`                  | 顶部分段控件的选中态、主按钮                |
| `--bg-scrim`       | `rgb(13 13 13 / 45%)`      | 模态与全局搜索的遮罩                        |
| `--text-primary`   | `#0d0d0d`                  | 标题、正文                                  |
| `--text-secondary` | `#414141`                  | 说明文字、卡片描述                          |
| `--text-tertiary`  | `#8f8f8f`                  | 占位符、时间戳、禁用                        |
| `--text-inverse`   | `#ffffff`                  | 深色底上的文字                              |
| `--border-subtle`  | `rgb(13 13 13 / 8%)`       | 发丝分割线、卡片描边                        |
| `--border-default` | `rgb(13 13 13 / 12%)`      | 输入框、chip 描边                           |
| `--border-strong`  | `rgb(13 13 13 / 14%)`      | 悬停/聚焦前置态、Composer 描边              |

大面积表面保持中性。语义色只出现在小图标、标签、边框或 diff 行上，并与文字或形状配对。

### 2.2 品牌与语义色

技能规定：蓝 = 焦点 / 链接 / 信息，绿 = 成功 / 新增，橙 = 警告，红 = 危险 / 删除。品牌绿仍是 K5 的 `--accent`，**不拿来当焦点环**。

| Token                          | 值                    | 用途                           |
| ------------------------------ | --------------------- | ------------------------------ |
| `--accent`                     | `#2FA37A`             | 品牌绿（K5）；主动作弱强调、进行中状态点 |
| `--accent-weak`                | `#E8F5EE`             | 品牌弱底                       |
| `--accent-strong`              | `#1B6B4F`             | 绿底上的文字、图标             |
| `--info` / `--info-weak`       | `#0169cc` / `#E8F1FA` | 焦点同源的信息色、规划中、链接 |
| `--success` / `--success-weak` | `#008635` / `#E6F5EC` | 已完成、diff 新增              |
| `--warning` / `--warning-weak` | `#923b0f` / `#F8EDE6` | 待处理、配额告警、misfire 提示 |
| `--danger` / `--danger-weak`   | `#ba2623` / `#FBECEA` | 失败、高危审批、删除           |
| `--focus-ring`                 | **`#0169cc`（不透明）** | 键盘聚焦环与链接。半透明 40% 压在白底上只有 **1.85**，达不到「能定位」。不透明对 `--bg-surface` **5.39 : 1** |

**语义色的文字变体**（必需，不可省）：基色首先是**图形色**（圆点、边条、进度填充）。任何 **Badge 文案、提示条正文、危险菜单项**必须用下面的文字变体 —— 即使某个基色在当前浅色板上碰巧 ≥4.5（`--info` / `--warning` / `--danger` 如今如此），换 `-weak` 底或主题后不一定还达标。`--success` 在 `-weak` 上只有 **4.18**，`--accent` 只有 **2.82**。

| Token              | 值        | 在 `-weak` 底上 | 在白底上 |
| ------------------ | --------- | --------------- | -------- |
| `--accent-strong`  | `#1B6B4F` | 5.74            | 6.44     |
| `--info-text`      | `#014A8F` | 7.74            | 8.83     |
| `--success-text`   | `#006B2A` | 5.94            | 6.70     |
| `--warning-text`   | `#923b0f` | 6.39            | 7.36     |
| `--danger-text`    | `#9A1F1C` | 7.07            | 8.12     |

> **品牌 token 是 K5 的落点**：`--accent` 系列 + `appName` + `logo` + `mascot` 四项构成品牌层。换品牌只改这四项，布局零改动。焦点蓝属于工作台语义，不属于品牌四项。

### 2.3 圆角

`--r-xs 4` · `--r-sm 6` · `--r-md 8` · `--r-lg 12` · `--r-xl 16` · `--r-2xl 24` · `--r-composer 22` · `--r-full 999`

用法：行内代码 / 小徽章 `xs` · 字段、菜单行、侧栏行 `sm`–`md` · 卡片 `lg` · 弹层 `lg`–`xl` · Composer 多行 `xl`、单行 `composer` · chip / 分段控件 / 头像 `full`。

### 2.4 阴影

优先发丝线，其次才用阴影。窗格用分割线分开；弹层、菜单、Composer 才给深度。

| Token         | 值                                                             | 用途               |
| ------------- | -------------------------------------------------------------- | ------------------ |
| `--shadow-xs` | `0 1px 2px -1px rgb(0 0 0 / 8%)`                               | chip、小按钮       |
| `--shadow-sm` | `0 1px 2px -1px rgb(0 0 0 / 8%)`                               | 卡片静态           |
| `--shadow-md` | `0 2px 4px -1px rgb(0 0 0 / 8%)`                               | 卡片悬停           |
| `--shadow-lg` | `0 3px 8px rgb(0 0 0 / 6%), 0 0 20px rgb(0 0 0 / 5%)`          | 弹层、下拉         |
| `--shadow-composer` | `0 0 0 1px rgb(0 0 0 / 4%), 0 2px 8px rgb(0 0 0 / 4%), 0 4px 40px 8px rgb(0 0 0 / 2%)` | Composer |

静态卡片用 `--border-subtle`，不要一上来打重阴影。

### 2.5 间距刻度

`2 · 4 · 6 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64`

4 px 网格。`2` / `6` 只给发丝光学补偿。间距刻度**不允许** 10 / 14 / 18 / 22；`--r-composer: 22` 是圆角，不在此列。

### 2.6 字体与排版

中文界面字体是产品约束，优先于技能的纯系统 UI 栈。代码仍用系统等宽栈。

```
字族  "PingFang SC", "HarmonyOS Sans SC", "Microsoft YaHei",
      "Noto Sans CJK SC", -apple-system, "Segoe UI", Roboto, sans-serif
等宽  ui-monospace, "SFMono-Regular", "SF Mono", Menlo, Consolas, "Liberation Mono", monospace
```

| Token     | 字号/行高/字重                         | 用途                                | 出现在                       |
| --------- | -------------------------------------- | ----------------------------------- | ---------------------------- |
| `display` | 28 / 34 / 600                          | 首页问候语、空态标题                | 「今天想完成什么？」         |
| `title-1` | 20 / 28 / 600                          | 页面区块标题                        | 插件页分类标题               |
| `title-2` | 18 / 24 / 600                          | 面板标题                            | 「资料库」「最近」           |
| `body-lg` | 16 / 24 / 400                          | Composer 输入、需要更舒适的阅读     | 输入框                       |
| `label`   | 13 / 18 / 500                          | 导航、按钮、chip、表头              | 侧边栏全部                   |
| `body`    | 14 / 21 / 400                          | 对话正文、卡片描述                  | 助手回复                     |
| `caption` | 12 / 16 / 400                          | 时间戳、分区标题、配额              | 「1天前」                    |
| `micro`   | 11 / 16 / 500                          | 角标、版本号                        | 「V5.5.1」                   |

强调多用 500，标题和选中标签可用 600；不要整页加粗。时长、计数、行号用等宽数字。等宽只用于代码、命令、路径、哈希和机器值。

**中文排版硬规则**：① 正文档 `body` 行高不低于字号 ×1.5（14/21 = 1.5）；② 卡片描述固定 **2 行**、`-webkit-line-clamp: 2`，不足 2 行也占 2 行高度；③ 中英混排在数字与中文之间不插空格；④ 禁止 `text-align: justify`。

### 2.7 动效

| Token                                      | 值                                |
| ------------------------------------------ | --------------------------------- |
| `--dur-fast` / `--dur-base` / `--dur-slow` | `150ms` / `180ms` / `300ms`       |
| `--ease-out`                               | `cubic-bezier(.19, 1, .22, 1)`    |
| `--ease-inout`                             | `cubic-bezier(.65, 0, .35, 1)`    |
| `--ease-exit`                              | `cubic-bezier(.8, 0, .4, 1)`      |

用法：悬停/焦点/按下 `fast`；面板、弹层、布局 `slow` 且不超过 300ms。优先动透明度和位移，不要装饰性视差或弹性过冲。**流式文字追加不做逐字动画**，只在新 Item 插入时做 150ms 淡入 + 4pt 上移。`prefers-reduced-motion: reduce` 下非必要过渡去掉，状态变化立刻到位。

`1 内容` · `10 吸顶/吸底` · `100 下拉/Popover` · `200 抽屉/侧滑` · `300 模态` · `400 审批置顶条` · `500 Toast` · `600 拖拽镜像`

## 3. 布局

### 3.1 三种骨架

三区心智不变：导航、聚焦工作、可选的上下文/工具面板。挤不下时收起分区，不要三区一起压扁。

```
A · 默认对话                    B · 按需结果工作区
┌──────────┬──────────────────┐ ┌──────────┬──────────────┬───────────┐
│ 侧边栏    │ 对话 / 页面主区    │ │ 侧边栏    │ 对话区        │ 结果工作区 │
│ 275      │ flex, 列 ≤768    │ │ 275      │ flex          │ 42%       │
└──────────┴──────────────────┘ └──────────┴──────────────┴───────────┘

C · 管理页（资料库 / 项目详情等）
┌──────────┬──────────┬──────────────────┐
│ 侧边栏    │ 可选中栏  │ 页面主区          │
│ 275      │ 272      │ flex             │
└──────────┴──────────┴──────────────────┘
```

| 区         | 宽度                                        | 底色          | 可调                         |
| ---------- | ------------------------------------------- | ------------- | ---------------------------- |
| 侧边栏     | 首选 **275**，夹在 240–520；可折叠至 0      | `--bg-app`    | 可拖；折叠独立于拖宽         |
| 管理页中栏 | **272**                                     | `--bg-app`    | 可拖拽 240–360               |
| 主内容区   | 剩余；工作窗格用 `minmax(0, 1fr)`           | `--bg-canvas` | —                            |
| 对话内容列 | **max 48rem / 768**，水平居中               | —             | —                            |
| 宽产物     | 表格、大 diff、示意图可到 **56rem / 896**   | —             | —                            |
| 结果工作区 | 默认主窗口的 **42%**，最小 420、最大 720    | `--bg-canvas` | 可拖拽、可关掉               |

**对话内容列 768 是散文与普通代码的可读性上限，不是所有页面的固定宽度。** 插件、设置、资料库等管理页可按表格或网格使用更宽主区。结果工作区打开时优先保证消息正文可读，不以固定三等分挤压对话。侧栏宽度用 `clamp(240px, var(--layout-sidebar-width, 275px), min(520px, calc(100vw - 320px)))`。

### 3.2 标题栏带（关键结构，容易做错）

窗口顶栏保持轻量，只放当前上下文与少量高频动作：

```
y 0 ────────────────────────────────────────────────── 52 ──
│ ●●●  [折叠]               │ 页面标题 / 当前模型        [动作]│
│ ←── 侧边栏段 275 ──────→ │ ←────── 主内容区段 ─────────→ │
```

- 标题栏带高 **52**，全宽，无背景色（继承各栏底色），无下边框。
- 侧边栏段：macOS `hiddenInset` 下必须先为交通灯预留空间，品牌名从第三颗灯右侧开始且空间不足时省略；再放侧栏折叠按钮。Windows / Linux 使用系统标题栏，不加这段占位。搜索改为侧栏中的明确入口。
- 任务页：左侧为任务标题，右侧最多保留“打开结果”；顶栏按住可拖动窗口。运行、待审批、失败时才显示状态。
- 首页：可显示当前模型选择，不显示营销、运营或活动入口。
- 管理页：可在顶栏放页面 Tab、搜索和一个主动作；低频动作收入菜单。

### 3.3 侧边栏纵向结构

```
y   0  ┌ 标题栏带：交通灯 + 折叠                  高 52
   52  ├ 品牌 + 搜索/筛选；新任务主按钮            高 72
  124  ├ 自动化 / 插件 / 资料库                   按内容
       ├ 项目：最近 3 项 + 每项至多 5 个任务        按内容
       ├ 最近任务：其余任务 + 分页滚动              flex
  620  └ 用户菜单                                 高 62
  682
```

- 侧边栏水平内边距 **8–12**（可点击行的外边界）；任务按钮显式左对齐。项目内任务标题与项目名称的文字起点对齐。
- 导航与列表节奏 **32** = 行高 28 + 行距 4；行可视高度 28–36，圆角 `--r-md`。选中行用中性填充 + 字重 600，不用品牌色块。
- 项目行下预览最近 5 个项目内任务；点击项目进入详情查看完整任务树。已在项目预览中的任务不在“最近”重复出现。
- 中部内容为唯一滚动区；插件、自动化、资料库与用户菜单吸底。不设置运营位。

### 3.4 网格

| 场景                               | 列  | 列宽   | 间距 |
| ---------------------------------- | --- | ------ | ---- |
| 技能 / 连接器 / 专家卡（截图 2/3） | 3   | 258    | 12   |
| 资料库提示卡（截图 4）             | 2   | 222    | 12   |
| 结果区产物卡（04）                 | 2   | 自适应 | 12   |

窗口 < 1240 时三列降为两列，< 1024 时降为一列（内容列宽随之收窄，仍居中）。

### 3.5 主内容区垂直节奏（首页）

`顶部弹性留白 → 问候语 44 → 24 → Composer 适配内容 → 16 → 上下文建议 30 → 底部说明`

首页主操作组位于视觉中部略上方。上下文建议最多 4 个，用户开始输入后立即消失；不展示场景分段控件、常驻案例或运营内容。

## 4. 响应与状态

### 4.1 折叠

- 侧边栏折叠（标题栏第一个图标 / `⌘\`）：宽度 275 → 0，`--dur-slow`，主内容区跟随。折叠后在主内容区左上角保留独立恢复按钮。
- 管理页中栏折叠（`⌘⌥\`）：272 → 0。
- 结果工作区（04）在有可展示结果时默认展开，没有结果时不显示；`⌘I` 或用户点击产物、文件、diff、网页预览时切换。用户手动收起后，同一任务的新内容不得抢开。次级面板必须可关掉。

### 4.2 断点

挤宽度时改结构，不要全局缩小字号。验收至少覆盖 1280×820、960×720、480×600。

| 宽度       | 行为                                                                 |
| ---------- | -------------------------------------------------------------------- |
| ≥1100      | 导航 + 工作区 + 可选结果区可以并存                                   |
| 760–1099   | 工作区为主；收起侧栏或结果区之一，结果区打开时覆盖主区               |
| 480–759    | 只留一个主窗格；导航与结果区改为抽屉或独立路由；Composer 必须够得到 |
| <480       | 不支持；提示放大窗口                                                 |

C7：本版只设计和验收浅色。技能色板含暗色值，token 包可以收录，但产品 CSS 不跟随 `prefers-color-scheme`，也不提供主题开关。

### 4.3 空态

统一结构：图标 40（`--text-tertiary`）→ 12 → 主文案 `body-lg`/`--text-primary` → 6 → 辅文案 `body`/`--text-secondary` → 16 → 主行动按钮（可选）。垂直居中于容器，容器高 < 200 时只保留主文案一行。

**空态文案必须给出下一步动作**，不写"暂无数据"。例：任务列表空 → 「还没有任务 / 在上方输入一句需求就能开始」+ 按钮「新建任务」。

### 4.4 加载与骨架

- 列表/网格：骨架卡（`--bg-sunken` 填充 + 1.4s 呼吸），数量按上次渲染数（≤6）。
- 行内小范围：不用 spinner，用文本占位「正在读取…」。
- 首屏 > 400ms 才显示骨架，避免闪烁。
- **禁止全屏 loading 遮罩**（会打断对话流）。

### 5.33 ProgressBar

确定进度条。高 4、`--r-full`、轨道 `--bg-selected`、填充 `--accent`，宽度按 `percent` 插值。
必带 `role="progressbar"` 与 `aria-valuenow/min/max`，以及一个 `aria-label`（说明"在进行什么"，
不是"进度"）。**不做不确定态（无限循环动画）**：不知道进度就写清"在等什么"，
一条永远在动的条会让人以为程序还活着，而它可能已经卡死了。

用于办公扩展安装（08 §4，2026-09-07 加入）。5.27 QuotaFooter 里那条**不复用它**：
那条带 >80% 转 `--warning`、>95% 转 `--danger` 的阈值配色，是"用量"语义而非"进度"语义，
合并会让两种含义共用一套颜色规则。

> **为什么它是第 33 个组件**：办公扩展的安装要几分钟，而 08 §4 要求这几分钟里
> 用户能看出"在下什么、还要多久"。此前清单里唯一的条形是 QuotaFooter 的用量条，
> 语义不同。按 Q24 的规矩，先登记再实现。

### 5.34 Dialog（模态壳）

宽 420（内容可撑到 520），`--r-lg`，`--bg-surface` + `--shadow-lg`，内边距 20。
层级 `300 模态`（§2.8 的 z-index 表里早已留位）。结构：

```
标题 title-2
正文（slot：说明文字 / 输入框 / 勾选框）
[弹性] [取消 PillButton] [主动作 PillButton accent|danger]
```

`role="dialog"`；**确认破坏性动作时用 `role="alertdialog"`**。`Esc` 关闭（§6.2 的逐层关闭链），
打开时焦点落在第一个可聚焦元素，关闭后还给触发它的按钮。

**`closable`（2026-09-16 补）**：标题行右侧一个 `IconButton`（§5.1）的 ✕，动作 = 取消。
**`variant="danger"` 时即使传了也不画** —— 一屏要填四个字段的弹窗多一个出口是省事，
而破坏性确认里多一个"看起来无害"的关闭口子只是增加误关的机会。

**它是已登记的模态壳，不是既成事实**：新模态一律用它搭。渲染层眼下还有**四处**各写一遍的
确认面板——`views/library.tsx` 与 `views/sidebar.tsx`（**两处共用 `ew-delete-confirm`**）、
`components/changes-view.tsx` 的 `ew-revert-confirm`、`components/composer.tsx` 的
`ew-danger-confirm`（`components/approval-card.tsx` 的 `role="alertdialog"` 不算，
那是 10 §3 规格下的内联审批卡，不是模态）。实现 Dialog 时只并入 `library.tsx` 这一处，
刻意把改动面控制住；其余三处**登记为待还债务**，之后再逐个折进来。

**`ew-delete-confirm` 的 CSS 规则因此不能跟着 library 一起删** —— sidebar 还在用它。
2026-09-08 实现 Dialog 时差点删掉：三个选择器共用一条容器规则，而 sidebar 的测试
只断言 role 与文案，删了一条测试都不会红，表现是那个确认框丢掉边框背景阴影。理由不是好看：三份各写一遍的确认文案，「删文件」还是
「删索引」这种措辞纪律会在其中一处慢慢走样而没人发现，直到用户真的删错了东西。

### 5.35 SecretInput（密钥录入）

高 32（同 §5.16 SearchInput）、`--r-md`、`--bg-surface` + 1px `--border-subtle`，等宽字体显示已保存态。
**三种状态是三件不同的事，不能压成一个输入框**：

```
① 空       [ 粘贴 API 密钥…                     ]            ← type=password，autocomplete=off
② 刚粘贴   [ ••••••••••••••••••••••  ] [保存]  形状提示       ← 形状不对时 warning 文案，但不拦保存
③ 已保存   已保存 · ****3f9a   [更换] [清除]                   ← 值不可读回；「清除」是显式动作
```

| 项       | 规格                                                                                                                                        |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 遮罩     | `type="password"` + `autocomplete="off"` + `spellCheck=false`。**没有"显示密码"的小眼睛** —— 见下                                             |
| 形状校验 | 粘贴即校验长度与前缀，只给提示**不拦保存**：厂商随时会改 key 的形状，拦下来的代价是用户拿着一把有效的 key 进不去（10 §2.2「认不出来也要显示」） |
| 已保存态 | 只显示后四位。**没有读回路径** —— 值不进 `value` prop，也不从任何 IPC 返回                                                                    |
| 清除     | 显式动作，**不是把输入框清空**：后者在用户看来与"没保存成功"无法区分                                                                          |
| 不可用   | `safeStorage` 不可用时组件上方挂一条 `TipBanner`（§5.29）说明只能明文保存或每次手填，**不静默降级**（11 §4.3）                                |

**为什么不能复用 SearchInput（§5.16）加一个 `secret` prop**：`SearchInput` 的值是可读回的
（受控 `value`），而密钥的"不可读回"是一条**安全属性**。做成同一个组件的 prop，就存在
"某处忘了传那个 prop"这种失败方式，而它的表现是密钥出现在渲染进程里 —— 等于出现在任何一个
XSS 面上（11 §12 第 2 条）。两个组件的话，这种失败方式在类型层面就不存在。

**没有"显示密码"按钮**同理：它要求组件持有明文并能渲染出来。用户想确认自己贴对了，
靠的是后四位与一次连通性检查，不是把 key 亮在屏幕上（旁边可能坐着别人）。

> **那么「添加模型」弹窗里那个小眼睛算什么**（11 §4.4，2026-09-16）：那不是这个组件。
> 本条禁的是**已保存密钥的读回** —— `SecretInput` 的值不进 `value` prop，也不从任何 IPC 返回。
> 弹窗里的明文是用户此刻正在打的字，本来就在渲染层；开关默认关，只为让人确认自己粘对了。
> 改一条已存模型时那个框**留空 = 沿用已存的那把**，界面上仍然只有后四位。

> **为什么它是第 35 个组件（不是 11 §4.5 原写的第 34 个）**：那份设计写于 2026-09-07，
> 当天 `Dialog` 抢先占了 5.34。按 Q24 的规矩先登记后实现 —— 这条编号冲突正是登记制度
> 起作用的地方：两个组件同时被"计划成第 34 个"，而清单里只能有一个。

### 5.36 GlobalSearchPalette（全局搜索面板）

覆盖在当前界面之上，不替换主内容区。宽度沿用 `--layout-content-column`，最大高度受窗口约束，
`--r-2xl`、`--bg-surface`、`--shadow-lg`；全屏遮罩使用 `--bg-scrim` 与模态层级。结构：

```
搜索输入（自动聚焦）
聊天
  状态点 · 标题 · 空间名 · ⌘/Ctrl+1…9
快捷操作
  新聊天 · 打开文件夹 · 搜索文件
```

空查询显示最近 9 条顶层聊天；输入后切到 `thread/search` 返回的标题与正文命中。上下方向键移动
选中项，`Enter` 打开，`Esc` 或点击遮罩关闭；关闭后焦点归还触发按钮。选中态使用中性
`--bg-hover`，不使用品牌色。Windows/Linux 的快捷键提示显示 `Ctrl+`，macOS 显示 `⌘`。

## 6. 状态视觉规范

### 6.1 任务状态（清单 §4.3 六态）

| 状态   | 点色               | Badge                     | 侧边栏行                          |
| ------ | ------------------ | ------------------------- | --------------------------------- |
| 进行中 | `--accent` + 呼吸  | `success` 底 · 「进行中」 | 标题 600                          |
| 规划中 | `--info`           | `info` · 「规划中」       | 标题 600                          |
| 待处理 | `--warning` + 呼吸 | `warning` · 「待你确认」  | 标题 600 + 行尾 `--warning` 圆点  |
| 已完成 | `--text-tertiary`  | `neutral` · 「已完成」    | 常规                              |
| 失败   | `--danger`         | `danger` · 「失败」       | 常规 + 标题前 `--danger` 感叹图标 |
| 已归档 | 无点               | `neutral` · 「已归档」    | 整行 `--text-tertiary`            |

「待你确认」用第二人称，因为它要求用户行动；其余用客观描述。状态派生规则见 04 §3.2（**不能只读 `ThreadStatus`**，README F7/F8）。

Badge 文案一律用 §2.2 的 `-text` 变体，底用 `-weak`。**6px 状态点不满足可靠的 3:1**（`--accent` 对 `--bg-app` 实测 3.00，余量为零），因此它在无障碍上被定义为**冗余装饰** —— 状态的可感知性由同一行的文字 Badge 或图标承担，点只做快速扫视。这也是 §8 "状态不靠颜色单传" 那条的技术前提。

### 6.2 焦点与键盘

- 焦点环：`0 0 0 2px --focus-ring`，`outline-offset 1px`，圆角随组件。**只在键盘导航时出现**（`:focus-visible`）。
- 所有可交互元素必须可 Tab 到达；列表用 `↑↓` 在项间移动、`Tab` 跳出列表（roving tabindex）。
- `Esc` 逐层关闭：Menu → Popover → 抽屉 → 模态。

### 6.3 禁用与只读

禁用：`--text-tertiary` + `opacity .6` + `cursor: not-allowed`，**必须配 tooltip 说明原因**。
只读（非禁用，如其他设备上的自动化、Ask 模式下的写操作）：正常颜色 + 右上角 12px 锁图标 + tooltip 说明「在 <设备名> 上运行，点击可迁移到本机」（07 §6）。两者视觉必须可区分。

### 8.3 边框对比度：一个必须正面承认的取舍

工作台的分隔线是**极浅的中性发丝线**（8–14% 主色透明度），这是密度语言的一部分。要把 `--border-default` 提到 3 : 1 需要做到约 `#8A8A8A` —— 那已经是中灰实线，界面会立刻变重。

**取舍与处理**（不许两头都要）：

1. **默认主题保真度优先**，边框按技能发丝线，并接受它在 WCAG 1.4.11 上不达标这个事实。
2. **控件的边界不得只靠描边表达**：输入框、下拉、chip 必须同时具备**填充差异**（`--bg-surface` on `--bg-app`）与**尺寸/内边距差异**；聚焦态用 2px `--focus-ring`（不透明蓝，对 `--bg-surface` 5.39 : 1），这是键盘用户的主要定位手段。
3. **提供高对比模式**，在 `prefers-contrast: more` 与设置项「高对比度」下均生效，只覆盖三个 token：

| Token              | 默认                   | 高对比    | 高对比下的比值 |
| ------------------ | ---------------------- | --------- | -------------- |
| `--border-subtle`  | `rgb(13 13 13 / 8%)`   | `#A3A3A3` | 2.52           |
| `--border-default` | `rgb(13 13 13 / 12%)`  | `#8A8A8A` | **3.45** ✅    |
| `--border-strong`  | `rgb(13 13 13 / 14%)`  | `#5D5D5D` | 6.58           |

高对比模式**不改**布局、圆角、字号，因此不产生第二套设计；它是同一套 token 的一组覆盖值。
