# 17 · 独立会话通信

## 产品行为

2026-10-18 用户决定对齐对话式交互：任务页不再提供独立的“会话通信”表单、跨项目复选框、目标下拉或通信记录列表。用户在正常对话中用自然语言指定目标和请求，例如“请让季度核对任务检查这份数据，并把结果返回这里”。代理复用下述 MCP 发现目标并发起调用；目标不明确时先澄清，发送和读取仍展示必要的授权确认。

默认仅发现同项目根任务；跨项目需明确指定目标，并在授权卡展示范围。无项目任务不将所有无项目任务视为同一项目。请求正文包含可选必要摘要与文件引用文字，不自动附带来源历史。工具调用和返回结果沿用正常对话记录，底层队列、取消与状态核对能力保留，不另设常驻表单。

代理通过随应用分发的 `thread_communication` MCP 获取同项目任务元数据、请求读取摘要/历史或发起请求。工具的目标、正文与共享范围进入显式确认卡；完全访问不代答此授权。授权只覆盖一次工具调用，不从文件、其他会话来信或共享目录推断授权。收到的内容标识为其他会话的信息，不能视作用户再次授权。

每条请求有稳定 ID。目标忙碌时保存在本机权威队列；空闲后经适配层恢复任务并启动正常回合，沿用目标模型与审批档。目标回合的最终文本或失败结果自动返回来源；来源忙碌时同样排队。回复可启动来源的汇总回合，但汇总回合不产生另一条自动回复；继续发送新请求仍需新的用户授权。子代理、定时任务不参与独立会话通信。

列表展示发送、等待、回复排队、完成、失败、投递结果待核对。历史不隐式持续共享，文件引用只是文字，不把附件或完整工作目录自动复制到其他项目。

## 实现边界与恢复

MCP stdio 进程仅通过受认证的本机回环 HTTP 连接宿主。身份来自内核 `_meta.threadId`，并按当前 MCP item 的服务名、工具名、完整参数、回合及内核世代核对；不接受模型自报来源。所有内核操作仍在 kernel-adapter，经 app-server JSON-RPC v2；不改内核、不读内核数据库或 rollout。

本机 `thread_message` 属权威表，含用户授权的消息正文及回复，不属于可重建投影，也不进入日志。调用 ID 去重，状态先落盘再投递；启动恢复已排队请求。投递中断不盲目重试：以写入内核用户消息的请求标识及权威回合历史核对，找到则接续，不能确认则保留未知状态并明确显示。删任一任务时清理相关正文；归档不自动唤醒；重启不会重放已确认投递的请求或回复。

项目归属优先读取宿主登记的任务环境，旧/外部任务才按 cwd 与项目根的路径边界回退，不依赖协议投影中可能为空的 projectId。请求/回复进入目标和来源的正常模型上下文，沿用既有模型拓扑。读取历史只共享文本和文件引用，不把图片 Base64 或工具执行内容混入文本。回复超过 12000 字明确截断，失败/停止结果明确标注；通信状态独立事件更新，避免触发产物文件重扫。

删除清理针对对应本机队列及其正文；已投递的原生消息按接收会话既有留存规则管理，不改写另一个会话的历史。

发现列表当前最多 100 个候选；底层记录查询最多 100 条且未完成优先。后台协调器处理全部未完成记录，不受查询上限影响。任务页直接展示正常对话，授权卡沿用已有 MCP 审批交互。
