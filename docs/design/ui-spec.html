中间那档是 prefers-contrast: more 与设置项「高对比度」下的取值。它只覆盖 3 个 token，不改布局、圆角、字号 —— 不产生第二套设计。
处理方式

① 默认主题保真度优先，接受 1.4.11 不达标这个事实；② 控件边界不得只靠描边表达，必须同时有填充差异与内边距差异；③ 聚焦态用 2px --focus-ring（对白底 3.16 : 1，达标），这是键盘用户的主要定位手段；④ 提供只覆盖 3 个 token 的高对比模式。

验收时对比度断言必须分档：文本 ≥4.5、-text 变体 ≥4.5、边框在高对比模式下 ≥3.0。不允许把默认模式的边框断言设成 3.0 然后放宽通过条件。

两条反直觉的规定

① 流式文字追加不做逐字动画。长回复逐字入场会让整段看起来在卡顿，且触发大量重排。只在新 Item 插入时做 120ms 淡入 + 4pt 上移。

08

状态视觉

清单要求 6 种任务状态，实际需要 7 种 —— TurnStatus::Interrupted 是真实存在的终态，映射到"已完成"会误导、映射到"失败"会让用户以为出错了。

状态Badge点侧边栏行派生依据
进行中进行中accent + 呼吸标题 600Active 且 activeFlags 为空
规划中规划中info标题 600投影表 mode=plan 且有未确认 plan item
待处理待你确认warning + 呼吸标题 600 + 行尾圆点activeFlags 含 WaitingOnApproval / WaitingOnUserInput
已完成已完成tertiary常规投影表 last_turn_status=completed
失败失败danger常规 + 标题前感叹图标投影表 failed 或 SystemError
已中断已中断，可继续tertiary常规投影表 interrupted · 清单缺此态
已归档已归档无整行 tertiarythread/list?archived=true
为什么状态必须自己派生

内核的 ThreadStatus 只有 NotLoaded | Idle | SystemError | Active{activeFlags}，未加载的 thread 状态恒为 NotLoaded、不携带上次执行结果；thread/list 也没有状态与日期过滤参数；ThreadExtra 是空结构体、thread/metadata/update 只能改 projectId 与 gitInfo —— 协议没有客户端自定义元数据槽。三条加起来，"已完成 / 失败 / 已中断"这几个用户最关心的状态和"按状态筛选"这个功能，都只能靠本机投影表（09 §4.1）。「待你确认」用第二人称，因为它要求用户行动；其余用客观描述。

暗色推导

截图只有浅色。暗色按同一套 token 名反相，保留暖偏（中性色带黄，避免冷蓝）。用 §07 顶部的 Light / Dark 开关可以把上面所有组件样例一起切过去看。

Token浅色暗色暗色下的比值
背景
--bg-app#F2F1EE#191917—
--bg-canvas#FCFCFA#1F1F1D—
--bg-surface#FFFFFF#262624层级主要靠它与 canvas 的明度差
--bg-selected#E9E8E4#33332F—
--bg-inverse#1D1D1B#F2F1EE反转后分段控件变浅底深字
文字
--text-primary#1F1F1D#F0EFEA13.2 – 14.3
--text-secondary#6E6D68#A8A7A06.3 – 6.8 · 比浅色更宽裕
--text-tertiary#9B9A94#77766F3.3 · 仍为非文本专用
边框与品牌
--border-subtle#E7E6E1#2F2F2C1.13 · 只做收边
--border-default#DCDBD5#3A3A361.33 · 高对比模式提到 #5A5A54
--accent#2FA37A#41B8916.13 · 提亮后可写文字

暗色的两条与浅色不同的规则

① 阴影全部失效。暗色下 --shadow-* 归零，层级由 --bg-surface(#262624) 与 --bg-canvas(#1F1F1D) 的明度差承担，描边只做收边 —— 因为 --border-subtle 在暗色下只有 1.13 : 1，指望它撑层级会得到一片糊。

② 语义色的文字变体方向相反：浅色下是加深（--danger-text #A53227），暗色下是提亮（#F5A9A1）。同一个 token 名、相反的推导方向，这是实现时最容易写错的一处。
