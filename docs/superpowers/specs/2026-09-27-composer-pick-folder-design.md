## 0. 审查结论与体验基准

「选文件夹 → 创建或复用本地项目」本身合理，可以缩短打开仓库的路径。缺陷是原稿把这条路径变成所有任务的前置条件，并把项目、cwd、附件和权限混为一体。

截至 2026-10-01 查阅的官方资料：

- [Projects and chats](https://learn.chatgpt.com/docs/projects?surface=app)：ChatGPT 和 Codex 均支持无项目聊天；本地项目可以关联文件夹。聊天组织与执行目录应分开建模。
- [Use ChatGPT](https://learn.chatgpt.com/docs/use-chatgpt)：附件是为任务提供资料的常规入口。
- [Work with files](https://learn.chatgpt.com/docs/artifacts-viewer?surface=app)：用户能在对话里创建、预览、下载和继续修改产物。

以上支持「无项目可开始、附件可直接添加、产物可持续访问」的体验原则。官方文字没有规定最近项目预选、复用 Toast、已有聊天换目录等具体控件行为；本文这些规则是基于上述原则的 EvoWork 设计判断，并非声称已逐像素复现官方客户端。普通 ChatGPT 项目也不等同于本地目录；本功能称为**本地项目**。多根目录仍另立需求，不宣称完整复刻上游项目能力。

| 严重度 | 原稿缺陷 | 本版处理 |
|---|---|---|
| 高 | 没选项目不能发送、不能加附件，普通问答也必须先找目录 | 提供「不使用项目」，宿主分配每任务独立且持久的工作目录 |
| 高 | 最近活动项目自动预选，后台任务或别处活动能改变首页下一条消息的目标仓库 | 全局首页默认无项目；项目入口继承明确上下文，草稿保留用户选择 |
| 高 | 已有任务选择项目会把下一回合 cwd 改到另一个仓库，旧历史和新目录混合 | 任务创建后固定执行目录；切换到另一项目通过新任务完成 |
| 高 | 路径检查发生在 realpath 之前，软链可绕过根目录或受保护目录检查 | 先解析真实目录，再检查、去重、持久化；发送前复查 |
| 中 | 去重仅先查后插，并发选择会创建重复项目；镜像失败后复用永远跳过镜像 | 主进程串行化同目录创建；已有项目缺 kernelId 时幂等重试镜像 |
| 中 | 按 cwd 最长匹配推断所有任务归属，后来新增嵌套项目会迁移旧任务 | 自建任务记录显式归属；最长匹配仅用于无显式归属的外部/旧任务 |
| 中 | 目录宽度检查被描述成完整读写保护，主目录提示承诺「不会再询问」 | 保留宽目录限制，说明它限制默认工作范围，不能替代实际权限策略 |

## 1. 决策

| # | 决策 |
|---|---|
| D-F1 | 项目保持一级组织概念，但任务不强制属于项目；无项目任务出现在「最近」 |
| D-F2 | 项目菜单「选择文件夹…」表示打开本地项目，创建或复用；附件入口表示添加资料，不创建项目、不改 cwd |
| D-F3 | 全局首页默认「不使用项目」。从项目发起时选中该项目；有效草稿中的显式选择优先保留 |

| D-F5 | 任何新任务都必须有宿主明确提供的 cwd；无项目由宿主分配任务目录，禁止使用进程默认目录 |

## 2. 现有实现与需要改变的接缝

本次只改设计，不把目标行为写成已实现。复核位置（行号会漂移）：

| 现状 | 接缝 | 设计影响 |
|---|---|---|
| 三个建项目入口共用函数；路径闸门后直接 insert，再镜像；镜像失败只记日志 | `apps/desktop/src/main/renderer-bridge.ts` 的 `createProjectImpl` | Composer 复用入口，补真实路径检查、串行去重和镜像补偿 |
| 没选项目时发送不传 cwd；适配层仅条件性写入 cwd | 同文件 `send`；`services/kernel-adapter/src/adapter.ts` 的 `createTask` | 上层解析任务环境，适配层拒绝缺省 cwd |
| 已有任务可通过下一次 turn 修改 cwd | `services/kernel-adapter/src/scenario.ts` 的 `expandTurnStart` | 普通续聊不得覆盖到其他工作目录 |

| 项目分组与任务计数使用不同 cwd 匹配方式 | sidebar、项目卡片查询 | 显式归属优先，共用同一查询口径 |

## 3. 设计

### 3.1 首页和菜单

```text
[📁 不使用项目 ▾]
┌─────────────────────────────────┐
│ ✓ 不使用项目                     │
│   evowork      ~/develop/evowork │
│   Q3 报告      ~/Desktop/Q3 报告  │
│ ─────────────────────────────── │
│ 📁 选择文件夹…                   │
└─────────────────────────────────┘
```

「不使用项目」是合法值，不是未完成状态。「选择文件夹…」是动作项，固定在分割线下；不能成为选中值。沿用 `InlineSelect.actions` 变体，包含键盘导航、焦点恢复和读屏名称。

- 全局「新任务」默认不使用项目；从项目页/侧栏项目的新任务入口发起则选中该项目；明确绑定项目的场景显示该项目。场景切换若要更改已有草稿的项目，须明确显示变更，不静默覆盖用户选择。
- 当前草稿保留已选项目、正文和附件；恢复时项目失效则提示并要求选择「不使用项目」或其他项目，不偷偷换仓库。
- 最近活动只影响菜单/侧栏排序，不决定 cwd。不得因列表刷新、自动化或其他窗口活动改变当前选中值。
- 取消系统对话框：保留原选中值和草稿，不提示。复用已有项目：直接选中，不例行弹 Toast；新建后刷新项目快照并选中。拒绝或失败：保留原值和草稿，显示原因。
- 文件夹选择、检查与创建期间显示忙碌状态，禁止重复提交及发送。结果返回时核对草稿标识；若已切换页面/草稿，不把结果选进新草稿。已成功创建的项目仍可从项目列表找到。
- 零项目仍可发送、添加附件和选择文件夹；空列表不描述「在默认目录运行」。

### 3.2 无项目任务与目录生命周期

「无项目」不意味着没有 cwd，也不是不保存的临时聊天。

1. 首次发送前，主进程生成稳定的任务环境 ID，并创建 `~/.evowork/workspaces/<环境ID>/`，目录只用于该任务的附件与产物。不得复用全局共享 cwd、主目录或 Electron 启动目录。预先创建的目录不产生侧栏空任务。
2. `thread/start` 显式传此目录；成功后将目录与 thread 关联并持久化，续聊和重启恢复沿用同一目录。首次发送失败时保留草稿与环境，重试不创建多个任务/目录；若 thread 已创建而 turn 失败，重试沿用该 thread。
3. 无项目任务不调用 `project/create`，不进入项目侧栏；产物照常进入结果区/资料库，可预览和导出。任务目录不是沙箱意义上的绝对不可读取其他位置的隔离容器，权限依旧由内核与策略控制。
4. 任务目录与任务同寿命；不得按会话结束或应用重启自动清空。删除任务时沿用删除确认，并说明本地附件和产物的处理；用户导出到其他目录的副本不受影响。废弃草稿的暂存目录另按草稿清理规则处理。
5. 配置一个独立 `drafts/<草稿ID>/` 暂存区。任务环境由宿主管理，通过显式 cwd 送入适配层，不允许前端任意声明一个内部路径以获取通行。恢复时验证登记关系、真实路径与目录存在性。

这一能力需要任务环境解析与生命周期管理，不能继续承诺「后台几乎不用新写」或「肯定不改表」。优先复用任务 cwd 和现有元数据；若不能可靠记录环境 ID、显式项目归属与清理关系，就增加最小宿主元数据/迁移，仍不读取内核内部存储。

### 3.3 添加附件

- 首页未选项目：直接打开文件选择框；拖入文件走相同暂存管道。显示附件卡片和解析状态，取消不改变草稿。无需先弹项目选择器。
- 选择文件只是复制/解析资料，不授予源文件所在文件夹的整体写权限，也不把该文件夹建成项目。
- 附件先保存到草稿暂存区；发送时按最终环境归入项目的 `uploads` 或无项目任务的 `uploads`。上传/解析/迁移未完成时阻止发送并显示状态；失败可重试或移除附件，正文保留。
- 草稿切换项目时仍保留附件卡片，发送前按最终环境完成归入并更新路径；成功后才清理源暂存。不要向内核传已失效的旧路径。
- 既有任务新增附件使用该任务固定的 cwd。此处的「上传」仅指本地导入，沿用 K6，不引入云端解析。

### 3.4 本地项目创建、去重和镜像

Composer 复用 `importProject`；成功返回 `projectId`、`reused` 与项目快照。取消、策略拒绝和运行失败应可区分，不能用同一个空返回值表示。

处理顺序：检查绝对路径与目录存在 → `realpath`（目录与 home）→ 在真实路径上执行根目录规则和硬拦截 → 同目录串行区内查询去重 → 自动命名 → 落库 → 幂等镜像。发送时重新验证，防止选择之后目录被删除或软链目标被替换。

- 去重使用平台文件系统的目录身份/规范路径规则，路径比较必须有分隔符边界，不能用裸字符串前缀。大小写敏感性按实际平台/卷处理，不能一律 lowercase，也不能以「没有手输」排除大小写别名。
- 同一规范目录的查询和插入须在主进程串行执行，覆盖 Composer、引导、项目页和多窗口并发；若依赖数据库唯一约束，要把迁移列入范围。
- 选中目录 realpath 失败则拒绝，不退回字符串放行。已有失效根保留为失效项目，不能用 fallback 确认它与可用目录是同一个。
- 复用已有项目不重复落库、不改用户自定义名称。新建对话框发现已有目录时说明使用已有项目及其名称。
- 已有项目具备 kernelId 时不重复镜像；缺失时用原项目 ID 作幂等键重试。镜像失败保留本地项目，显示可恢复状态；下次选择或使用时可补偿，不能永久跳过。
- 自动名称为目录名；重名用「目录名 · 上级目录名」，再加 `(2)` 等。用户自定义名称不自动改写；列表同时显示路径以区别同名项目。创建本身不在用户目录写配置文件。

### 3.5 路径规则和 cwd 守卫

保留 `workspaceRootRefusal(path, home)`，但它接收解析后的真实路径，以路径段/祖先关系判定。

| 不可由用户选择为项目根 | 原因 |
|---|---|
| 文件系统根、Windows 盘根、UNC 共享根 | 范围过大，请选择具体工作文件夹 |
| 主目录及其任意祖先 | 范围覆盖整个主目录，请选择具体工作文件夹 |
| `~/.evowork` 及子目录 | 这是应用的数据目录，请选择自己的工作文件夹 |
| 现有策略的系统/凭据等硬拦截目录 | 显示现有策略原因 |

外置卷根与 Desktop 等子目录可以选，但在选择器中显示完整目标范围；这是一项 EvoWork 产品取舍，不称作 ChatGPT 的统一限制。旧项目不删除，标记不可用并在发送前拒绝。宽目录限制避免过大的默认工作范围，**不能据此声称选中目录就免去所有审批，或目录外所有读取都需审批**；覆盖、删除等沿用现有策略，完全访问模式也不等同于工作空间模式。

统一守卫位置：

1. 用户建项目入口：真实路径根目录规则与硬拦截全部生效。
2. 主进程环境解析：项目根复查；内部任务目录仅允许由宿主登记的 task workspace，助理使用登记的固定 assistant 目录。不能因为字符串包含 `.evowork` 就全部放行或全部拒绝。
3. 适配层所有任务创建/恢复/续聊入口：新任务缺 cwd、cwd 非绝对路径或命中 `too-broad` 时拒绝；续聊检查实际有效 cwd，不能仅检查请求里是否携带覆盖字段。内部目录必须来自第 2 步的已验证环境。
4. 启动内核进程显式指定独立的空启动目录，它只作纵深防护，不可作为任务 fallback。

守卫通过 app-server 边界实现，不改内核。旧版把 `thread/start` 一处称作「全部入口」过强：必须追踪 resume、fork、已有任务 turn 及自动化实际有效环境；任何新增入口都要复用同一环境验证。

### 3.6 任务固定目录与归属

创建任务时快照显式 projectId（可为空）与 cwd；普通续聊不能因首页选择、最近项目排序或侧栏点击而改变它。任务页显示项目/目录及路径，运行期间也不能换 cwd。

「在其他项目新建任务…」先打开新草稿，用户选择目标并确认发送；不自动复制或发送原任务全部历史。原任务留在原项目，产物路径不变。无项目任务后续需要处理仓库时也走这条路径；仅新增附件不改变 cwd。

任务归属与数量：显式 projectId 优先，无项目任务保持在「最近」；只有外部导入/旧任务缺少显式归属时，才按 cwd 与项目根的真实路径做最长边界匹配。项目新增嵌套根不得迁移已有显式归属任务。侧栏、项目卡片、最近活动统计共用此口径，archived 的处理保持现有规则。

### 3.7 自动化

自动化不因未选项目而天然无效：通用摘要/资料处理允许无项目，执行时每次运行分配独立、可恢复的任务环境；需要仓库的自动化显式绑定项目。执行前解析环境，再调内核。

旧无项目自动化按无项目模式运行，不能仅因 projectId 为空就暂停。指定项目失效、环境创建失败或环境不符合策略时，立即暂停并通知可操作的原因，记 `FAILED / ENVIRONMENT`，不启动任务；不走不计入连续失败的「三次失败」路径。恢复需修复环境，不能偷偷换成无项目或别的项目。

## 4. 边界与实现范围

- K1/K2：不改内核，任务环境和归属由宿主记录；对内核只走现有 app-server 协议。
- K6：附件处理继续本地执行，无新增云端文件上传路径。
- 复用现有组件与项目 IPC；草稿附件和环境生命周期是否需要新增端口按现有边界确定，不能用「不新增 IPC」约束倒逼错误体验。
- 允许为可靠持久化增加最小元数据；实现计划须明确存储与恢复方式，不能把 cwd 猜测当成项目归属真源。

## 6. 测试设计

测试后果，避免只断言函数返回枚举。以下是实现要求，本次文档审查未运行这些测试。

| 场景 | 后果断言 |
|---|---|
