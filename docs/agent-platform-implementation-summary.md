# EvoWork 实现方案总结

> 基于 EvoWork 官方文档与运行时环境的直接观察整理。官方未发布完整架构白皮书，本文档中已区分「文档确认」「运行时观察」与「合理推断」三类信息来源。

---

## 一、总体结论

**EvoWork 采用「端云协同」混合架构：客户端是重执行侧（富客户端），云端是重智能侧（API 服务）。**

单纯归类为"富客户端"或"纯 API 调用"都不准确。它属于当下主流的 **"本地 Agent Runtime + 云端模型 API"** 架构模式：

- **客户端（四肢）**：负责干活——文件操作、代码执行、沙箱隔离、产物管理
- **云端（大脑）**：负责思考——推理、生成、检索

这种设计的核心动机是**隐私与能力兼顾**：敏感数据不出本机，模型能力无需本地部署重型算力。

## 三、富客户端侧的构成（本地执行）

| 组件                | 说明                                                                                                                              | 信息来源   |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| **本地 Agent 沙箱** | 工具调用（读写文件、Bash、Grep 等）在本机沙箱中执行，产物直接落在本地磁盘                                                         | 运行时观察 |
| **托管运行时**      | 本机 `~/.evowork/binaries/` 下安装独立的 Python 3.13 和 Node 22，数据分析与脚本执行完全在本地运行，包安装走隔离 venv / 受管工作区 | 运行时观察 |
| **本地存储**        | 自动化任务存于本地 SQLite（`~/.evowork/evowork.db`）；技能、记忆、MCP 配置均为本地文件                                            | 运行时观察 |
| **内置浏览器**      | 可预览 localhost 开发服务器，客户端本身承载 Web 渲染能力                                                                          | 运行时观察 |
| **本地 MCP 服务器** | `~/.evowork/mcp.json` 中配置的 MCP（如 Playwright）以子进程方式在本机启动                                                         | 运行时观察 |
| **隐私边界**        | "所有文件处理默认在本地完成，原始数据不上传云端。服务端仅处理数据片段，用后即弃，不保存也不用于模型训练"                          | 官方文档   |

## 五、一次任务的典型执行流程

1. 用户在对话区用自然语言下达任务（可附文件/截图/`@` 引用）
2. 云端 LLM 接收上下文，进行任务理解与规划（对话区显示"规划中"）
3. Agent Loop 启动：模型逐步决策调用哪个工具（Read / Write / Bash / Grep…）
4. 工具在本机沙箱中执行——读写本地文件、运行 Python/Node 脚本、启动本地服务器
5. 执行结果回传云端模型，模型基于结果决定下一步（循环迭代直至完成）
6. 产物在右侧结果区呈现：文件预览、内置浏览器预览、变更 diff
7. 用户可继续追问，基于已有上下文迭代交付

> 关键点：**"决策"在云端，"执行"在本地**。模型不直接碰文件系统，而是通过工具调用协议驱动本地沙箱完成操作。
