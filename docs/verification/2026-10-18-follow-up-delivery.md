## 实现与判据

| 行为 | 核对结果 |
| --- | --- |
| 本次发送方式 | 原生 radio 互斥显示“排队发送 / 立即插话”，默认排队；仅选择不会发送或中断。 |
| 单次插话 | 真实点击发送后返回明确插话回执，显示“已发送，正在调整方向”，选择恢复排队；下一条点击排队按钮确实入队，在原回合放行前没有进入模型请求，放行后两条输入均可在真实请求中核对。 |
| 跨任务范围 | 在两个运行任务之间切换、回到新任务、再打开原任务，均默认排队；结束运行后下一轮也恢复排队。 |
| 发送和停止独立 | 运行中显示独立“停止”和跟随当前方式的发送按钮。点击、Enter 发送均接通；停止不发送草稿，停止后草稿保留，Esc 仍可中断。空草稿、解析中、模型不可用或请求在途时禁用发送，停止仍可用。输入本地命令时仍保留停止。 |
| 降级可见 | 注入缺失活动回合投影：适配层实际排入原生队列；IPC 保留降级原因；页面同时显示“等待当前任务完成”和“当前没有可插话的回合，这条输入已改为排队。”，不显示插话成功。放行后模型实际收到该输入。 |
| 失败与迟到回执 | 回归覆盖失败保留草稿及插话选择、成功重试才重置、请求在途禁止重复提交、切任务后旧回执不能改变新草稿或新选择。 |
| 队列管理 | 排队显示、编辑、上下调序、删除及回合结束后的自动执行通过真实窗口验证。本机降级队列同样返回 queued=true，不再把队列存放位置误当投递结果。 |
| 窄窗布局 | 1000 与 600 宽验证按钮组位于输入卡片内部、按钮互不重叠、方式选项完整位于窗口内。600 宽先收起覆盖式侧栏；按钮组整体换行，停止与发送不拆散。截图已查看。 |
| 相关回归 | 输入创建任务、无项目任务目录隔离，以及流式进度、停止、刷新和详情恢复均通过。 |

主要变更为 Composer、App 本次状态、共享 SendResult 与桌面桥接回执；适配层复用原生 turn/steer 和队列，没有修改执行内核或网关。

## 过程与边界

首轮窗口用例 5 通过、4 失败：旧用例仍要求运行中没有发送按钮；“扣住下一次请求”的剧本未绑定需求，可能被后台请求消费；降级用例还等待了不属于该剧本的 turnClaimed 指标。已改为按需求标记绑定并核对 scriptedTurnHeld，保留队列不得提前进入模型请求的判据；旧断言改为明确验证独立的停止与禁用发送按钮。

第二轮 9/9 通过，但人工查看截图发现 600 宽时按钮组挤出输入卡片，展开侧栏还遮住输入区。随后修正运行中工具行与按钮组布局，补充卡片边界、完整选项可见性断言，并增加跨任务范围旅程，得到上述最终 10/10。前两轮现场保留于本机 `/private/tmp/evowork-follow-up-ui-first/` 与 `/private/tmp/evowork-follow-up-ui-second/`。

全仓复验曾出现一次既有“慢文件预览返回前用户已关闭结果区”失败（2951 项通过、1 项失败、2 项既有跳过）；同一测试单独复验通过。没有放宽该测试或修改文件预览逻辑，Electron 结束后串行完整复验再次通过（2952 项通过、2 项既有跳过）。

受限环境首次完整构建被 Swift 缓存写入权限拦截，随后通过允许的沙箱外构建入口成功。窄窗导航覆盖仍沿用原应用交互，本轮只验证收起导航后可操作的完整输入区。降级旅程只对宿主投影注入故障，之后 UI、IPC、适配层、原生队列与模型请求均为真实链路。反馈证明内核已接收，不保证模型已经执行新要求、立刻取消在途工具或撤销已发生动作。未验 Windows/Linux、真实厂商模型遵循质量，未发布安装包。
