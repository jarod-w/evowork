# 四项 P2 执行问题修复与验收

2026-10-24，macOS arm64。在四项 P1 已提交的基础上，继续处理文件轮询、图表数值表达、图表缺字检查和移动后的重复产物索引。

## 实现

1. 文件监视的初始基线只保存元数据指纹（设备、inode、大小、纳秒 mtime/ctime），不先同步读全部正文。正常两秒轮询异步列举与分块读取，稳定文件复用完整 SHA-256 缓存；十分钟重新校验。缓存会检测等长尾部修改、恢复 mtime 与原子替换；忽略目录、上传副本、符号链接和非产物在读正文前过滤。重叠扫描复用在途哈希，同一监视器不并发扫描，停止后不发布迟到结果；批量新增/删除只触发一次对账。
2. `value_format` 接入实际数值纵轴，比例 0.25 显示 25.0%，千分位与一位小数同样生效。正负混合堆叠分别累计正、负基线；不再把负柱画在正柱范围内。
3. 图表按实际 canvas 渲染与导出时的字形警告核验字体回退，不把只检查“装了中文字体”当作逐字验收。覆盖 CJK 扩展区，并为渲染器自动添加的中文“数据来源”选择中文字体。缺字 `failed`，检查异常与其他渲染警告 `needs_review`；两者保留文件、返回 `ok:false`、退出 6，只报告位置、码位与错误类别。检查范围为 glyphs，不冒充完整视觉评分。
4. 对账先用新路径匹配旧记录，再补录剩余路径；每个新目标只认领一次。真实轮询的新增/删除也走同一批次对账，保留原 ID、任务/回合归属、版本与哈希，防止先插入新记录再把旧记录搬来。没有对已存在的历史重复记录做破坏性清理。

边界：显式登记单个文件时，缓存缺失仍同步核对目标文件；本轮解决常规轮询与初始基线的全量同步读取，不能声称主进程从此没有任何同步文件 I/O。目录枚举、SQLite 操作仍在主进程；异步读期间的 SHA-256 更新按 64KiB 分块，不是独立 worker 线程。无法完整扫描的轮询保留上一份快照，不把一次读取失败当成全部文件被删。

## 回归与性能

新增首轮在旧实现上 **13 失败 / 17 通过**。后续修正了测试本身的两点：原生僻字在选对 CJK 扩展字体后确实可显示，缺字反例改用确定没有字形的 U+0378；小数刻度不能假定自动定位器必然选中输入值 1.5，最终改用整数输入 1000，要求实际刻度显示 1,000.0，确保旧版忽略格式时不能误通过；中间遗漏千分位的测试预期也已订正。没有删减正负几何、百分比与缺字失败的后果断言。

最终相关五文件定向 **79/79**；补充真实 SQLite 移动唯一性用例后，该文件 **5/5**，共 **80 个相关用例**。覆盖真实生成 PNG/SVG、实际坐标文本、四段正负柱几何、检查异常后的待复核、缺字退出码与诊断不泄露原文；覆盖缓存复用/期满复核、等长尾部修改与恢复 mtime、符号链接、并发哈希复用、迟到结果、扫描失败、批量变化；覆盖实际 SQLite 上报接线及旧索引移动后的唯一性。

64MiB 合成文件样例：首次异步完整校验约 **64ms**，期间 1ms 心跳运行 **62 次**；随后三轮扫描 **0.20 / 0.14 / 0.50ms**，四轮总共只读取一次完整正文。原先审查中，同一大小的同步完整哈希每次约 35–82ms。该对照只说明本机文件扫描路径，不是整项模型任务的加速比例。

## 真实模型与宿主

`node scripts/verify-execution-p2.mjs --credentials-stdin` 使用发货内核（先核验来源）、产品网关、实际 local-services、实际文件轮询和临时 SQLite。凭据从关闭回显的 stdin 注入，只在测试宿主内存中使用，不进入内核子进程环境或配置。独立临时 HOME/cwd，结束后清理；只在 `test-results/execution-p2/` 保留合成 SVG。

DeepSeek（`deepseek-flash`，`https://api.deepseek.com/`）和 GLM（`glm-5.3-flash`，`https://open.bigmodel.cn/api/paas/v4`）分别读 charts 技能、自己构造两张图的内容 JSON、调用生产渲染器与正式 mark_artifact 上报。不是由测试预先生成正常图的内容 JSON，也不是假上游。首个制图回合逐请求核对实际型号、HTTP 200 与 low 推理强度；移动回合继续显式使用同一模型。

每家两个回合：

- 生成百分比柱图和正负混合堆叠 SVG；从实际 SVG 核对百分比刻度和四段柱形几何，实际工具事件必须出现缺字样例退出 6；两张正常图在宿主索引中具有正确任务归属。
- 模型实际将两图移入 archive；等待真实两秒轮询更新 SQLite，核对只剩两条产物记录、ID/版本/哈希/归属不变。

缺字输入为固定 U+0378 夹具，正常图的数据由模型构造；该验收不能代表任意数据分析与所有制图任务的正确率。首轮验收解析器误把图例色块计入数据柱（8 对 4），修正为只读图例之前的实际数据柱。随后两轮内核回合 failed，但当时脚本未保留具体错误消息，无法追溯根因；原失败日志保留，不能归因于已修复产品问题。补充只含请求形状、退出码和脱敏错误的诊断后继续验证，最终一轮两家均完成两个回合，**4/4 通过，脚本退出 0**：DeepSeek 首回合 15 次请求、约 28.1 秒；GLM 首回合 13 次请求、约 94.3 秒。两个移动回合的真实轮询与 SQLite 唯一性均通过，内核运行中意外退出 0。两家实际 SVG 已转为 PNG 并逐张查看，百分比刻度、正负零线和中文来源可见；没有把此前失败当成通过。
