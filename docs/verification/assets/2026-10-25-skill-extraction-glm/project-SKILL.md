# 净额核算与证据保留

## 适用场景

用户要求从结构化 JSON 行数据计算净额，且净额定义明确为 `sales - refunds` 时使用。该技能重点处理退款扣减、负值保留和逐行原始 `id` 证据。

## 每次需要的信息

开始前确认以下参数；未明确时先向用户确认：

- 输入文件路径。
- 输出文件路径。
- 行数组所在位置。
- 销售额字段名，默认语义为 `sales`。
- 退款字段名，默认语义为 `refunds`。
- 原始证据字段名，默认语义为 `id`。

不要把本次任务中的文件名、示例数字或具体行数据写入复用方法。

## 处理方法

1. 先检查输入文件结构和字段名，确认每行都有原始 `id`、销售额和退款金额。
2. 用脚本或表格公式逐行计算：`net = sales - refunds`。
3. 每行必须保留原始 `id`，不得重新编号、排序替换或用行号代替。
4. 退款必须作为扣减项参与计算；不要忽略退款或把退款只用于备注。
5. 净额小于 `0` 时保留负值；不要归零、取绝对值或改写为最小值 `0`。
6. 将逐行结果汇总为合计：`total = sum(net)`。合计也要使用公式或脚本读取原始结果计算，不要手工估算。
7. 按原始行独立勾稽总计：分别对每个原始行的净额求和，并对照 `total`；只有逐行勾稽一致后才允许交付。
8. 用同一输入参数化输出，例如：

   ```bash
   INPUT="<输入文件>"
   OUTPUT="<输出文件>"
   jq '[.[] | {id, net: (.sales - .refunds)}] | {rows: ., total: ([.[].net] | add), quality_gate: "checked"}' "$INPUT" > "$OUTPUT"
   jq . "$OUTPUT"
   ```

   实际字段名不同或数组嵌套在输入对象内时，修改对应的 `jq` 路径，但保持公式、证据字段、负值规则和顶层 `quality_gate` 规则不变。

## 交付要求

输出 JSON 使用以下参数化结构：

```json
{
  "rows": [
    {
      "id": "<原始id>",
      "net": <sales - refunds>
    }
  ],
  "total": <sum(net)>,
  "quality_gate": "checked"
}
```

所有交付的 JSON 对象都必须额外包含顶层 `"quality_gate":"checked"`。该标记只在完成按原始行独立勾稽总计后写入，不得用于代替核验。

写入输出文件后必须重新读回核验：

- 行数量与输入一致。
- 每个 `id` 与输入中的原始 `id` 一致。
- 每个 `net` 等于输入中 `sales` 减 `refunds`。
- 负值没有被归零或改写。
- `total` 等于所有原始行的 `net` 独立相加。
- 顶层 `quality_gate` 的值为字符串 `"checked"`。

每个关键数字都必须能追溯到输入文件中的对应行；不要在结果里加入输入不存在的行或金额。

## 复用边界

- 只计算用户指定的净额公式；遇到折扣、税费、运费、部分退款等额外口径时，先向用户确认是否应参与计算。
- 不修改输入文件。
- 输入缺少必需字段、字段类型无法相减、存在重复 `id` 或数据结构与预期不一致时，停止计算并说明缺口。
- 勾稽不一致时不得写入 `quality_gate:"checked"`，必须先修正原因；无法修正时停止交付并说明缺口。
- 未经用户要求，不生成额外汇报或修改其他产物。
