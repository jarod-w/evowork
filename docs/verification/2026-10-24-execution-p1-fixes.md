# 四项 P1 执行问题修复与验收

2026-10-24，macOS arm64。范围为第二轮扫描中的 P1：公式误判、托管停止漏取消、错误正文无限等待、非流式正常回复被丢弃。P2 项不在本轮范围内。

## 修复行为

1. `SUMPRODUCT` 按行数与列数比较形状，拒绝等长但方向不同的范围；条件汇总中的 `*` / `?` 只匹配文本，不把数字、布尔与空白格先转成字符串。错误公式退出 2，不产生新文件、不覆盖旧文件；可验证的公式继续保留公式并写缓存。
2. 托管转发监听响应连接提前关闭，以及请求中止。停止会取消到云端网关的 HTTP 请求，继续传递到厂商请求；提前退出时取消并释放正文读取器，正常收尾不因 `close` 误取消。
3. 错误正文与完整 JSON 都有总期限（沿用首片预算，默认 300 秒）、片间空闲期限（默认 120 秒）、客户端取消与字节上限。错误正文上限 64KiB、完整 JSON 上限 8MiB；限制也在实际 HTTP 字节层执行，单行不结束不能绕过。持续滴流不能无限续期。读取失败仍按原 HTTP 状态映射，401/400 保持永久失败，503 保持可重试。
4. 非流式上游请求继续发送 `stream:false`，完整 JSON 进入已有 `chunksFromCompletion` 和同一流式翻译器；文字、思维链、工具调用、用量与结束原因全部沿用同一规则。截断、内容过滤、坏 JSON 与残缺调用不能冒充完成；非流式流内错误也按厂商映射处理。

新增管道与公式用例在旧实现上 **13 失败 / 16 通过**；两条真实 HTTP 托管停止用例（等待响应头、读取正文）在旧实现上 **2/2 失败**，取消信号均未触发。
