# Windows 双模型剩余失败项修复复验

> 2026-11-02，承接 [首轮完整验收](2026-11-01-mimo-deepseek-windows-playwright.md)。本轮按用户要求继续处理失败项；原始失败、修复前诊断和独立复验均保留，不将不同批次结果拼接为全量通过。

## 本轮修复

1. **Chrome 启动环境**：E2E 只改 shell HOME，不改真实 Windows USERPROFILE。后者不能重定向 Known Folders，且导致 Chrome 拒绝调试端口。相同 Chrome/参数的独立对照复现后，原生授权读取/引用/刷新及拒绝零读取均通过。
2. **显式共享技能目录**：集成宿主可传 additionalSkillRoots，经已有原生 skills/extraRoots/set 注册并在重启后重放；不扫描额外正文或增加 renderer 目录注册权限。隔离测试通过此入口声明一次性共享目录，不再声称 USERPROFILE 能改变原生默认发现。宿主 31/31 和真实共享目录界面用例通过。
3. **草稿错误恢复**：schema、任务交接和错误消息明确 draft 是对象，不经 JSON.stringify。仍拒绝字符串、数组；失败不递增修订，同一调用改正后发布一次、重传幂等。宿主 12/12 通过，包含先失败后纠正的回归；首次未选中测试的诊断不算红测。
4. **Windows 策略 hooks 真正接通**：宿主使用系统 PowerShell、UTF-8 管道和随包 Electron 运行 hooks；CMD 和 PowerShell 两种父解释器均真实验证，异常脚本路径不插值到 shell。无执行策略绕过。Windows 绝对路径导入改为 file URL，修复曾被吞掉的 vendor 导入失败；tilde 展开前归一化 Windows home 斜线，恢复凭据目录匹配。通过 hooks/list 公开 RPC 核对五组已启用且可信 hooks，不读取原生数据库或私有历史文件。
5. **搬迁后的自身保护**：宿主绑定实际应用数据目录，经受控环境传给策略；保留默认目录保护，并将配置/历史等规则和现有技能/记忆例外映射到实际位置。PreToolUse 与 PermissionRequest 同步使用该上下文；提权到受保护位置直接拒绝。仅使用不存在的金丝雀路径与自有隔离夹具验证，不枚举原生记忆正文。
6. **PowerShell 删除风险**：Remove-Item 的普通、大小写混排和模块限定写法均显示删除风险，不提供整任务放行。真实复合脚本先追加再删除的用例要求出现审批，拒绝后两个文件精确内容不变；原 POSIX 已知缺口断言仍保留并明确平台范围。
7. **交付与测试同步**：Windows craft 指令明确当前未提供 apply_patch 命令，要求用可用执行工具写入后读取核验；模式发货哈希同步登记。Stop hook 生效后，确定性测试在原断言期限内等公开历史终态，再检查回合数与建议。这些 Stop 同步调整未延长 Playwright 业务断言期限或删除断言；队列 RPC 注入期限的独立修正在第 12 项说明。

8. **Windows 大小写敏感路径保护**：真实窗口红测证明大写 .SSH 曾进入审批而不是硬拒绝，测试未允许执行。硬拒绝前缀按 Windows 路径比较，workspace 与技能/记忆写入例外仍保持原来的严格比较，避免扩大写权限；POSIX 规则不变。定向单元和 v7 原生界面拦截通过。
9. **运行中公开历史**：只依据已收到的原生 turnStarted 活动回合，避免读取 notLoaded 历史时误 resume 正在执行的线程；同 ID 的历史 interrupted 占位及缺页不会把活动回合显示成结束。完成、失败、断线清除活动状态，不从冷启动的旧投影复活回合。适配器 123/123 通过，新增四项回归。
10. **退出清理**：窗口 closed 或 before-quit 后停止向该窗口发送宿主事件。两项回归先失败后通过；这修复日志中已确认的 Object has been destroyed 清理异常，不把它说成早退窗口的根因。
11. **严格的真实测试驱动**：内置供应商按设计隐藏可编辑 endpoint，但逐次实际请求的型号和端点检查不变；浏览器接受 evowork 合法别名并仍精确检查厂商请求；多代理答案合并同一回合已交付正文，不能用上一回合、工具输出或推理充数；强退以全部自有 PID 已退出为判据，保留原始 taskkill 状态。安装指引只单次批准测试自己上传正文的精确 Get-Content 只读命令，未知命令直接失败，不能自动安装。
12. **队列测试的故障类型**：Stop hook 让原回合结束约需 2.4 秒，原结束竞态使用的 1500ms 人工 RPC 期限会提前进入未知投递分支。三项结束竞态恢复使用产品默认 15000ms RPC 期限；专门的超时/丢回执用例继续使用 1500ms。Playwright 原有 20000ms 断言期限及单次接受、反馈、降级、文件断言均保留。三项独立复验通过；延迟通知实验被发送前的公开状态核对消解，实验失败另行保留。

## 证据与判定约束

证据位于 dist/playwright-repair2/ 以及 dist/playwright-dual/ 下的新 repair2-* 批次，全部零 Playwright 重试、单窗口 worker。不同构建与源码指纹分别记录。新增真实浏览器用例通过本机 HTTP 服务生成未出现在提示词中的随机口令，要求真实 Chrome 读取、来源授权前零请求、禁止 exec 联网、持久引用与厂商型号/端点逐次匹配；它验证实际模型工具链，不代表公开互联网研究质量。

## 后续 UTF-8 与清理调整

公开任务历史显示 PowerShell 默认读取随包中文 SKILL.md 得到乱码。相同发货脚本的独立对照 windows-utf8-read-probe.json：默认 ANSI 936 不匹配原 UTF-8，显式 -Encoding UTF8 精确匹配。拟补充 craft 的明确读取和无 BOM 写入指令及发货哈希；不改系统编码、不将受保护文件解码后注入上下文。附件读取驱动只增加绑定正文的有限显式 UTF-8 写法，附加命令仍拒绝。

Playwright 明确提供 artifactsDir 并允许保留调用者自己的结果目录。后续将每项产物放在该项结果目录，减少驱动自动删除私有临时目录的影响并保留证据；关闭自有进程、网关回收和意外内核退出断言保留。官方存在[Windows 临时目录清理挂起的报告](https://github.com/microsoft/playwright/issues/42109)，但本机 Temp 并非该报告的 null DACL，不能直接认作同一根因；两项旧 teardown 失败仍须保留。
