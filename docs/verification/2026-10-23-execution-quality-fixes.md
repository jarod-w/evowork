# 执行效果修复：响应终态、公式、字体缓存、推理强度与成品检查

2026-10-23，macOS arm64。修复范围是用户选定的五项，不包含新增模型质量评分体系。

## 实现与边界

1. 网关只有在明确的 `stop` / `tool_calls` 结束原因和完整 JSON 对象参数下提交工具调用并宣布完成。EOF / `[DONE]` 不能代替结束原因；输出达到长度限制、内容过滤、未知结束原因和残缺参数明确失败，已经流出的文字仍可保留。缺失结束原因按断流交给内核既有重试，不增加独立重试层；有正常结束原因时可省略 `[DONE]`。
2. xlsx 写出前在本机核验公式。受限解析器不使用 `eval`、不执行宏与外部链接、不出网；支持算术、比较、跨表范围、IF / IFERROR、常见汇总与条件汇总、ROUND 等。错误公式退出 2，原文件与新输出均不被坏结果覆盖。受支持的结果写入计算缓存，原公式保留，并设置自动重算。未知函数、整列/数组/外部引用、预算上限等标待复核，保留文件、退出 6，不冒充完整 Excel 引擎；业务口径仍需独立核对。
3. 办公骨架与直接调用的版式检查均在导入 Matplotlib 前配置缓存。显式配置确实可写时保留，否则使用用户专属临时缓存（0700），跨 Python 命令复用。共享缓存拒绝符号链接和其他用户所有的目录；不写项目目录，第一次仍需生成字体索引。
4. 网关按确切协议类型和模型名传递 Chat 顶层 `reasoning_effort`。三家 P0 的 low / high / max 均保留；medium 映射为 high，别名规则见总纲 D2。表外模型不冒传，模型菜单通知采用厂商默认强度；不能把“支持显示思维链”当作“支持调强度”。参数依据为官方文档，本轮没有调用真实厂商模型。
5. docx / pptx / PDF 与 xlsx 的生成结果带 `quality.status` 及检查范围。确定的版式问题为 failed；估算溢出和检查未完成为 needs_review；两者均 `ok:false`、退出 6，保留产物、要求修正或复核。PDF 沿用转换前 docx 的状态。新增真实多行样例还发现软换行在原估算中漏计：现按 `paragraph.text` 和显式换行计行，避免内容已经溢出却被报通过。
