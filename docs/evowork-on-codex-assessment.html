03

四个硬缺口

这些不是"改造一下"，是从零开始。工作量与风险都集中在这里。

整个前端 自建

仓库里只有 TUI。桌面 App 和 VS Code 扩展是闭源的，codex app 只负责去下载安装器。三栏布局、产物面板、变更视图、浏览器预览，全部要自己写。

好消息：app-server 的 JSON-RPC 协议文档有 2800 行，且有官方 TS / Python SDK。

定时自动化 自建

全仓库 grep 不到任何 cron 或 scheduler。定时执行、有效期、ACTIVE/PAUSED、执行历史都要自建——本来也不该进内核，因为它牵涉多租户、幂等、重试与告警。

好消息：codex exec 非交互模式成熟，外部调度器套上去即可。

办公产物技能 自建

内核里有产物识别逻辑，认 presentations / documents / spreadsheets / pdf 四个插件，但技能本体从 OpenAI 私有市场 openai-primary-runtime 下载。机制开放，内容要自己写。

上报约定已固定：--operation-kind · --expected-output-count · --output-format。

文档解析入口 自建

UserInput 只支持 Text / Image / Audio。清单里的 PDF / Word / Excel / CSV / ZIP 上传，需要本机解析管道先解析成 Markdown + 附图，再以文本与图片形式注入回合。Q3 硬约束 + Q1=A 后没有云端兜底：解析运行时随包分发。

这条链路同时是"文件处理默认在本地完成"这条隐私承诺的落地点。

最容易被低估的一项
wire_api = "chat" 已被上游移除，codex 只说 OpenAI Responses API，内置 provider 仅 OpenAI / Amazon Bedrock / Ollama / LMStudio。接任何国内模型或 Anthropic，都必须自建一层协议网关，且要完整实现流式语义、工具调用、reasoning 段与 prompt cache 行为。这是本方案单项风险最高的工作量——除非主力模型本就是 OpenAI 或 Bedrock，那么它归零。

07

16 个问题的决策记录

2026-09-03 产品评审全部决策完毕，含三个阻塞项与两个由 Q1=A 派生的问题。没有开放项，唯一未答的是"是否有自建推理服务"，按"无"处理。

Q1
阻塞部署形态？

A 纯本地桌面应用 · B 本地 agent + 云端服务 · C 纯云端容器执行。这决定沙箱、文件访问、隐私承诺与调度器的位置。C 与"文件处理在本地完成"直接冲突。

已决策 · A 纯本地桌面应用执行、沙箱、解析、调度、产物索引全部在本机；云端只做账号 · 私有源索引 · 模型网关 · 分享托管。代价是调度可靠性与分发体积，见 D9 / R9 / R10 / M9。
Q2
阻塞主力模型是哪家？是否必须支持国内模型？

codex 只说 Responses API。是否必须支持通义 / 豆包 / DeepSeek / Kimi？是否有自建推理服务？

已决策 · 必须支持国内模型网关是全量协议适配层而非薄转发，M1 由 6 上调到 8 人周；P0 名单见 Q16：DeepSeek · Kimi · GLM-5.3-flash。
Q3
阻塞"原始数据不上传云端"是硬约束还是宣传口径？

若为硬约束，则文档解析必须本地执行（需随包分发 Python/Node 运行时，安装包增大 100–300MB）、不能用云端 OCR 理解扫描件、产物分享需显式二次授权。

已决策 · 硬约束解析必须本地执行、不得用云端 OCR、离开本机的动作逐次显式授权。与 Q1=A 同向，无内部张力。
Q4
重要视频 / 3D 生成本期是否 P0？

codex 只有图片生成（走当前 model provider，可直接用）。视频与 3D 各需新写 extension + 对接第三方 API，每项约 3 人周。

已决策 · 本期只做图片直接复用 ext/image-generation，增量成本≈0；视频与 3D 放 v2。
Q5
重要技能市场是集中托管还是仅私有源？

codex 支持 npm / git / 本地目录三种来源。集中托管需自建 registry + 审核流 + 评分，约 6–8 人周。

已决策 · v1 只做官方内置技能 + 企业私有源不建公开 registry、不做审核评分，M7 由 8 降到 5 人周。
Q6
重要是否必须支持 Windows？安全等级要求？

windows-sandbox-rs 相对新，隔离强度弱于 Linux landlock 与 macOS Seatbelt。

已决策 · 支持 Windows，暂用上游 windows-sandbox-rs不自研沙箱；隔离强度在 M4 单独评估，不足则禁用 danger-full-access 并以审批为主。
Q7
重要与上游的长期关系：跟随 rebase 还是版本冻结？

跟随可持续获得上游演进（guardian、goal、多 agent 演进很快），但需常设约 0.5 人力；冻结短期省事，一年后等于自己维护一个分叉。

已决策 · 跟随上游季度 rebase，补丁硬上限 5 个文件 / 500 行，常设 0.5 人力（不计入 53 人周）。
Q8
重要定时任务的并发与失败语义？

上次未跑完又到点：跳过 / 排队 / 并行？失败是否重试、几次、间隔多久？连续失败是否自动暂停并告警？

已决策 · SKIP + 不自动重试 + 连败 3 次自动 PAUSE 并通知scheduler 数据模型据此定型。
Q9
重要国内生态集成的 P0 名单？

清单提到腾讯文档 / ima 知识库 / 乐享 / 企业网盘。每家 OAuth + API 约 2–5 人日。

已决策 · 本期不做飞书 / 企微 / 钉钉 / 腾讯文档 / ima / 乐享 / 企业网盘全部推 v2，只保留浏览器 MCP，M6 由 8 降到 2 人周。MCP 协议能力本身仍完整，用户可自接第三方 server。
Q10
重要产物分享链接的托管形态？

"生成公开链接"需要服务端托管产物内容，与 Q3 的隐私承诺存在张力。A 显式授权后上传 · B 仅内网链接 · C 导出文件自行分发。

已决策 · A 显式授权后上传默认关闭、逐次授权、链接带有效期。
Q11
重要并发与成本上限？

单用户可并行多少任务？是否需要单任务 token 硬预算（ThreadGoal 已有 budget 字段）？超预算是暂停、降级还是失败？

已决策 · 单用户 3 并行 + 单任务硬预算 + 超预算暂停询问并行数再按本机 CPU / 内存动态下调（Q1=A 后机器就是资源上限）。
Q12
可选清单第 15 章的"下一代"方向本期是否落地？

codex 里恰好都有雏形：声明式目标与预算（ext/goal）、审计可复现（rollout-trace）、Agent 身份（agent-identity）、对抗式验证（guardian-v2 + review/start）。落地成本远低于从零做。

已决策 · 只落审计留痕与单任务预算其余（agent 密码学身份、对抗式验证、持续 reconcile）保留接口不实现。
Q13
可选是否对外保留 CLI 形态？

codex exec 与 TUI 已存在，几乎零成本。保留对开发者生态与自动化集成有价值，但会暴露技术来源。

已决策 · 保留 CLI以「EvoWork CLI」独立品牌对外，随桌面包分发。
Q14
新增模型网关的托管形态？

Q1=A 把执行面留在本机，但模型调用天然要出网。网关放云端统一托管、企业私有部署，还是桌面内置？

已决策 · 云端托管为主 + 企业私有部署包网关不落盘 prompt 与响应体，只记 token 计数、时延与错误码。要同时管住三条会泄露正文的路径：应用日志、APM trace 的 span attribute、错误上报的异常堆栈。私有部署下密钥由客户自持，EvoWork 云不接触 prompt。
Q15
新增同账号多设备时，定时任务归属哪台设备？

Q1=A 下触发在本机，多设备会重复执行。

已决策 · 绑定创建它的设备只有该设备触发，其他设备只读展示并提供「迁移到本机」；离线超 7 天提示迁移。迁移要重置 misfire 基准，否则新设备一上线就补出一堆历史触发。
Q16
