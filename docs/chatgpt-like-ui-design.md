## 1. 文档目的

本方案把 EvoWork 已有功能重组为一种接近 ChatGPT 的使用体验：用户打开应用后先看到对话，输入一句话即可开始；历史任务与项目从左侧进入；模型、附件、技能和执行模式围绕输入框按需展开；产物、文件、变更和浏览器在需要时以右侧工作区出现。

这里的“类 ChatGPT”指交互心智与信息层级相似，不是复制 ChatGPT 的品牌、文案或像素：

- 对话是默认入口和视觉中心；
- 左侧栏负责新建、搜索、项目与历史；
- 输入框固定在内容底部，工具按需展开；
- 运行过程就地呈现，低价值技术细节默认折叠；
- 文档、文件、代码或结果需要持续操作时，打开并排工作区；
- 高级管理能力离开主对话路径，进入独立页面或设置。

本方案不改变 EvoWork 的执行内核、数据边界、权限模型和本地优先原则。

## 2. 设计依据

### 2.1 EvoWork 当前能力边界

本方案仅为仓库当前已有能力安排界面位置，并区分“已经接通”与“已有组件但尚未接线”。

| 能力 | 当前状态 | 新 UI 中的位置 |
| --- | --- | --- |
| 新建任务、连续对话、流式回复 | 已接通 | 首页与任务页的中心对话区 |
| 历史任务、搜索、筛选、分组、置顶 | 部分接通 | 左侧栏；未接通的行操作不得伪装成可用 |
| 项目与本地工作空间 | 已接通 | 左侧“项目”分组及项目详情页 |
| 模型选择、Craft / Plan / Ask、权限档位 | 已接通 | 输入框工具条；常用项直显，其余收入菜单 |
| 19 类执行事件、推理、计划、命令、文件变更 | 已有渲染器 | 助手消息内的“过程块” |
| 四类审批 | 已接通 | 对话时间线内联卡片，并在顶部提示待处理数 |
| 产物、文件、变更、浏览器 | 组件与服务部分具备，任务结果区尚未接线 | 右侧工作区；只在有内容或用户主动打开时出现 |
| 资料库 | 已有页面，部分能力为 UI 壳 | 左侧一级入口；仅显示真实数据和可用动作 |
| 自动化列表与历史 | 已有页面；创建、立即运行等未接通 | 左侧一级入口；创建入口在接通前不展示 |
| 用量与审计 | 已接通 | 用户菜单中的独立页面 |
| 模型、账号、数据、安全、关于 | 已有设置页 | 左下用户菜单 → 设置 |
| 插件目录（技能、连接器、专家） | 已接通 | 左侧一级入口“插件”；页内按能力类型管理 |
| 技能安装与卸载 | 已接通 | 插件页“技能”分类；支持本地目录、Git 与静态风险审计 |
| 连接器添加、信任与移除 | 已接通 | 插件页“连接器”分类；当前含官方 browser MCP 与自定义 MCP |
| 专家创建、使用与删除 | 已接通 | 插件页“专家”分类；标记为 EvoWork 扩展类型 |
| “发现应用”抽屉 | 已接通，但当前把技能或可信连接器逐项映射为应用 | 改名“使用插件”，作为 Composer 的快捷选择器 |
| 通知中心、设备中心、全局命令面板、语音 | 尚未完成 | 不在本次设计中承诺 |

### 2.2 ChatGPT 交互模式参考

截至本文日期，ChatGPT 官方资料体现了以下稳定模式：项目从侧边栏进入，项目内聚合聊天、文件与说明；文件和工具从输入区进入；较复杂的写作或代码工作可在与聊天并排的 Canvas 中继续处理。EvoWork 借用这些模式，但把“项目”映射为本地工作空间，把 Canvas 映射为本地结果工作区。

参考：

- [Projects in ChatGPT](https://help.openai.com/en/articles/10169521-projects-in-chatgpt)
- [File storage and Library in ChatGPT](https://help.openai.com/en/articles/20001052-library-for-chatgpt)
- [Introducing canvas](https://openai.com/index/introducing-canvas/)

### 2.3 Codex 插件模型与本方案结论

OpenAI 官方插件架构把“插件”定义为用户发现、安装、分享和发布的上层包。插件可以只包含技能、只包含 MCP Server，也可以同时包含二者，还可以带生命周期 hooks 与可选 UI。技能负责可复用工作流的指令与资源，MCP Server 负责实时数据、受控动作和外部系统连接。

参考：

- [Plugin architecture](https://developers.openai.com/plugins/concepts/plugins)
- [Skills](https://developers.openai.com/plugins/concepts/skills)
- [MCP server](https://developers.openai.com/plugins/concepts/mcp-server)

因此，本方案采用以下命名决定：

| 层级 | EvoWork 对外名称 | 含义 |
| --- | --- | --- |
| 一级产品入口 | **插件** | 与 Codex 保持相同的发现、安装、管理心智 |
| 插件能力分类 | 技能 | 指令、模板、脚本与可复用工作流 |
| 插件能力分类 | 连接器 | MCP Server 提供的外部数据与动作 |
| EvoWork 扩展分类 | 专家 | `agent-roles` 角色配置；不是 Codex 标准插件组件，界面必须标明“EvoWork 专家” |
| 内部能力 | Hooks | 随插件或产品分发的策略与生命周期扩展，普通用户不需要单独管理 |

结论是“产品概念保持一致、能力分类继续保留”，而不是把“插件 / 技能 / 连接器”做成三个同级入口。

### 2.4 已确认的视觉相似度（C1）

**决定：采纳建议。** “类 ChatGPT”借鉴其信息结构、交互层级与视觉密度；EvoWork 保留自己的品牌色、字体、暖灰 token 和安全语义，不做像素级复刻，也不复制 ChatGPT 的品牌资产与文案。

### 2.5 已确认的交互策略（C3–C7）

| 编号 | 已确认决定 | 在本方案中的含义 |
| --- | --- | --- |
| C3 | 采用与 ChatGPT 一样的项目策略 | 侧栏把“项目”和“最近任务”作为独立分区；点击项目进入项目视图，不在侧栏内展开项目任务树。项目内再集中显示任务、文件、说明和自动化。 |
| C4 | 采用与 ChatGPT 一样的并排工作策略 | 结果工作区按内容与用户意图打开：用户主动打开，或系统明确判断产物适合持续预览、比较、编辑时打开；不机械地在第一个产物出现时自动展开。 |
| C5 | 采纳建议 | 未接通入口在主路径隐藏；只有当位置本身具有发现或管理价值时，才在设置或管理页保留带原因的禁用态。 |
| C6 | 采用与 ChatGPT 一样的首页策略 | 空白首页保持克制，只显示问候、Composer 和少量上下文建议；不展示常驻案例墙或运营内容。建议在用户输入后消失。 |
| C7 | 暂不做暗色主题 | 暗色主题不属于本方案范围，相关需求、阶段与验收项已删除。当前只设计和验收浅色主题。 |

C3 参考 ChatGPT 当前“置顶 / 项目 / 聊天”的分区组织方式：[项目和聊天](https://learn.chatgpt.com/zh-Hans/docs/projects)。C4、C6 采用同样的渐进披露原则，但具体触发条件以本节和 §8、§11 为准，避免把“与 ChatGPT 一样”变成不可验收的描述。

### 2.6 2026-09-11 代码重新评估

本次按提交 `180a7c1` 重新检查。相较 v0.1，以下事实发生变化：

因此，v0.1 中“管理页尚未完成、接通前隐藏”的判断已删除。新的设计重点是统一产品概念和入口，而不是等待功能实现。

## 3. 目标与非目标

### 3.1 目标

1. 新用户不学习导航即可发出第一条需求。
2. 老用户能像管理聊天记录一样查找、继续和组织任务。
3. 复杂的模型、权限、场景和工作空间选择不压过输入本身。
4. 运行过程可理解、可打断、可审批，但不把对话变成日志控制台。
5. 产物和变更具有持续工作空间，不与对话正文争宽度。
6. 已实现与未实现能力在界面上可明确区分，杜绝“按钮能点但没有效果”。
7. 保持本地优先、显式出网授权、敏感路径保护和审计规则不变。

### 3.2 非目标

- 不改变内核协议、任务模型、项目模型或本地数据库结构。
- 不新增移动端形态；本期仍是桌面端设计。
- 不照搬 ChatGPT 的商标、图标、颜色、动效或营销入口。
- 不因 UI 相似而引入 ChatGPT 云端依赖、账号体系或连接器。
- 不在本次改版中补齐所有尚未实现的业务功能。

## 4. 设计原则

### 4.1 对话优先

启动后默认进入“新任务”。没有单独的欢迎仪表盘，不要求用户先选择场景、专家或模板。场景建议可以出现，但只作为快捷提示，不成为开始任务的门槛。

### 4.2 渐进披露

首屏只保留一句主提示、输入框和少量建议。模型、模式、权限、工作空间、技能、附件等信息按使用频率分三层：

- 常显：当前模型、添加内容、发送；
- 次级：工作模式、工作空间；
- 高级：权限、预算、记忆、连接器等，进入“更多选项”。

### 4.3 任务是对话，项目是上下文

“任务”对应一次可持续对话，“项目”对应一组共享本地目录和说明的任务。用户可以在项目内新建任务，也可以把已有任务移动到项目；界面不再让“空间”“项目”“工作目录”作为三个并列概念出现。

对用户统一使用以下词汇：

| 产品概念 | 对外名称 | 禁止混用 |
| --- | --- | --- |
| Thread | 任务 | 会话、线程 |
| Project + cwd | 项目 | 空间、工作空间（设置说明中可解释一次） |
| Artifact | 产物 | 输出件、结果文件 |
| Collaboration mode | 工作模式 | Agent 模式 |

### 4.4 结果按需并排

默认只有侧栏与对话。出现产物、文件变更、网页预览，或用户主动点击“打开结果”时，右侧工作区滑入。关闭工作区不会终止任务，也不会丢失选中项。

### 4.5 运行透明但不过载

用户最关心“正在做什么、是否需要我、最后得到什么”。命令全文、工具 JSON、完整输出等开发细节默认折叠；审批、错误、计划变化和产物必须显式展示。

### 4.6 不可用即不可操作

未接线功能应隐藏，或以明确的禁用态说明原因。不得保留点击后只写 `unimplemented` 日志的菜单项。

## 5. 总体信息架构

### 5.1 一级结构

```text
EvoWork
├── 新任务                     默认入口
├── 搜索                       搜索任务标题与对话内容
├── 项目                       置顶/最近项目 + 全部项目
├── 最近任务                   按时间显示，可置顶
├── 插件                       发现、安装、使用与管理扩展能力
├── 自动化                     独立管理页
├── 资料库                     独立管理页
└── 用户菜单
    ├── 模型与账号
    ├── 用量与预算
    ├── 数据管理
    ├── 安全与权限
    ├── 用量与审计
    └── 关于
```

“插件”保留为一级入口，与 Codex 的上层概念一致。插件页内部继续使用“技能 / 连接器 / 专家”分类，以便用户判断能力来源和安全边界：

- 技能：告诉智能体怎么完成一类工作；
- 连接器：允许智能体访问哪些外部数据和动作；
- 专家：EvoWork 的角色配置扩展，回答由谁来做。

当前“发现应用”与“技能·连接器”是两个容易混淆的入口：前者面向使用，后者面向管理。新 UI 统一为一个“插件”产品概念——左侧“插件”进入完整目录与管理页，Composer 的“使用插件”打开轻量选择器，不再使用“应用”作为第三个同义词。

### 5.2 页面清单

| 页面 | 默认骨架 | 主要任务 |
| --- | --- | --- |
| 新任务 | 侧栏 + 主区 | 发起任务 |

| 搜索 | 侧栏 + 搜索结果 | 查找并继续旧任务 |
| 插件 | 侧栏 + 目录页 | 浏览、安装、信任、使用和管理插件能力 |
| 自动化 | 侧栏 + 管理页 | 查看规则与运行历史 |
| 资料库 | 侧栏 + 管理页 | 查找本地资料和产物 |

### 5.3 导航状态

- 任务被选中时，左侧对应任务行高亮。
- 项目详情被选中时，对应项目高亮；项目内任务在项目视图中显示，不展开到侧栏。
- 设置、审计等二级页打开时，用户菜单保持激活态，不误高亮“新任务”。
- 返回行为遵循最近访问栈；“新任务”永远新建空白草稿，不产生空 Thread。

布局规则：

- 左侧栏默认 260，可折叠；折叠后主区左上提供恢复按钮。
- 对话内容列最大宽度 800；消息内容宽度优先于左右留白。

### 6.3 顶栏

任务页顶栏只承担任务级上下文与动作：

- 左侧：折叠侧栏、任务标题；
- 中间或标题旁：运行状态，仅在运行、等待审批、失败时出现；
- 右侧：分享、打开结果、任务菜单；
- 模型选择放在空白任务页上方或 Composer 内，不在运行中的顶栏重复展示。

任务菜单包含重命名、移动到项目、分叉、归档、删除等动作。只展示已经接通并可撤销或有确认流程的动作。

## 7. 左侧栏设计

### 7.1 顶部固定区

顺序为：品牌/折叠按钮 → “新任务”主按钮 → “搜索任务”。新任务是侧栏中视觉权重最高的动作，但使用中性样式，避免与 Composer 的发送按钮争夺注意力。

### 7.2 项目区

- 显示最近使用的 3–5 个项目，可折叠；底部“查看全部项目”。
- 项目与最近任务是两个独立分区；项目行不展开任务树。
- 点击项目进入项目视图，并在项目页提供“在此项目中新建任务”。
- 项目菜单保留当前已接通的重命名、打开文件夹、移除项目等动作。
- 项目根目录不可用时，在项目行显示警告，不等用户进入任务后才报错。

### 7.3 最近任务区

- 置顶任务优先，随后按最后活动时间降序。
- 默认只展示最近一段，滚动后加载更多。
- 任务行显示标题；仅在运行、待审批或失败时显示状态图标，空闲和已完成不额外加 Badge。
- 时间只在悬停或上下文需要时出现，悬停时切换为更多菜单，不引起行宽跳动。
- 搜索与复杂筛选从搜索页进入，不在窄侧栏长期占用三枚图标。

### 7.4 底部固定区

底部只保留自动化、资料库和用户菜单。用量、设置、审计、账号、数据管理全部收入用户菜单。不设置运营位。

## 8. 新任务首页

### 8.1 空白态

首页以一个更轻的 ChatGPT 式空白态替代当前信息密度较高的 Hero：

```text
                  今天想完成什么？

        [生成一份汇报] [分析表格] [整理文档] [自由提问]

        ┌────────────────────────────────────────┐
        │ 描述你的目标，或添加文件开始…           │
        │                                        │
        │ [+ 添加]  Craft ▾  选择项目 ▾      [↑] │
        └────────────────────────────────────────┘
        AI 可能犯错；重要结果请在交付前确认。
```

- 问候语使用产品语气，不将品牌名作为大标题重复展示。
- 场景入口从分段控件改为少量上下文建议；建议数量随窗口与用户上下文变化，最多 4 个。
- 点击建议只填充输入框，不自动发送。
- 用户开始输入或任务开始后，建议立即消失，不占用对话空间。
- 不展示常驻案例墙、轮播推荐或运营内容；案例库若未来实现，从独立入口进入，不回填首页。
- 模型不可用、服务断连等阻断问题显示在 Composer 上方，且给出下一步。

### 8.2 首次发送

1. 用户输入或添加文件。
2. 系统在本地创建任务，并用第一条需求生成确定性标题。
3. 主区原地过渡为任务对话，不进行整页闪白。
4. 用户消息立即显示；任务创建或发送失败时原文保留在输入框中。
5. 任务行加入左侧“最近任务”，并显示运行状态。

## 9. Composer 输入区

### 9.1 结构

Composer 是首页和任务页共用的唯一输入组件，固定在主内容区底部。

```text
┌────────────────────────────────────────────────────────────┐
│ [附件 chips / @ 引用 chips / 排队消息]                     │
│ 输入多行需求…                                              │
│                                                            │
│ [+]  Craft ▾  项目：季度汇报 ▾         模型名 ▾   [发送]  │
└────────────────────────────────────────────────────────────┘
```

### 9.2 “添加”菜单

左下角 `+` 汇总低频入口：

- 添加本地文件；
- 从资料库选择；
- 引用项目文件；
- 使用插件：打开轻量选择器，列出可直接使用的已安装技能、可信连接器和专家；
- 管理插件：跳转完整插件页。

菜单项必须显示数据去向：本地文件默认本地解析；连接器或插件的任何上传、访问外部服务动作，在执行前单独授权。

### 9.3 模式与权限

- 工作模式常显：Craft、Plan、Ask。
- 权限档位放入工作模式菜单的二级区域，并用一句结果导向文案说明。
- Ask 模式自动显示“只读”，退出 Ask 时恢复用户之前的权限选择。
- 完全访问必须使用危险色和二次确认，不把它包装成“更强模式”。

### 9.4 运行中行为

- 发送按钮变为停止按钮。
- 用户继续发送时默认进入队列；Composer 上方显示“已排队 2 条”。
- “立即插话”放在队列面板中，不做常驻开关，并说明会改变当前执行方向。
- 停止后保留未发送草稿并自动聚焦输入框。

### 9.5 快捷键

| 操作 | 快捷键 |
| --- | --- |
| 发送 | `Enter` |
| 换行 | `Shift + Enter` |
| 新任务 | `⌘/Ctrl + Shift + O` |
| 搜索任务 | `⌘/Ctrl + K`（全局命令面板落地前可先用 `⌘/Ctrl + F` 打开搜索页） |
| 停止运行 | `Esc` |
| 切换侧栏 | `⌘/Ctrl + \` |
| 切换结果工作区 | `⌘/Ctrl + I` |

## 10. 对话与执行过程

### 10.1 消息层级

- 用户消息：右对齐浅色气泡，最大宽度 80%。
- 助手回答：左对齐、无大气泡，使用完整 Markdown 渲染。
- 消息操作：悬停显示复制、重试、分叉等已接通动作。
- 时间戳默认隐藏，在消息菜单或详情中查看。

### 10.2 过程块

19 类 Thread Item 不直接平铺为 19 种视觉样式，而归并成 5 个用户可理解的组：

| 组 | 包含内容 | 默认状态 |
| --- | --- | --- |
| 思考与计划 | Reasoning、Plan、ContextCompaction | 计划展开，推理折叠 |
| 操作 | CommandExecution、McpToolCall、DynamicToolCall、WebSearch | 折叠为一行摘要 |
| 变更 | FileChange、ReviewMode | 展开摘要，完整 diff 去右侧工作区 |
| 协作 | SubAgentActivity、CollabAgentToolCall、HookPrompt | 折叠；待处理状态展开 |
| 产物 | ImageGeneration、图片、文档与其他产物 | 展开预览卡 |

每个过程块至少表达：当前动作、状态、耗时或进度、是否需要用户操作。完整命令输出和原始 JSON 仅在展开后显示。

### 10.3 运行状态

顶部不常驻“空闲”状态。仅显示以下强状态：

- 正在工作：轻量脉冲点 + 当前阶段；
- 等待确认：警告色 + 待审批数量；
- 已排队：Composer 上方显示；
- 失败：错误摘要 + 重试或打开设置；
- 已停止：时间线分隔符。

### 10.4 审批

审批卡继续内联在时间线上，不使用阻断整页的模态。页面顶部同时出现吸顶提示“需要你确认 1 项”，点击滚动到审批卡。

卡片先写影响，再写技术细节：

1. 将发生什么；
2. 影响哪些文件、目录或网络域；
3. 为什么需要；
4. 允许一次、允许本次任务、拒绝；
5. 完整命令或 diff 放在“查看详情”。

## 11. 右侧结果工作区

### 11.1 打开规则

- 用户点击产物、文件、diff 或网页预览时，打开对应 Tab。
- 系统只有在产物需要持续预览、比较或交互，且当前任务意图明确时才主动打开工作区；普通附件、单个下载文件或后台文件变更不触发。
- 文件变更默认只在对话中出现摘要和“查看变更”。
- 用户手动关闭后，本任务内不再自动打开，除非用户再次主动打开。
- 切换任务时记住各任务最后选中的 Tab；应用重启后可不恢复面板开关状态。

### 11.2 Tab

| Tab | 内容 | 主要动作 |
| --- | --- | --- |
| 产物 | 文档、表格、幻灯片、图片、图表 | 打开、在文件夹显示、另存、查看版本、分享 |
| 文件 | 项目文件树与只读预览 | 打开、在文件夹显示、引用到对话 |
| 变更 | 本回合 / 本任务 diff | 查看完整变更、撤销、回滚 |
| 浏览器 | 本地网页和 HTML 预览 | 刷新、前进后退、系统浏览器打开 |

右侧工作区的直接编辑能力不在本期范围；文件修改仍通过对话或用户的本地编辑器完成。撤销与回滚必须继续使用不同文案，明确是否修改磁盘文件。

### 11.3 产物卡与分享

- 对话中显示轻量产物卡，右侧工作区显示完整预览。
- 分享不是默认主按钮；只有选中具体产物后才出现。
- 每次分享只授权一个产物，勾选框不预选，不记忆授权。
- 分享服务尚未接通时不显示分享按钮，不能用假成功或本机链接替代上传链接。

## 12. 项目

项目详情采用 ChatGPT Project 的“上下文容器”心智，但保留本地目录事实：

```text
项目：季度汇报                                      [在项目中新建任务]
本地目录：~/Documents/Q3-report                      [打开文件夹] [⋯]

[任务] [文件] [项目说明] [自动化]
```

- “任务”是默认 Tab，显示该项目最近任务。
- “文件”复用结果工作区文件树，不做第二套文件组件。
- “项目说明”对应现有 AGENTS memo，保存时明确影响该项目后续任务。
- “自动化”只展示绑定到本项目的规则；创建功能接通前不显示创建按钮。
- 项目删除/移除只删除 EvoWork 中的项目记录，不删除本地目录；文案必须明确。

## 13. 插件、自动化、资料库、审计与设置

这些页面保留独立管理形态，但统一使用同一套侧栏、标题栏、表格、筛选和空态。

### 13.1 插件

插件页使用“插件”作为页面标题和一级导航名称，页内保留能力分类：

```text
插件                                      [搜索] [仅看已安装] [添加 ▾]

[技能] [连接器] [EvoWork 专家]

精选 / 已安装 / 本地与企业来源
```

交互规则：

- “技能 / 连接器 / EvoWork 专家”是同一插件页里的过滤与管理视图，不是三个一级入口；
- “添加”菜单根据当前分类显示“从目录或 Git 导入技能”“添加 MCP 连接器”“新建 EvoWork 专家”；
- 技能卡继续显示来源和 P0/P1/P2 风险；连接器卡继续显示信任与连接状态；
- 官方 browser MCP 作为内置插件能力展示，不伪装成已连接的第三方账号；
- 使用某项能力时回到新任务页并填入默认提示，不自动发送；
- 现有“发现应用”抽屉改名为“使用插件”，从 Composer 的 `+` 菜单打开；左侧栏不再重复放“发现应用”chip；
- 当前数据层以技能或连接器为记录单位，尚未形成真正的 bundle 聚合视图。UI 可以先统一命名，但后续若支持包含多个技能、MCP 与 hooks 的包，必须新增 bundle ID、版本、来源、签名、更新和卸载边界，不能仅靠名称把多条记录拼成一个插件。

### 13.2 自动化

- 页面标题下直接说明“仅在绑定设备在线时运行”。
- 列表优先展示下一次运行、绑定设备、最近结果和启用状态。
- “错过”和“失败”保持不同语义与统计。
- 当前创建、立即运行、迁移功能未接通，在接通前不显示相应按钮。

### 13.3 资料库

- 一级分类简化为“最近、我的资料、本地产物、我分享的”。
- “我的资料”删除代表删除磁盘文件；“本地产物”删除只移除索引，两者使用不同确认文案。
- 全文检索接入 FTS 前，搜索框明确为“搜索文件名”，不宣称搜索正文。
- 分享链路接通前隐藏“我分享的”空 Tab 或标记为预览，不展示不可用撤销动作。

### 13.4 审计

- 默认只显示动作、结果、时间、分类和短哈希。
- 页面与导出均不得出现提示词正文、文件内容或原始路径。
- 过滤器收在标题栏下方，避免在左侧栏增加审计专用控件。

### 13.5 设置

设置从左下用户菜单进入，分区保持：模型与账号、通用、用量与预算、数据管理、安全与权限、关于。保存采用就地反馈；涉及出网、密钥或删除数据时继续使用明确确认。

## 14. 视觉语言

本次沿用既有 token 体系和暖灰基调，调整的是层级与密度，不追随 ChatGPT 的具体色值。

### 14.1 色彩

- 主画布：接近白色；侧栏：轻微暖灰；卡片与 Composer：白色或浅表面色。
- 品牌绿只用于主动作、焦点和成功语义，不大面积铺底。
- 运行、警告、危险继续使用已有语义 token，文字必须使用对应高对比度变体。

### 14.2 排版

- 对话正文从当前 `13/20` 提升到建议 `15/24`，中文长文更接近阅读界面。
- 侧栏与元信息保持 `13/20`。
- 首页主提示建议 `28/36`，弱化当前 36px Hero 的营销感。
- 代码、命令、diff 保持等宽字体。

### 14.3 容器

- 减少首页多层卡片和边框，优先用留白分组。
- Composer 使用 16–20 圆角、细边框和轻阴影；聚焦时只增强边框与 focus ring。
- 助手正文无气泡；工具、审批、产物使用卡片。
- 弹层只用于选择和详情，核心流程不依赖连续模态。

### 14.4 动效

- 侧栏与右侧工作区：180–280ms。
- 新消息块：120ms 淡入与轻微上移。
- 流式文字不做逐字位移动画。
- `prefers-reduced-motion` 下取消非必要动效。

## 15. 响应式与窗口状态

| 窗口宽度 | 布局 |
| --- | --- |
| ≥ 1440 | 左侧栏 + 对话 + 可选右侧工作区 |
| 1180–1439 | 左侧栏 + 对话；结果工作区打开后适度压缩对话 |
| 900–1179 | 左侧栏可折叠；结果工作区覆盖主区 |
| < 900 | 左侧栏为抽屉；独立页单列；提示建议放大窗口 |

高度不足时 Composer 始终可见，对话区独立滚动；审批提示和系统 Banner 不得把 Composer 推出视口。

## 16. 状态、错误与空态

| 场景 | 表现 | 用户下一步 |
| --- | --- | --- |
| 本机服务启动中 | Composer 禁用，短文案“正在启动本机服务…” | 自动恢复 |
| 无可用模型 | Composer 上方错误条 | 打开模型设置 |
| 项目目录失效 | 任务顶栏警告，禁止发送 | 重新选择目录 |
| 执行连接中断 | 顶栏提示重连，不遮住历史 | 等待或重启应用 |
| 任务失败 | 时间线内错误块，保留原始错误摘要 | 重试 / 打开设置 |
| 等待审批 | 顶部吸顶提示 + 内联卡片 | 查看并决定 |
| 无产物 | 不自动打开结果工作区 | 继续对话 |
| 未实现能力 | 隐藏或禁用并说明 | 不制造可点击假入口 |

所有错误遵循三条规则：不丢失用户输入、不用“发生未知错误”覆盖可行动原因、不把本地失败自动降级为未经授权的云端行为。

## 17. 可访问性

- 所有图标按钮提供中文可访问名称和 tooltip。
- 键盘焦点顺序遵循侧栏 → 顶栏 → 对话 → Composer → 结果工作区。
- 聚焦环使用现有不透明 `--focus-ring`，保持至少 3:1 非文本对比度。
- 文字和背景满足 WCAG AA；状态不能只靠颜色表达。
- 流式区域使用克制的 `aria-live`，不逐 token 朗读；完成一个语义块后再播报。
- 弹层支持 `Esc` 关闭并把焦点还给触发按钮。
- 审批、删除、完全访问等关键动作可完全通过键盘完成。

## 20. 验收标准

### 20.1 关键任务

- 用户能从启动页直接新建并发送任务。
- 用户能从左侧找到、搜索、打开和继续历史任务。
- 用户能在输入区选择模型、模式与项目，并能理解权限影响。
- 运行中能停止；等待审批时能定位并完成审批。
- 生成产物后能从对话卡或右侧工作区打开。
- 用户能进入项目、插件、自动化、资料库、审计和设置页面。
- 用户能从插件页管理技能、连接器与专家，并从 Composer 使用已安装能力。
- 不存在“可点击但只记录未实现日志”的控件。

### 20.2 体验指标

| 指标 | 目标 |
| --- | --- |
| 首次任务发起 | 不超过 1 次页面导航 |
| 空白首页主要操作数 | 不超过 5 个可见入口，不含场景建议 |
| 普通任务常驻顶栏动作 | 不超过 4 个 |
| Composer 常驻控件 | 不超过 5 个 |
| 打开最近任务 | 不超过 2 次点击 |
| 从产物卡打开文件 | 不超过 2 次点击 |
| 任何危险动作 | 明确影响范围 + 二次确认 |

### 20.3 工程约束

- 保持 `pnpm run check` 全绿。
- 不直接依赖内核内部实现，继续通过现有适配层和 IPC。
- 样式继续 token-only，不在组件里加入颜色和尺寸字面量。
- 未知 Thread Item 必须有可见兜底。
- Composer 首页与任务页继续共用一个实现。
- 不新增未登记的出网路径。

## 21. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 只做视觉模仿，复杂能力仍然堆在首屏 | 以渐进披露和关键任务指标验收，不按截图相似度验收 |
| 侧栏同时放功能导航、项目和大量历史，变得拥挤 | 项目只显示最近项，历史分页，低频管理入口收入用户菜单 |
| 结果区挤压对话 | 设置最小宽度，窄窗口改覆盖式面板 |
| 执行细节折叠后失去透明度 | 摘要必须包含动作、状态、耗时和是否需要用户 |
| 把每个技能或连接器都叫插件，未来 bundle 出现时层级混乱 | 对外统一“插件”，页内保留能力类型；数据层补齐 bundle 后再提供插件级版本与卸载 |
| “发现应用”“技能·连接器”“插件”三个名称并存 | 左侧与页面统一“插件”，Composer 只使用动作词“使用插件” |
| 已有 UI 壳被误认为现成功能 | 以 `status.md` 和端到端接线为准；未接通即隐藏或禁用 |
| 后续修改再次形成双真源 | Approved 交互先改本文，再同步对应详细设计与 `status.md` |
| ChatGPT UI 持续变化 | 只采用稳定交互模式，不追逐单次视觉更新 |
