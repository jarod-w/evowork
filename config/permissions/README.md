# 权限 profile 的中文文案映射（10 §2.2）

profile **本体**定义在 `config.toml` 的 `[permissions.*]`（内核解析），
这里只放**面向用户的文案** —— 协议返回的 `description` 是英文且面向开发者（F4）。

| id                  | extends               | 面向用户的名字 | 一句话说明（UI 直接显示）              | 用在                   |
| ------------------- | --------------------- | -------------- | -------------------------------------- | ---------------------- |
| `evowork-ask`       | `:read-only`          | 只读           | 只能查看文件，不能修改，也不联网       | Ask 模式（D8）         |
| `evowork-plan`      | `:read-only`          | 只读 + 联网    | 可以查看文件和上网查资料，不能修改文件 | Plan 模式              |
| `evowork-workspace` | `:workspace`          | **默认权限**   | 可以在这个工作空间里读写文件、执行命令 | Craft 模式（默认）     |
| `evowork-full`      | `:danger-full-access` | 完全访问       | 可以读写这台电脑上的任何文件并联网     | 需二次确认，仅当前任务 |

「默认权限」这个名字直接对应截图 1 的「默认权限 ∨」—— 截图给的就是 profile 选择器，
不需要发明新控件（03 §4.5）。

## 三条硬规则（10 §2）

1. **未知 id 不隐藏**：企业自定义的 profile 用协议返回的 `description`，缺失则显示 id 本身。
   隐藏一个存在的档位会让用户以为产品坏了。
2. **`allowed = false` 渲染为禁用并显示原因**（「已被企业策略锁定」），不隐藏 ——
   用户需要知道存在这个档位但自己不能选。
3. **`evowork-full` 也挡不住硬拦截清单**（10 §2.3）：系统目录、`~/.ssh` / `~/.aws` /
   keychain / 浏览器 profile、以及 EvoWork 自身的 `config.toml` / `requirements.toml`。
   用户点「完全访问」是为了让 agent 装依赖、改工作空间外的项目文件，
   不是为了让它读走 SSH 私钥。把这条做成不可绕过，比在审批卡上写警告有效得多。
