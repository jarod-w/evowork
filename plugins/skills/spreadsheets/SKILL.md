# spreadsheets —— 生成表格

## 何时用

用户要**一份能继续改、能继续算的表**时用它：台账、预算、对账、统计汇总。
只是要在对话里看几个数时不要用 —— 直接列出来更快。

## 怎么用

```bash
node container_tools/mark_artifact.mjs \
  --operation-kind create --expected-output-count 1 --output-format xlsx \
  --title "Q3 应收对账" --path "<绝对路径>/Q3应收对账.xlsx"

# 内容 JSON 是中间文件，写进本任务的临时目录，不要写进用户的目录：第一次用
# mktemp -d "${TMPDIR:-/tmp}/evowork.XXXXXX" 建一个、记下它打印的路径，之后的命令都沿用它
python3 container_tools/render.py --content "<临时目录>/content.json" --out "<绝对路径>/Q3应收对账.xlsx"
```

输出格式由 `--out` 的扩展名决定：`.xlsx`（需要办公扩展）或 `.csv`（不需要，属基础包）。

## **最重要的一条：计算列给公式，不给算好的数**

```json
{
    "sheets": [
        {
            "name": "明细",
            "columns": [
                { "header": "产品", "type": "text" },
                { "header": "单价", "type": "currency" },
                { "header": "数量", "type": "integer" },
                { "header": "金额", "type": "currency", "formula": "=B{row}*C{row}" },
                { "header": "占比", "type": "percent", "formula": "=D{row}/SUM($D$2:$D$100)" }
            ],
            "rows": [
                ["A 线", 12.5, 100, null, null],
                ["B 线", 8.0, 200, null, null]
            ],
            "total_row": true,
            "conditional_formats": [{ "column": "金额", "rule": "data-bar" }]
        }
    ]
}
```

- 计算列写 `formula`，`{row}` 会被替换成当前行号；
- 这些列在 `rows` 里对应位置**必须写 `null`** —— 校验器会拦，且这是硬规则；
- `total_row: true` 会追加一行 `SUM` 公式合计（同样不是算好的数）。

**为什么这条不能通融**：用户拿到表之后会改数。单元格里如果是常量，改了单价之后
金额、合计、占比全都纹丝不动 —— 而它看起来完全正常，一路带进汇报才被发现。
你算得对不对不重要，重要的是**这张表在用户手里还能不能继续算**。

## 按分组汇总：条件区域要装着和条件同一种值

跨表按区域 / 部门 / 产品汇总时，`SUMIF(条件区域, 条件, 求和区域)` 的**条件区域**必须是
装着区域名的那一列。明细表里只有「机构代码」、区域写在另一张清单里时，
**先在明细表里加一列「区域」**，再对它写条件：

```json
{
    "header": "存款合计",
    "type": "integer",
    "formula": "=SUMIF(存款!$B$2:$B$19,A{row},存款!$D$2:$D$19)"
}
```

（`存款!B` 是区域列，`存款!D` 是年末余额列。）拿区域名去「机构代码」列里找，
条件永远不成立，每个格子都是 0 —— 而表看起来完全正常。渲染器会拦下这种写法
（`--validate-only` 就能提前发现）。

**你自己用脚本重算一遍原始数据，验证不了单元格里的公式**：两者对得上，只说明你的脚本对。

## 生成后必须核对检查状态

渲染器会在本机计算受支持的公式（算术、比较、IF / IFERROR、SUM / SUMIF(S)、COUNTIF(S)、AVERAGEIF(S)、MIN / MAX、ROUND 等），保留公式并写入计算缓存。断引用、除零、循环依赖等明确错误会退出 2，且不写出新文件；按报错里的表序号和单元格修正。

成功输出的 `quality.status=passed` 只表示列出的 `checks` 已通过，不代表业务口径自动正确。仍需用原始资料独立核对关键汇总值。遇到不支持的函数、外部引用、整列引用、数组表达式或计算预算上限，文件会保留，标准输出里是 `ok:false`、`quality.status=needs_review`，退出码 **6**。此时如实告诉用户哪些单元格还没核验，不能说公式已通过，也不要把公式改成写死的值来绕过检查。

## 列类型决定数字格式

| `type`     | 显示         | 用在                                                                  |
| ---------- | ------------ | --------------------------------------------------------------------- |
| `text`     | 原样         | 名称、备注、编号                                                      |
| `integer`  | `1,234`      | 数量、件数                                                            |
| `number`   | `1,234.56`   | 一般数值                                                              |
| `currency` | `¥1,234.56`  | 金额                                                                  |
| `percent`  | `12.3%`      | 占比、增长率（**写小数 0.123，不是 12.3**）                           |
| `date`     | `2026-09-05` | 日期：写 `2026-09-05`（可带时刻）渲染成真日期，写不成日期的字原样保留 |

`percent` 那一行最容易错：Excel 的百分比格式会把 `0.123` 显示成 `12.3%`。
写成 `12.3` 会显示成 `1230%`。

## 其他

- **冻结首行默认开**（超过一屏的表不冻结就没法看），不想要就写 `"freeze_header": false`。
- 条件格式四种：`negative-red`（负数标红）· `above-average-green` · `top10-green` · `data-bar`。
- 一个 `sheets` 数组可以放多张表；**csv 只能装一张**，多张时渲染器会让你改成 xlsx。
- 大表（几千行）没问题，但超过 5 万行应该考虑给用户原始数据文件而不是生成表格。

## csv 的降级是显式的

csv 没有公式。输出 csv 时计算列会**留空并在表头标注"（公式列，csv 不支持）"**，
而不是悄悄填一个算好的值 —— 用户看到空列会来问，看到一个数不会。
需要公式就输出 xlsx。

## 改已有文件

用户要改的是已经存在的 xlsx 或 csv 时，先提取成内容 JSON，改 JSON，再写回。上报用 `--operation-kind edit`。

```bash
python3 container_tools/render.py --extract "<绝对路径>/对账.xlsx" --out "<临时目录>/对账.content.json"
python3 container_tools/render.py --content "<临时目录>/对账.content.json" --out "<绝对路径>/对账.xlsx" --overwrite
```

提取出的 JSON 是中间文件，写进本任务的临时目录（第一次用 `mktemp -d "${TMPDIR:-/tmp}/evowork.XXXXXX"` 建）。

**提取收不回的内容会被列出来，而且默认失败**：图表、图片、批注、合并单元格、超链接、数据验证、隐藏行列、筛选、透视表、定义的名称、外部链接、页眉页脚、颜色标记、数组公式等。先把清单告诉用户、说清楚重新渲染会丢掉它们；用户同意后加 `--allow-lossy` 再提取，并把结果里的 `dropped` 原样转告。重新渲染会套用本技能的样式，原表的列宽、字体不保留。

**写回原文件要显式加 `--overwrite`**，否则目标已存在时会被拒绝。任务目录里的文件可在 App 里撤销；任务目录之外的文件没有撤销副本，先另存一份。

xlsx 里同一列、随行号变化的公式会收成 `=B{row}*C{row}` 这种模板，数据行对应位置是 `null`：只替换单元格引用里的相对行号，`$` 锁住的行号、字符串和数字常量都不动。表头上方的标题行（合并的大标题、「单位：元」）不会写回，会出现在 `dropped` 里；删掉标题行时公式引用整体平移。表头必须从 A 列开始且连续。数据下方隔一行、只占 A 列的那行字收成 `note`。合计行只有在数字列都是本列 `SUM` 时才收成 `total_row`；留空的会被补上 `SUM` 并上报，写死的数或别的公式会被拒绝。一列里既有公式又有常量，或各行公式收不成同一个模板时停下来，不把其中一种悄悄丢掉。

csv 比表头宽的行会被拒绝（多出的格子不会悄悄丢掉）；以 0 开头的编号和超过 15 位的数字保持文字。

csv 没有公式。表头带「公式列，csv 不支持」时拒绝提取，让你改去读原来的 xlsx，而不是交出一张空列看起来像结果的表。

## 需要办公扩展

`.xlsx` 依赖本机的**办公扩展**（Python + openpyxl，约 120MB，按需下载）。
未安装时渲染器会退出并给出提示 —— 此时可以改输出 `.csv`（不需要扩展），
或者告诉用户安装。**不要用 zip 手工拼 xlsx**，那几乎一定产出打不开的文件。
