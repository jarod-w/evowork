# 界面设计

做安静、高密度的桌面工作台：中性表面、克制的边框与阴影、系统字体、紧凑控件、一条清晰任务流。保留宿主平台的窗口惯例和用户的产品需求。把这套规范当设计语言用，不要复制专有资产，也不要发明文档里没有的产品行为。

## 分流

1. 先判断表面：完整外壳、任务/对话、输入框、导航、代码/diff/终端面板、设置，或只有输出内容。
2. 选尺寸、字体、颜色、层级或动效前，先读 [foundations.md](references/foundations.md)。里面的精确数值是有版本的实现基线，不是永恒品牌规则。
3. 做完整外壳或组件时读 [patterns.md](references/patterns.md)。
4. 写任务对话、助手回复、进度行、工具活动、代码、diff 或终端输出时读 [output-style.md](references/output-style.md)。
5. 产出代码或核对还原度时读 [implementation.md](references/implementation.md)。目标支持 CSS 自定义属性时复用 [ui-tokens.css](assets/ui-tokens.css)。

## 核心不变量

- 任务、当前状态、下一步动作必须先于装饰出现。
- 三区心智模型：导航、聚焦工作、可选的上下文/工具面板。挤不下时收起分区，不要三区一起压扁。
- 助手表面以无框为主。实心底座留给用户输入、控件、选中态、警告和独立的工具产物。
- 层级靠间距、字重、对齐和低对比中性色。不要靠高饱和色或重阴影。
- 界面文字用系统 UI 字体栈，代码用系统等宽栈。不要依赖未随包的品牌字体。
- 4 px 间距网格，控件 28–36 px，发丝分割线，中等圆角，150–300 ms 短过渡。
- 支持浅色、深色、键盘、减少动效、缩放、长路径、长代码、本地化、空/加载/错误态，以及 480 px 最小宽度布局。
- 语义色保持一致：蓝=焦点/链接/信息，绿=成功/新增，橙=警告，红=危险/删除。中性 UI 保持中性。
- 渐进披露：先给结果和相关状态；日志、原始命令输出、元数据和高级动作可展开。

## 还原度怎么取

需要贴近当前桌面比例时用基线精确值；目标是 web、移动、嵌入式或受已有设计系统约束时再适配。先保住关系再改数字：侧栏窄于工作区，对话窄于宽产物，输入框视觉锚定，次级面板可关掉。

需求冲突时按这个顺序：

1. 无障碍与平台行为。
2. 信息架构与任务清晰度。
3. 现有产品约束。
4. 与这套工作台视觉的相似程度。

接近还原时说明对着哪一版基线。更松的适配就写成「工作台风格」。

## 验收

在 1280×820、960×720、480×600 下看；浅色和深色；只用键盘；至少一条长标题、路径、命令、diff 和错误。确认焦点可见、面板按预期收起、输入框始终够得到，次要装饰不跟任务输出抢注意力。
