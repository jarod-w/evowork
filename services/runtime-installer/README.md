## 它解决的问题

在此之前 08 §4 只有决策没有实现：引导第 ⑤ 步的 `runtimeInstalled` 硬编码 `false`，
安装按钮没有回调，于是 **Word / Excel / PPT / PDF 在任何一台干净机器上都不可用**，
而用户唯一的出路是自己去装 uv 再敲两条命令。这个包把那两条命令变成一个按钮。

```
① 下 python 发行版 → ② 解包摊平 → ③ pip 装六个包 → ④ 下字体并切静态实例 → ⑤ 验收 → ⑥ 原子换入
```

## 为什么它不在 `services/ingest` 里

`ingest` 的身份是"**结构上不出网**"——它的测试扫源码里的 `fetch(` / `node:http`，
守的是"用户的文件不会被传到云上解析"（K6 的核心承诺）。为一个下载器在那里开口子，
之后往里加什么就没人拦得住了。

把下载放到另一个包之后，`ingest` 那边的扫描从"手工列的文件名单"收紧成了**整个 src 目录**
——承诺反而更强了。

## 四条不能松的

1. **每个下载都带 sha256**，校验不过就整包失败并删文件。没有"校验失败但先用着"这条分支。
2. **原子换入**：全程装在 `office.staging/`，验收通过才 rename。半截目录会被探针判成
   "装好了"，然后每次生成产物都以奇怪的方式失败。
3. **验收是真的跑一遍**：用装出来的解释器 import 六个模块，并让 matplotlib 真的登记出
   `Noto Sans SC` 这个家族名 —— `plugins/skills/charts` 在用户机器上就是这么找字体的。
4. **离线包一个字节都不出网**。测试把 `downloadFn` 换成"一被调用就炸"来守这一条。

## 两个被真机跑出来的教训

- **`uv venv` 建的目录不可搬运**：`bin/python` 是指向 `~/.local/share/uv/python/...` 的
  绝对符号链接，客户机器上拷过去就是死链，而且不带 pip。所以用 python-build-standalone
  的 `install_only` 构建。判断"可不可搬运"别去看"是不是符号链接"——
  `bin/python3 → python3.12` 是**相对**链接，搬到哪儿都成立（E2E 直接搬一次再跑）。
- **下载会停滞**：2026-09-07 的真机 E2E 撞到连接挂在 0%、15 分钟后测试超时。
  放到用户那里就是"点了安装永远卡在 0%"，没有报错也没有出路。
  现在 60 秒收不到字节就判定连接死了并给出可照做的原因。

## 发版前必须跑

上游资产变了（清单过期、GitHub 改布局）**只有真机 E2E 能发现**：

```bash
EVOWORK_INSTALL_E2E=1 npx vitest run --project runtime-installer

# 离线包那条（先用 scripts/build-office-bundle.mjs 打一份）
EVOWORK_INSTALL_E2E=1 EVOWORK_OFFICE_BUNDLE=<目录> npx vitest run --project runtime-installer
```

它默认不跑不是"按机器状态跳过"（CLAUDE.md §9.1 反对的那种），而是按显式意图开关：
每次跑都在一个全新的临时 HOME 上从零装，验的就是干净机器。默认关只因为它要下 ~180MB。
