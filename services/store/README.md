# services/store —— 本机数据模型（M2a）

设计：[09 §4](../../docs/design/09-service-layer.md)。单个 sqlite：`~/.evowork/evowork.db`，WAL，
**单写者（服务层），UI 只读走服务层 API**。

**存在理由**（不是缓存优化，是协议缺口）：`thread/list` 没有状态与日期过滤（F8），
`ThreadExtra` 是空结构体、没有客户端元数据槽（F9）。所以派生状态、场景、产物计数、分享状态
只能落本机投影表。

**两个迁移器（09 §4.6，必须在代码里显式区分）**：

| 类别                 | 表                                                                                                                           | 迁移失败时                                                    |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 投影类（真源在别处） | `thread_projection` · `item_digest` · `library_index`                                                                        | **丢弃重建**，不阻塞启动                                      |
| 权威类（丢了就没了） | `automation` · `share` · `audit_log` · `subscription` · `image_operation` · `thread_message` · `follow_up_*` · `next_action` | 先备份 → 失败则回滚并报错，**宁可启动失败也不丢定时任务定义** |

不显式区分的话，"重建索引"的逻辑总有一天会把 `automation` 表也清了。

**2026-10-11 独立会话通信**：权威 v5 新增 `thread_message`，保存授权请求正文、回复、稳定 ID、去重键和投递/回传状态。升级 v4 前备份，迁移失败回滚；不外键关联可重建的任务投影。正文属于必要的本机队列数据，不复制到诊断日志。删除任一参与任务会清理对应通信；投影重建不会删除队列。详见 [17](../../docs/design/17-thread-communication.md)。

**2026-10-20 下一步建议**：权威 v7 新增 `next_action`，保存来源回合、候选正文与采纳/关闭状态；不与待执行队列混用，不进入投影和诊断日志，任务删除时清理。详见 [22](../../docs/design/22-next-actions.md)。
