# services/store —— 本机数据模型（M2a）

设计：[09 §4](../../docs/design/09-service-layer.md)。单个 sqlite：`~/.evowork/evowork.db`，WAL，
**单写者（服务层），UI 只读走服务层 API**。

**存在理由**（不是缓存优化，是协议缺口）：`thread/list` 没有状态与日期过滤（F8），
`ThreadExtra` 是空结构体、没有客户端元数据槽（F9）。所以派生状态、场景、产物计数、分享状态
只能落本机投影表。

**两个迁移器（09 §4.6，必须在代码里显式区分）**：

| 类别                 | 表                                                    | 迁移失败时                                                    |
| -------------------- | ----------------------------------------------------- | ------------------------------------------------------------- |
| 投影类（真源在别处） | `thread_projection` · `item_digest` · `library_index` | **丢弃重建**，不阻塞启动                                      |
| 权威类（丢了就没了） | `automation` · `share` · `audit_log` · `subscription` | 先备份 → 失败则回滚并报错，**宁可启动失败也不丢定时任务定义** |

不显式区分的话，"重建索引"的逻辑总有一天会把 `automation` 表也清了。
