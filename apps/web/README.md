## 为什么先登记一个空目录

Q37=B（管理员 = **租户管理员**）之后，「管理端」必须有一个落点，而它**不能在客户端里**：

- **客户端（Electron）没有管理员界面**。`role = admin` 时设置页只显示一个跳系统浏览器的入口；
  客户端知道自己是管理员也做不了管理动作 —— 授权在服务端。
- **Q32=B 的密码表单只出现在这里**。与 Q33=A（系统浏览器 + PKCE + loopback）合起来是硬约束：
  `password` 不出现在客户端进程、IPC 契约与 `packages/logging` 的字段注册表里
  （[11 §12](../../docs/design/11-account-and-models.md) 第 12 条）。

## 三个面各自明确**没有**什么

| 面     | 有什么                                                                  | 明确没有什么                                                              |
| ------ | ----------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 账号页 | 注册 · 登录 · 邮件验证 · 密码重置 · 额度查看                            | 不做任务执行、不做产物浏览 —— 数据属于机器（D10）                         |
| 管理端 | 默认模型（base_url + key + 协议适配类型）· 成员 · 每人额度 · 策略包签发 | **不接触任何内容面**：API 的返回类型里没有能装任务 / 产物 / prompt 的字段 |
| 分享页 | Q10 的产物只读查看（显式授权 + 有效期）                                 | 不需要账号；与管理端不共享任何数据面                                      |

「管理员能不能看员工的任务」是企业采购必问项，答案必须是**结构上看不到**，
不是"我们承诺不看"——内容从不上云（D9 / K6），而管理端 API 的类型里没有那个字段。
