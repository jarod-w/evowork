## 为什么管理端在这里、不在客户端

Q37=B（管理员 = **租户管理员**）之后，「管理端」必须有一个落点，而它**不能在客户端里**：

- **客户端（Electron）没有管理员界面**。`role = admin` 时设置页只显示一个跳系统浏览器的入口；
  客户端知道自己是管理员也做不了管理动作 —— 授权在服务端。
- **Q32=B 的密码表单只出现在这里**。与 Q33=A（系统浏览器 + PKCE + loopback）合起来是硬约束：
  `password` 不出现在客户端进程、IPC 契约与 `packages/logging` 的字段注册表里
  （[11 §12](../../docs/design/11-account-and-models.md) 第 12 条）。

## 界面规格在 [01 §11](../../docs/design/01-ui-design-system.md)

01 前十节都是从桌面截图反推的，**从没提过 `apps/web`** —— 那是这一页长成
「带样式的 phpMyAdmin」的第一因：token 一直是对的（`styles.test.ts` 全绿），
但没有规范可遵守，于是每一页现场发明。2026-09-26 补上 §11：两套骨架、五个分区、
组件复用、以及 WEB 特有的四条（主按钮底用 `--accent-strong` · 小字用 `--text-secondary` ·
时间按本地时区 · 每段数据自己报三态）。

`src/components.tsx` 是 01 §5 那批基础件在 WEB 侧的薄实现。**不新增组件**；
抽 `packages/ui` 的时候这一层是被合并掉的那一半，不是要长期并存的第二套。

## 三个面各自明确**没有**什么

| 面     | 有什么                                                                                                                                                                                           | 明确没有什么                                                              |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| 账号页 | 注册 · 登录 · 邮件验证 · 密码重置 · **改密** · 额度查看 · **额度提醒开关** · 设备吊销 · **吊销其他全部** · 注销（再输密码）                                                                      | 不做任务执行、不做产物浏览 —— 数据属于机器（D10）                         |
| 管理端 | 概览 · 成员（**邀请** / 行内额度、班级、admin）· 默认模型（加 / **删** / 测试连接）· 用量与配额（**提醒设置**）· 策略与审计（**签发向导 + diff** · **生效面** · 历史 · 撤销 · **审计导出 CSV**） | **不接触任何内容面**：API 的返回类型里没有能装任务 / 产物 / prompt 的字段 |
| 分享页 | Q10 的产物只读查看（显式授权 + 有效期）—— **未做**（Q41，跟分享上传走）                                                                                                                          | 不需要账号；与管理端不共享任何数据面                                      |

**不是"还能加什么"。** 超出这四条的一律见 [11 §13.10 E](../../docs/design/11-account-and-models.md) 的否定清单（网页版工作台 · 管理端看成员任务 · 云端产物浏览 · 充值 · 「与我共享」收件箱 · 浏览器内渲染办公文件 · 云盘入口）。

| 云端职责       | 这里的落点                                                                                                            | 现状                                 |
| -------------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| 账号 / 配额    | 注册 · 登录 · 验证 · 重置 · 改密 · 额度 · 设备吊销 · 注销 · **邀请** · **吊销其他全部** · **额度提醒** · **审计导出** | 齐                                   |

| 企业私有源索引 | 源的注册 / 版本 / 签名                                                                                                | **没有**，边界未定（**Q44** 未决策） |

## 已知缺口（2026-09-26；A / B / B' / D 已落地）

细则与理由在 [11 §13.10](../../docs/design/11-account-and-models.md)。
P3.5-4 补了 A / B / D；2026-09-26 的 **B'** 补了五件「已有职责缺的另一半」：
成员邀请 · 吊销其他全部设备 · 策略包生效面 · 额度提醒 · 身份面审计导出。

**同轮修掉的那个缺陷值得单独记一笔**：access JWT 只有 15 分钟，而这一页从不续期 ——
管理端开着一刻钟之后每个按钮都静默变成「请求失败」，页面上没有一句话说要重新登录。
现在是 401 → 续期 → 重放原请求，续不上才弹「登录已过期」（验收口径第 26 条）。

仍未做：

1. **企业私有源索引管理面**：等 Q44 决策，不要先建 `/admin/sources`。
2. **本机侧的分享接线**：分享页与云端服务已就绪，但 `createShare` / `createUploader`
   至今没有调用方 —— 桌面产物卡上的「分享」按钮还到不了授权模态。那一段在 `apps/desktop`。

## 两个入口

| 入口                        | 谁在看                   | 会话                                    |
| --------------------------- | ------------------------ | --------------------------------------- |
| `index.html` → `src/`       | 登录用户与租户管理员     | 读 `sessionStorage`，带 `authorization` |
| `share.html` → `src/share/` | **链接接收方，没有账号** | **不读、不带、不种 cookie**             |

`test/share-isolation.test.ts` 扫 `src/share/**` 的 import 图：越界到 `../api.js`、
`../components.js` 或任何 screens 就红。**改这条测试就是那次决策的登记动作** ——
分享页要渲染的是不可信来源的元数据，它旁边不该放着一把令牌（11 §13.10 C 第 1 条）。

`test/no-content.test.ts` 那条从「没有分享页」改成了「账号应用里没有分享路由」，
同样不许悄悄在这个应用里加一个 `/s/` 路由绕过去。

## 这个包里的命名

策略包的「生效面」叫 **`reach`**，不叫 `rollout`：后者在本仓库已经是**内核 thread 轨迹文件**
的名字，`@evowork/no-kernel-internals` 会直接拦下来。拿它指"下发到了几台设备"
就是在造第三个词（CLAUDE.md §9）。

本地开发：

```
EVOWORK_WEB_ORIGIN=http://127.0.0.1:5174
VITE_IDENTITY_ORIGIN=http://127.0.0.1:8788
pnpm --filter @evowork/web dev
```
