## 为什么管理端在这里、不在客户端

Q37=B（管理员 = **租户管理员**）之后，「管理端」必须有一个落点，而它**不能在客户端里**：

- **客户端（Electron）没有管理员界面**。`role = admin` 时设置页只显示一个跳系统浏览器的入口；
  客户端知道自己是管理员也做不了管理动作 —— 授权在服务端。
- **Q32=B 的密码表单只出现在这里**。与 Q33=A（系统浏览器 + PKCE + loopback）合起来是硬约束：
  `password` 不出现在客户端进程、IPC 契约与 `packages/logging` 的字段注册表里
  （[11 §12](../../docs/design/11-account-and-models.md) 第 12 条）。

## 三个面各自明确**没有**什么

| 面     | 有什么                                                                       | 明确没有什么                                                              |
| ------ | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 账号页 | 注册 · 登录 · 邮件验证 · 密码重置 · 额度查看 · 设备吊销 · 注销（再输密码）   | 不做任务执行、不做产物浏览 —— 数据属于机器（D10）                         |
| 管理端 | 默认模型（base_url + key + 协议适配类型）· 成员 · 每人额度 · 授予/收回管理员 | **不接触任何内容面**：API 的返回类型里没有能装任务 / 产物 / prompt 的字段 |
| 分享页 | Q10 的产物只读查看（显式授权 + 有效期）—— **未做**（Q41，跟分享上传走）      | 不需要账号；与管理端不共享任何数据面                                      |

## WEB 该支持什么 = D9 四条云端职责的界面面

**不是"还能加什么"。** 超出这四条的一律见 [11 §13.10 E](../../docs/design/11-account-and-models.md) 的否定清单（网页版工作台 · 管理端看成员任务 · 云端产物浏览 · 充值 · 「与我共享」收件箱 · 浏览器内渲染办公文件 · 云盘入口）。

| 云端职责       | 这里的落点                                                      | 现状                                 |
| -------------- | --------------------------------------------------------------- | ------------------------------------ |
| 账号 / 配额    | 注册 · 登录 · 验证 · 重置 · **改密** · 额度 · 设备吊销 · 注销   | 齐，**缺改密**                       |
| 模型网关       | 默认模型 · 成员 · 每人额度 · 配额班级 · 授予收回 admin · 策略包 | 齐，三笔欠账                         |
| 分享托管       | `/s/<share-id>`（Q41）                                          | **没有**                             |
| 企业私有源索引 | 源的注册 / 版本 / 签名                                          | **没有**，边界未定（**Q44** 未决策） |

## 已知缺口（2026-09-20 对账，**只登记，未实现**）

细则与理由在 [11 §13.10](../../docs/design/11-account-and-models.md)，这里只列改哪。

1. **改密页缺失 —— 种子管理员被锁在门外。** identity 的 `/v1/admin/*` 在 `mustChangePassword` 为真时一律 403，而 `/v1/password` **在这个包里没有调用方**：账号页只有一句红字，`AdminPage` 也只判 `role` 不判 `mustChangePassword`。要补 `/account/password` 表单，以及改密前管理端只渲染改密。**验收口径第 23 条，当前已被违反。**
2. **成员动作靠手粘 `userId`**：成员表显示的是邮箱，而三个表单要 id，管理员无处可取。改成行内动作。
3. **策略包只显示 `kid`**：补当前 payload 的可读渲染 + 签发历史 + 撤销入口。
4. **没有管理动作审计**：谁在何时授予 admin / 改了默认模型的 key / 签发了策略包（身份面，不碰内容面）。
5. **用量只有本人一行**：管理端按 Q43=A 补「租户总量 + 按人当期累计」，**不做按人按天曲线**。
6. **分享页**：跟分享上传同一切片；且它**不读 `sessionStorage` 里的 session、不带 `authorization` 头**，最好是独立入口。

`test/no-content.test.ts` 断言 `app.tsx` 里不出现 `/s/`、且带着"没有任务 / 产物 / 分享页"这句注释 ——
**改这条测试就是分享页那次决策的登记动作**，不许悄悄加一个路由绕过去。
